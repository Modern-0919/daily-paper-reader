## 摘要
现有的评估常常将代理失败简化为系统级的结果，掩盖了故障的起源以及何种干预措施能改进代理系统。这产生了修复分配问题：同一可见的失败可能因来源不同而需要模型后训练、框架工程、环境重新设计或基准修复。由于代理行为产生于模型、框架、用户、工具、记忆和环境之间的交互，结果级标签往往不足以指导改进。大多数失败分类法对此问题帮助甚微，因为它们针对特定基准且缺乏共享结构。我们提出一种以交互为中心的分类法，将失败定位到其源起的交互，并识别责任组件。它将每种失败模式分配给两个组件之间的边，并标注故障侧以指示修复的责任方。这使分类法具有可操作性：模型端失败确定后训练的目标，框架端失败指向脚手架和工具集成修复，而环境或评分器失败揭示需要重新设计的评估条件。该分类结构适用于多种代理架构，从编程助手到长时程个人助理以及多代理系统。我们利用公开基准、模型系统卡、已发表报告和记录的代理轨迹中的实例来支撑该分类法，并使用独立推理代理作为评判者评估其可重复性。与人类类别标签相比，最强的评判者在四个前沿模型中达到了 Cohen's κ = 0.76，表明这些类别捕捉了共享结构而非标注者特定的偏好。

## Abstract
Existing evaluations often reduce agent failures to system-level outcomes, obscuring where the fault originated and which intervention would improve the agent system. This creates a repair-assignment problem: the same visible failure may call for model post-training, harness engineering, environment redesign, or benchmark repair depending on its source. Because agent behavior emerges from interactions among models, harnesses, users, tools, memory, and environments, outcome-level labels are often insufficient for improvement. Most failure taxonomies do little to resolve this problem because they are benchmark-specific and lack a shared structure. We introduce an interaction-centric taxonomy that localizes failures to the interactions in which they originate and identifies the responsible component. It organizes 41 failure modes by assigning each to an edge between two components and a fault side indicating where the repair belongs. This makes the taxonomy actionable: model-side failures identify targets for post-training, harness-side failures point to scaffolding and tool-integration fixes, and environment or grader failures reveal evaluation conditions requiring redesign. The schema applies across agent architectures, from coding assistants to long-horizon personal assistants and multi-agent systems. We ground the taxonomy in worked examples from public benchmarks, model system cards, published reports, and logged agent trajectories, and evaluate its reproducibility using independent reasoning agents as judges. Across four frontier models, the strongest judge reaches Cohen's $κ=0.76$ against human category labels, suggesting that the categories capture shared structure rather than annotator-specific preferences.

## 1. 核心问题与整体含义

- **研究动机**：现有代理（agent）评估通常将失败压缩为系统级结果（如任务成功/失败），但同一可见失败可能源于不同组件——模型本身、框架（harness）、工具、环境或评分器——需要截然不同的修复策略。作者称之为「修复分配问题」（repair-assignment problem）。
- **关键矛盾**：例如，代理忽略早期用户指令，可能是框架上下文压缩（context compaction）将其移除，也可能是指令仍可用但模型未能遵循。前者需修复框架，后者需模型后训练。结果级标签无法区分这两种情况。
- **现有方法的不足**：多数失败分类法（taxonomy）是基准特化的（benchmark-specific），如 SWE-bench 或 WebArena 相关分析只覆盖单一场景；多代理系统研究（如 Cemri et al. 2025）虽涉及系统设计失败，但并不明确指出哪个组件应负责修复；安全领域的分类法（如微软 AI 红队）按威胁组织，而非按失败源组织。
- **总体含义**：作者主张，代理行为涌现于模型、框架、用户、工具、记忆、环境间的交互，因此失败定位应**以交互为单位**，明确「故障侧」（fault side），才能使分类法直接指导干预——模型端失败指向后训练，框架端失败指向脚手架工程，环境/评分器失败指向评估条件重新设计。

## 2. 方法论：交互中心分类法

- **组件词汇表**：定义了 12 个组件，包括 Model（LLM 策略）、Owner（任务赋予方）、Grader（评分机制）、Third party（第三方参与者）、Context（当前交互上下文）、Memory（持久存储）、Tool（工具接口）、Local env（本地执行环境）、External env（外部服务）等。多代理场景中，另一模型按角色分为 peer 或 subagent。
- **核心表示**：每个失败标记为 `COMP1 — COMP2 · fault: SIDE`，其中边（edge）表示两个组件间的交互，故障侧（fault side）表示责任组件。例如 `TOOL — MODEL · fault: MODEL` 指模型忽视了工具返回的错误，而 `TOOL — MODEL · fault: TOOL` 指工具包装器抑制了错误导致模型无从知晓。
- **归属规则（root-cause 原则）**：从观察到的系统级失败出发，沿因果链回溯，标注**最早不可恢复的失败**（the earliest failure from which execution does not recover），而非下游症状。一个干预在该点可改变结果，后期错误可能只是其后果。
- **故障侧判断标准**：若一个更强的模型在相同条件下本可避免或从失败中恢复，则归为模型侧故障。这导致 41 种失败模式中 36 种归于模型侧，5 种归于周围组件（Owner、Context、Tool、Environment）。
- **分类结构**：按三个家族组织——User（Owner/Grader/Third party）、Harness（Context/Memory/Tool/Model-peer/subagent）、Environment（External/Local）。共 41 种失败模式，例如 Over-initiative、Specification Gaming、Indirect Prompt Injection、Context Rationale Erosion、Missed Write、Tool Hallucination、Mistranslation、Delegation Failure 等。
- **构建流程**：迭代式地审查公开基准、模型系统卡、公开报告和代理轨迹；定义稳定后冻结分类法，用于所有标注和验证。对安全/隐私相关失败附加 OWASP Top 10 风险类别标注。

## 6. 主要结论与发现

- **分类法可重复**：独立推理代理能够以高于偶然的水平恢复人工标签。最强评判者 GPT-5.5 在类别级与人类标注达到 Cohen's κ = 0.76（准确率 80%），其余三个 Opus 模型 κ = 0.70–0.71。评判者之间一致性（最高 κ = 0.84）与对人类的认同度相当，说明类别捕捉了共享结构而非个体偏好。
- **失败模式级更具挑战**：所有模型在此级别的一致性都更低（准确率 62–72%），部分错误源于类别选择错误，而非模式间混淆；给定正确类别后，Opus 模型的表现显著提升（如 4.6 从 0.80 提升至 0.70 F1），说明类别阶段是主要瓶颈。
- **选择性投票可提升精度**：≥3/4 评判者一致时，类别精度达 0.83–0.96；但覆盖范围降至 90%–68%，需在精度与覆盖率间权衡。
- **归因偏差**：评判者倾向于将失败归咎于模型，即使真实故障在环境。案例研究（Harbor-Mix GAIA2/ARE）中，评判者将脚本回复未送达的环境故障误判为模型观察失败。
- **模型侧失败占主导**（36/41），部分反映归属规则本身（更强模型可避免则归模型侧）。

## 7. 优点

- **视角新颖**：以「交互边 + 故障侧」为分析单位，清晰地分离了失败表现位置与失败责任归属，直接对接修复干预选择。
- **固定归属规则**：采用「最早不可恢复失败」的根因原则（借鉴 AgentRX），减少了多故障级联时的标注歧义。
- **跨域通用性**：组件词汇表适用于单代理、多代理编排、长时程个人助理等不同架构；模态无关，示例涵盖多模态场景。
- **实验验证严谨**：用代理作为独立评判者，且有明确的三回合流水线（证据重建→分类→反思），并通过 pre-tool hook 防止标签泄漏，保证评估独立性。
- **可操作性强**：每个失败模式附带定义与边界消歧规则，模型侧/框架侧/环境侧故障与实际干预选项直接映射。
- **案例库丰富**：40 个实例来自多种真实来源，含完整轨迹、报告、系统卡，且有安全风险标注（OWASP 映射），兼具学术价值与实践参考意义。

## 8. 不足与局限

- **描述性而非定量**：分类法不估计失败频率，40 个实例为示例性集合而非代表性样本，不能用于衡量各模式流行程度。
- **证据依赖性**：标签受限于可用证据；某些来源（如公开事件报告、系统卡）缺乏完整轨迹，难以唯一归因。例如 E4 中上下文压缩与未授权行动两种解释均可能成立。
- **评判者准确率有限**：即使最强模型，类别级 κ 仅 0.76，失败模式级更低；根因追溯对 LLM 而言仍是核心瓶颈（OpenRCA 2.0 也报告同样结论）。
- **覆盖-精度权衡**：选择性投票提升精度以牺牲覆盖为代价，在归属最不确定时系统会选择弃权，限制了实际部署的可用性。
- **模型侧偏见**：归属规则倾向将失败分配给模型，可能低估框架/环境系统性缺陷；评判者也表现出将失败归因于模型的行为偏差（见附录 A.2 案例）。
- **分类法演化需求**：分类结构可能随代理架构、框架能力和环境类型的变化而需扩展，其长期稳定性未经验证。
- **安全/风险标注非系统化**：OWASP 类别仅为「最显著」的单一标注，不覆盖所有潜在危害维度，也未预先为每种失败模式固定风险类别。
