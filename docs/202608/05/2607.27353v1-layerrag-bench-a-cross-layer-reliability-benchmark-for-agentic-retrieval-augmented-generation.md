## 摘要
智能体检索增强生成系统可能产生看似有依据的答案，却在证据、工具契约、授权或会话状态层上失效。我们引入了LayerRAG-Bench，这是一个受控的跨层可靠性基准，涵盖8个企业领域、240个任务、9种故障场景、2种契约模式，以及来自OpenAI、Anthropic和Gemini的九个模型共38,880条实时任务级记录。模式规范化将模式漂移成功率从0.000提升至0.913，但陈旧证据、缺失工具输出、权限被拒和错误会话上下文的问题无法通过模式规范化修复。仅基于依据的评估在陈旧和错误会话证据下也会产生大量误报。这些结果支持一种分层评估原则：可靠性干预措施应因其修复目标层而受到认可，而不应被误认为通用解决方案。

## Abstract
Agentic retrieval-augmented generation systems can produce answers that appear grounded while failing at the evidence, tool-contract, authorization, or session-state layer. We introduce LayerRAG-Bench, a controlled cross-layer reliability benchmark with 8 enterprise domains, 240 tasks, 9 fault scenarios, 2 contract modes, and 38,880 live task-level records across nine models from OpenAI, Anthropic, and Gemini. Schema normalization raises schema-drift success from 0.000 to 0.913, but stale evidence, missing tool output, denied permissions, and wrong-session context are not recovered by schema normalization. Groundedness-only evaluation also produces substantial false positives under stale and wrong-session evidence. These results support a layer-specific evaluation principle: a reliability intervention should be credited for repairing its target layer without being mistaken for a universal fix.

# LayerRAG-Bench：面向智能体检索增强生成的跨层可靠性基准——详细总结

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **背景**：检索增强生成（RAG）通过外部证据约束模型输出，而智能体 RAG（Agentic RAG）进一步引入工具调用、结构化接口、权限管理和持久状态。然而，系统可靠性不再只取决于答案是否在文本上"有据可依"（grounded）——一个回答可能忠实总结了已废弃的政策、引用了错误会话中的证据，或基于不完整的工具输出，却仍然看似合理。
- **核心问题**：现有检索与忠实度指标（如 RAGAS、ARES、CRAG、Self-RAG 等）虽然必要，但会将来自不同层级的故障混为一体——例如，模式规范化（schema normalization）可以修复工具载荷变化（schema drift），却无法恢复缺失证据、绕过授权、刷新陈旧索引或纠正租户上下文。评估体系缺乏对"干预措施到底修复了哪一层"的精细判别能力。
- **整体含义**：论文提出一个核心原则——**可靠性干预应被归功于其修复的目标层，而不应被误认为是通用修复方案**。LayerRAG-Bench 正是为这一分层评估原则而设计的受控基准。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：构建一个跨层故障矩阵，将 9 种故障场景映射到不同的运维层，并为每个场景设置"严格模式"与"修复模式"进行配对比较，从而检验某类修复手段是否只修复其目标层、而对其他层无效（负对照）。
- **基准构成**：
  - **enterprise_v2 语料库**：8 个企业领域、80 项政策规范、160 份文档、240 个任务。每个政策单元包含现行文档+被取代文档+3 个模板化问题变体。
  - **9 种故障场景**：clean（无故障）、stale index（陈旧索引）、schema drift（模式漂移）、missing tool output（工具输出缺失）、conflicting evidence（证据冲突）、permission denied（权限拒绝）、partial tool timeout（部分工具超时）、corrupted metadata（元数据损坏）、wrong session state（错误会话状态）。
  - **2 种契约模式**：严格模式（strict）拒绝不符合预期模式的工具输出；修复模式（repair）应用有界的模式规范化——注意，修复模式**不**设计用于重建缺失证据、绕过权限、刷新索引或修复会话上下文。
- **检索器设计**：确定性评测使用的 `tfidf_domain_validity` 检索器结合 TF-IDF 匹配、查询派生的领域线索与状态/年份有效性重排序；不会收到任务标注的领域标签。
- **评估指标**：严格成功的定义为四个条件的合取：

  **Sₜ = Eₜ ∧ Rₜ ∧ Gₜ ∧ Vₜ**
  - Eₜ：归一化精确匹配（答案正确性）
  - Rₜ：所有任务指定的证据文档 ID 均被检索到
  - Gₜ：至少有一条引用，且引用仅限于已检索证据
  - Vₜ：所有工具调用满足其模式约束

  拒答（abstention）在严格指标下视为失败，但会在诊断标签中保留；在聚焦 LangChain 研究中另设"安全解决"（safe resolution）指标，将不安全条件下的结构化拒答计为成功。
- **分层干预原则**：表 1 明确各场景的目标层与预期缓解行为——例如权限拒绝的预期缓解是"不应被生成绕过"（应触发安全拒答），陈旧/错误会话证据不应仅因支持生成文本而获得分数。

## 3. 实验设计：数据、基准与对比方法

- **主实时矩阵（Live Cross-Provider Matrix）**：
  - 9 个模型：OpenAI（gpt-5.4、gpt-5.4-mini、gpt-5.5）、Anthropic（claude-sonnet-5、claude-haiku-4-5-20251001、claude-opus-4-8）、Gemini（gemini-3.1-flash-lite、gemini-3.5-flash、gemini-3.1-pro-preview）。
  - 9 场景 × 2 契约模式 × 240 任务行 × 9 模型 = 162 个单元格，共 **38,880 条记录**。
- **确定性基准**：在不调用模型的情况下，用固定检索器在所有 240 个任务上验证基准能否分离可回答条件、契约故障与证据/状态故障。
- **检索器消融**：比较报告检索器、仅领域线索（去除有效性重排序）、仅有效性（去除领域线索）、纯 TF-IDF、显式任务领域过滤五种条件，评估 required-document top-1 recall。
- **聚焦 LangChain 集成研究**：对比不受控的检索+生成（基线）与证据感知的 allow、abstain、reject、bounded-retry 控制；使用 1 个模型、8 个任务、9 种证据条件、2 个臂，共 **144 个单元格**。
- **对比方法**：论文未直接对比其他基准的分数，而是通过"严格 vs 修复"配对、基线 vs 控制臂的对照，以及 groundedness 假阳性统计来验证分层评估的必要性。

- **实验规模**：

  - 确定性评测：240 任务全量覆盖。

- **充分性与客观性**：
  - 优点：配对设计（同一任务同时跑严格与修复模式）使修复增益可归因；分层 bootstrap 提供不确定性区间；隐私安全归档支持全部聚合结果的重新计算。

## 6. 主要结论与发现

- **模式修复合约的专属有效性**：schema drift 在严格模式下成功率为 0.000，修复模式下升至 0.913（配对增益 91.3 个百分点，分层 95% 置信区间为 85.4–95.6），最大离目标契约变化仅 0.7 个百分点（特异性边际 90.6 点）。
- **负对照的顽固性**：stale index、missing tool output、permission denied、wrong session state 在两种模式下成功率均为 0.000；partial tool timeout 仅约 0.31 且不受修复影响。模式规范化无法修复这些层。
- **Groundedness 假阳性普遍存在**：wrong session state 下 77.6% 的严格记录（78.8% 修复记录）虽 grounded 却严格失败；所有 grounded 的 stale-index 记录也均严格失败。因此"有据"既非充分条件，也非运维正确性的代理。
- **检索器敏感性**：有效性重排序是现行版本偏好的主要来源（移除后 clean top-1 recall 从 0.896 降至 0.483）；显式领域过滤虽可提升 clean 场景表现，但对损坏的领域元数据完全失效（top-1 与 top-3 均降为 0）。
- **更强的基础模型不消除系统层需求**：各提供商的故障形态高度相似，说明系统级控制（新鲜度校验、访问感知拒答、超时恢复、会话隔离）不可被模型能力替代。
- **聚焦集成验证**：基线 LangChain 安全解决率 50.0%，加入 LayerRAG 控制后达 100.0%（可回答条件 24/24 严格成功，不安全条件 48/48 安全解决），且 clean 任务严格成功率保持 100%，无错误干预。

## 7. 优点：方法与实验设计的亮点

- **分层故障矩阵设计**：9 种场景被精确映射到各自的目标层（新鲜度、工具契约、可用性、证据冲突、访问控制、完整性、元数据、会话状态），并配有明确的"预期缓解行为"，使评估具有结构化解释力。
- **匹配的严格/修复配对条件**：这是论文最突出的方法论创新——通过同一任务上的配对比较，能够精确量化某类干预的净收益，同时用负对照防止干预被夸大。
- **Groundedness 假阳性量化**：直接量化"有据但错误"的比例，从实证上否定了仅凭文本支持度评估 RAG 可靠性的做法。
- **确定性 + 实时双重验证**：先在不调用模型的情况下验证基准的判别能力，再进行跨提供商的实时评估，降低了模型噪声对基准设计的干扰。
- **隐私安全与可复现性**：发布的归档不含原始模型文本、文档 ID 和凭据，但包含重算所有聚合指标（场景聚合、修复增益、bootstrap 区间）所需的全部字段；提示哈希覆盖 28,080/38,880 条记录。
- **分层不确定性量化**：层次化 bootstrap 按提供商-模型-任务嵌套结构重采样，比简单 bootstrap 更符合实验设计。

## 8. 不足与局限

- **语料合成性**：corpus 为合成政策类文本，无法复现真实生产的歧义性、文档多样性、用户行为与组织复杂性。
- **任务相关性偏倚**：240 个任务为 80 个政策单元的 3 个语言变体，语言变体间相关而非独立，可能高估覆盖多样性。
- **检索器领域推断缺陷**：查询派生领域线索在 138 个任务上未解析、14 个任务上错误；且存在一个查询在 returns 与 legal 任务中出现但答案不同的情况，暴露了纯查询文本识别领域/会话的边界。
- **历史结果的一致性瑕疵**：历史 live 提示包含文档元数据中的版本局部答案字段（当前代码已移除），因此历史跨提供商结果应被解读为"加固前完整流水线"的测量，而非无元数据阅读理解测试。
- **模型覆盖与采样有限**：仅 9 个模型、每单元格单个完成，无法支撑提供商排名或稳定性结论；聚焦 LangChain 研究仅 1 模型、8 任务，作者明确称之为"窄研究"。
- **威胁模型边界**：不涵盖提示注入、越狱、数据外泄、生产访问控制认证等安全问题；也不评估延迟或成本。
- **无多次采样方差**：未报告多轮完成间的随机性影响，可能低估评估噪声。
