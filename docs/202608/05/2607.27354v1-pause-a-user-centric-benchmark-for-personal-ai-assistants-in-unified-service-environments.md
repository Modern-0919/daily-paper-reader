## 摘要
个人AI助手越来越多地被部署为面向任务、工具增强的智能体，在统一服务环境中运行以支持用户的日常活动。在现实场景中，此类助手必须对持久化的用户状态进行推理，尊重用户特定的配置和权限，并在多个服务之间维持长跨度、约束感知的交互。然而，现有基准往往将服务上下文碎片化或抽象掉用户状态，限制了其在现实服务设置中评估以用户为中心的个人助手行为的能力。我们引入了PAUSE，这是一个在状态化、服务集成环境中评估个人AI助手的用户中心基准。PAUSE通过要求智能体在协调异构用户自有资源上的行动，同时保持与环境状态的一致性、多轮交互中的授权约束，捕捉了现实世界助手部署的核心挑战。该基准通过逼真的用户模拟融入了显式的用户-智能体交互，使得评估超越了静态工具执行。为了支持原则性和可复现的评估，PAUSE采用了一种与任务特征一致的多机制评估框架。开放式的服务管理任务使用语义和轨迹级别的行为指标进行评估，而约束密集型任务则允许确定性的、基于状态的验证。基准结果显示，即使是最先进的专有模型，在需要状态化推理和配置感知的场景中，其任务完成率也未能达到70%，揭示了一致且可解释的失败模式。最后，我们提出了一条以用户为中心的合成流水线，能够实现连贯服务环境、用户配置和可靠标注任务的可扩展生成，支持基准的可扩展性和未来研究。

## Abstract
Personal AI assistants are increasingly deployed as task-oriented, tool-augmented agents that operate within unified service environments to support everyday user activities. In realistic settings, such assistants must reason over persistent user state, respect user-specific configurations and permissions, and sustain long-horizon, constraint-aware interactions across multiple services. Existing benchmarks, however, often fragment service contexts or abstract away user state, limiting their ability to evaluate user-centric personal assistant behavior in realistic service settings. We introduce PAUSE, a user-centric benchmark for evaluating personal AI assistants in stateful, service-integrated environments. PAUSE captures core challenges of real-world assistant deployment by requiring agents to coordinate actions across heterogeneous user-owned resources while maintaining consistency with environment state, authorization constraints over multi-turn interactions. The benchmark incorporates explicit user-agent interaction via realistic user simulation, enabling evaluation beyond static tool execution. To support principled and reproducible evaluation, PAUSE adopts a multi-regime evaluation framework aligned with task characteristics. Open-ended service management tasks are assessed using semantic and trajectory-level behavioral metrics, while constraint-intensive tasks admit deterministic, state-based verification. Benchmark results show that even state-of-the-art proprietary models fail to reach 70% task completion on scenarios requiring stateful reasoning and configuration awareness, revealing consistent and interpretable failure patterns. Finally, we present a user-centric synthesis pipeline that enables scalable generation of coherent service environments, user configurations, and reliably annotated tasks, supporting benchmark extensibility and future research.

- **总体框架**：将 PAUSE 建模为**部分可观测的用户–智能体交互过程**，扩展了 τ²-Bench 的双控制（dual-control）环境设定：智能体动作 `a_t ∈ A` 与用户动作 `u_t ∈ U` 交替推进交互。
- **环境状态与观测**：
  - 潜在环境状态：`s_t = (D_u, I_u, C_u)`，其中 `D_u` 为用户数据、`I_u` 为用户画像与账户信息、`C_u` 为系统/用户配置（权限、钱包、订阅、隐藏服务 API 访问等）；

## 6. 主要结论与发现

- **总体性能**：即使 SOTA 专有模型，在需要**状态化推理与配置感知**的硬任务上任务完成率均**低于 70%**（Gemini-3-Flash 59.12%、GPT-5 47.34%、Gemini-3-Pro 48.39%），揭示现有模型的显著能力缺口。
- **分层表现**：
  - easy 任务：顶级模型接近饱和（GPT-5 95.26%、Gemini-3-Pro 92.06%），弱模型大幅落后（GPT-4.1 33.34%）；
  - hard 任务：所有模型大幅下降，弱模型（GPT-4.1-Mini 10.53%）几乎失效；
  - 购物任务：排名与前述一致，DeepSeek-V3.2-Thinking 表现接近专有模型（0.550 vs Gemini-3-Flash 0.590），因其对时间推理要求低。
- **一致的失败模式**：
  - 强模型（Gemini-3-Flash）hard 任务错误集中于**系统配置推理（SCE）**，基础能力不再是瓶颈；
  - 中游模型（DeepSeek-V3.2-Thinking）出现大量**数据与计算错误（DCE）**，源于长上下文中的时间推理退化

## 6. 主要结论与发现（续）

- **一致的失败模式（续）**：
  - 弱模型（GPT-4.1-Mini）的失败多为**工具边界错误（TBE）**与**无关响应错误（RNE）**，表明其尚未掌握基础的工具调用协议；
  - 这一错误类型随模型能力演进的迁移模式（弱模型：工具调用基础错误 → 中游模型：数据计算与时间推理错误 → 强模型：隐含系统配置推理错误）构成一个清晰的**能力发展阶梯**，有力地支撑了 PAUSE 对"配置感知"作为下一代能力瓶颈的论证。
- **购物任务表现**：
  - 各模型在购物任务上的得分普遍高于 hard 任务但低于 easy 任务，符合任务复杂度的预期排序；
  - 时间推理并非购物任务的核心瓶颈，因此 DeepSeek-V3.2-Thinking 与专有模型的差距显著缩小，进一步佐证不同类型任务所需能力的正交性；
  - 约束跟踪细节（如库存状态、优惠券条件、预算平衡）对模型状态维护能力提出持续的高要求，所有模型在 Voucher 和 Balance 子项上均出现明显短板。
- **消融实验结论**：
  - 在 hard 任务上注入策略引导提示 `P_rollout_k` 后，模型表现大幅提升，说明**当前模型并非完全不具备配置推理能力，而是难以主动发现隐含配置**——一旦被提示引导到正确的推理路径上，任务成功率显著上升。这提示未来可通过"推理时提示策略"或"工具调用规划辅助"来缓解能力缺口。
- **评估器一致性**：
  - Gemini-3-Flash 作为默认 LLM 评估器与人工标注的一致性良好，但不同评估器之间存在一定分歧，说明 LLM-as-judge 在开放任务的目标达成判断上仍存在误差，需依赖人工抽检与多评估器交叉验证来增强结论可靠性。
- **核心论断**：论文认为，现有模型在**以用户为中心的持久化状态推理**上存在系统性的、尚未被现有基准揭露的能力天花板，而 PAUSE 将该缺口量化为可复现的评测信号。

## 7. 贡献与创新点

- **基准层面**：提出 PAUSE，首个在统一服务环境中同时包含**持久用户状态、多服务集成、隐式配置依赖、权限门控**的评测基准，填补了从"工具调用准确性"到"个人 AI 助手真实服务能力"之间的评估空白。

- **框架层面**：将任务规格统一为 `T_k = {E_k, P_task_k, P_rollout_k, O_k, D_k}`，任何新任务只需按模板补充相应组件即可接入，为后续社区扩展提供了清晰的接口设计。

- **实证贡献**：在 9 个主流模型上系统评估，揭示出即使最先进的专有模型在隐含配置推理任务上亦不足 60% 的完成率，为社区提供了方向性的研究议程信号。

## 8. 局限与改进方向

- **数据合成与真实性**：任务场景基于模板与 LLM 生成，虽经多轮过滤，仍可能存在场景分布与真实用户请求的偏差；用户模拟器（Gemini-3-Flash）的行为模式较为单一，模拟的"用户"未必能覆盖真实用户的多样性（如含糊表达、错误指代、临时修改需求等）。
- **领域单一性**：仅实例化于个人健康管理，虽然健康领域天然适合验证状态化与权限推理（可穿戴数据、医疗服务、订阅支付），但购物任务已经体现了一定的跨域潜力，未来可拓展至金融、办公、出行等领域以检验框架的泛化性。
- **评估器依赖**：开放任务采用 LLM-as-judge 判断目标完成，尽管验证了与人工标注的一致性，但 judge 模型的偏差、幻觉与判定波动仍可能对最终分数产生微妙影响；且未报告不同 judge 温度、prompt 变体下的稳健性。
- **统计严谨性**：核心指标（TC、F1、购物子项）大多仅报告点估计，缺少置信区间、多重比较校正与显著性检验；多模型之间的微小差异（如 Gemini-3-Flash 与 DeepSeek-V3.2-Thinking 在购物任务接近）可能不具备统计意义。
- **模型覆盖度**：开源模型仅评估 DeepSeek-V3.2 一个系列，未能反映开源生态的多样性；也未包含 Llama、Qwen、Mistral 等主流开源模型。
- **采样稳定性**：作者自述未系统报告多次采样下的通过率指标（pass^k / pass@k），无法判断轨迹随机性对任务完成率的影响幅度。

## 9. 可复现性与资源可获取性

- **代码与数据**：论文以基准论文形式呈现，按该类工作的惯例，基准任务定义、生成流水线代码与评测脚本需配套开源。当前文本中未给出仓库链接或具体的开源协议说明，但设计上已为复现做好了铺垫（任务模板结构清晰、环境状态转移规则明确、评测指标公式完整）。
- **数据依赖**：基础数据采用合成模板 + 公开的 Kaggle FitBit 数据集，规避了专有数据壁垒；但合成数据生成依赖闭源 LLM API（Gemini-3-Flash 等），完全复现需要相应 API 授权与预算。
- **评估依赖**：评测框架本身依赖 LLM-as-judge 与人工标注双重验证，其中人工标注部分无法直接自动化复现，但作者已公开 4 个评估器与人工标注的一致性结果，可作为复现时的参考标定。
- **算力要求**：整体工作对本地算力的需求有限（主要是调用 API 进行 generation 和 judgment），但 API 调用规模与总成本未披露，可能影响完全复现的现实可行性。

## 10. 客观评价

- **优点**：
  - 问题定位准确且具有前瞻性——将评估视角从"工具调用正确性"转向"以用户为中心的持久状态与隐含配置推理"，准确切中了 LLM 作为个人助手智能体的核心痛点；
  - 方法设计严谨：三阶段生成流水线中的"目标对齐验证"环节保证了任务的可解性，杜绝了"基准任务本身不可完成"的常见缺陷；
  - 多维度指标体系设计合理，错误类型分类与消融实验提供了较强的可解释性；
  - 在多个 SOTA 模型上的一致表现表明所揭示的能力缺口是系统性的而非单一模型的偶然现象。
- **不足**：
  - 统计推断缺失（无置信区间、无显著性检验）削弱了部分对比结论的强度；
  - 任务数量（180 个）虽属中等，但相对任务种类的丰富度而言，每类任务的样本量有限，模型性能方差可能较大；
  - 用户模拟器的真实性、多轮交互的深度（对话轮次上限未明确报告）可能限制了策略探索的复杂度；
  - 领域实例化的选择虽合理，但健康数据的隐私敏感性可能限制了任务场景对真实产品环境的映射程度（如真实 EHR 数据缺乏），也使某些"用户状态"设计显得简化。
- **总体定位**：PAUSE 是一项设计精心、实证扎实的基准工作，在个人 AI 助手评估这一快速演进的方向上提出了有价值的评测范式。其结论为社区提供了清晰的能力风向标，方法论框架亦具备良好的扩展潜力。主要短板在于统计严谨性与领域覆盖度，这些可通过后续版本与社区共建来弥补。

## 11. 一句话总结

PAUSE 通过构建一个包含持久用户状态、隐式系统配置、权限门控与多服务集成的状态化评估环境，系统性揭示并量化了当前最强 LLM 在个人 AI 助手的"用户中心推理"场景下普遍存在的能力缺口（hard 任务完成率不足 60%），为下一代智能体评估与研究提供了可扩展的基准框架与诊断工具。
