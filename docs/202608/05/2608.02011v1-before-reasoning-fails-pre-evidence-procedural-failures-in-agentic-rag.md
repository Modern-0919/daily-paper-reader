## 摘要
代理式检索增强生成（RAG）系统可能在测试基于证据的推理之前就失败：代理可能检索到候选片段，但未检查即完成。我们将这种失败模式作为代理轨迹的程序性属性进行研究，利用保存的工具调用轨迹、检索到的证据、阅读的段落和最终答案，将错误答案分解为证据前纪律失败和黄金阅读后失败。在HotpotQA、2WikiMultiHopQA和MuSiQue上的12,000个成对轨迹中，两种失败类型在很大程度上是非冗余的：在regex和spaCy实体提取器中，同时触发的比率在[11.2%, 13.1%]之间。然后我们评估了Read-Gate，一种最小运行时不变式，要求代理在搜索之后、最终确定之前进行阅读。在原本会跳过阅读的轨迹上，强制阅读将LLM-Acc提高了14.9-19.9个百分点，在完整的最小推理单元上提高了3.2-9.4个百分点。额外的诊断表明，更大的隐藏思考预算不一定增加证据检查。这些结果共同表明，证据收集应作为轨迹级别的控制问题来评估，与答案侧的推理分开。

## Abstract
Agentic retrieval-augmented generation (RAG) systems can fail before evidence-conditioned reasoning is tested: an agent may retrieve candidate snippets but finalize without inspecting them. We study this failure mode as a procedural property of the agent trajectory, decomposing wrong answers into pre-evidence discipline failures and post-gold-read failures using saved tool-call traces, retrieved evidence, read passages, and final answers. Across 12,000 paired trajectories on HotpotQA, 2WikiMultiHopQA, and MuSiQue, the two failure types are largely non-redundant: the both-trigger rate is in [11.2%, 13.1%] across regex and spaCy entity extractors. We then evaluate Read-Gate, a minimal runtime invariant requiring an agent to read after search and before finalization. Forced reading improves LLM-Acc by 14.9-19.9 points on trajectories that would otherwise skip reading and by 3.2-9.4 points on full minimal-reasoning cells. Additional diagnostics show that larger hidden thinking budgets do not necessarily increase evidence inspection. Together, these results indicate that evidence-gathering should be evaluated as a trajectory-level control problem, separately from answer-side reasoning.

## 论文核心问题与整体含义（研究动机与背景）

- **核心问题**：代理式检索增强生成（Agentic RAG）系统可能在"基于证据的推理"开始之前就已失败——代理执行了搜索、收到了候选片段，却**未读取任何检索内容就直接给出最终答案**。这种"证据前程序性失败"（pre-evidence procedural failure）不同于常规的推理错误，因为模型根本没有检查它所依赖的证据。
- **与固定上下文 RAG 的区别**：代理式 RAG 可自主决定何时搜索、读取哪些结果、何时停止作答，这种灵活性在多跳问答中很有用，但也引入了程序性风险——代理可能仅凭搜索摘要（snippet）作答、只读部分证据链、或完全不读就终止。仅看最终答案正确率无法揭示代理是否真正执行了证据收集流程。
- **核心主张**：证据收集应被视为一个**轨迹级控制问题**，与答案侧推理分开评估和优化。将"未读证据就作答"与"读了证据仍答错"混为一谈，会掩盖一个可操作的失败来源。

## 论文提出的方法论

### 1. 轨迹级错误分解框架
- 将错误答案按固定优先级划分为互斥的四个桶：
  - **纪律失败（Edisc）**：回答错误且违反证据检查程序，含三个可观测子类型：
    - 零读取终结（read count = 0）
    - 仅摘要终结（答案实体只出现在检索摘要中，从未出现在读取块中）
    - 低证据终结（问题命名实体在读取块中的覆盖率 < 80%）
  - **黄金读取后失败（Epost）**：检索成功、读取了至少一个黄金支持块、但仍答错
  - **检索失败（Eretr）**：黄金证据未出现在 top-k 检索结果中
  - **歧义/残余（Eamb）**：无法干净归类的剩余情况
- 优先级顺序：Ewrong = Edisc ∪ Epost ∪ Eretr ∪ Eamb；同时采用**多标签独立指标**避免互斥分配掩盖共现标签。
- 标签是基于保存轨迹的**确定性测量**，而非对模型潜在认知的推断。

### 2. Read-Gate：运行时证据检查约束
- 最小环境级不变式：**搜索后必须读取，才能作答**。
- 实现方式：若模型在 read count = 0 时发出 final 动作，环境拒绝该动作并返回纠正性观察提示（"You MUST call read on a promising chunk before giving the final answer"），循环继续。
- 不改变模型权重、检索器、索引、评判器、解码温度或推理预算；仅改变环境的执行规则。

### 3. 三个可证伪预测
- **H1 非冗余性**：纪律失败与黄金读取后失败不应坍缩为同一失败轴。
- **H2 条件收益**：Read-Gate 的精度增益应随残余纪律错误而非单纯推理水平变化。
- **H3 差异响应**：Read-Gate 与推理努力应在 (Pdisc, Ppost) 平面上产生可区分的特征。

## 实验设计

### 数据集与基准
- **三个维基百科式多跳 QA 基准**：HotpotQA、2WikiMultiHopQA、MuSiQue。
- 每数据集-条件对 n = 1,000 题，按问题 ID 配对。
- 共 **12,000 条 OpenAI 控制器轨迹**（3 数据集 × 4 条件 × 1,000 题）：gpt-4o-mini、gpt-5-mini minimal、gpt-5-mini medium、gpt-5-mini minimal + Read-Gate。

### 代理接口与工具
- 双工具接口：**混合搜索**（BM25 + 稠密检索，倒数秩融合，内部 k=60，返回 top-5 块 ID 及摘要）+ **读取**（按块 ID 展开全文）。
- 0.6B 稠密嵌入模型（Qwen3-Embedding-0.6B），最大循环预算 10，最大 token 预算 128k，温度 0.0。

### 对比方法与控制
- **Prompt-only 严格提示控制**：仅修改系统提示禁止跳过读取，无环境级门控。
- **ctx-inject 三臂消融**：同触发器但将 rank-1 块文本静默附加为 user 角色观察，不发出 read 工具调用。
- **四臂通道-动作分解探针**（MuSiQue，n=500）：区分工具角色注入 vs 用户角色注入 vs Read-Gate 自发性读取动作。
- **推理努力对比**：gpt-5-mini minimal vs medium。
- **外部模型诊断**：Gemini 2.5 Flash 隐藏思考预算开关（0 vs 1024 tokens）。
- **跨系列泛化**：Qwen2.5-Instruct（3B/7B/14B），每单元 n=200。
- **网关家族探针**：no-read + snippet / + lowev / full 等更强变体（n=100）。
- **接口粒度对比**：与 A-RAG 三工具分层接口比较。

### 评估协议
- 主要指标：**LLM-Acc**（固定 gpt-5-mini 评判器，温度 0.0，二值语义等价判断）；次要指标：Contain-Acc。
- 交叉评判鲁棒性：Gemini 2.5 Pro 重判 n=450 分层样本，κ=0.924。
- 统计检验：配对 McNemar 检验、问题聚类稳健标准误、配对 bootstrap、分层标签置换检验、Benjamini-Hochberg 多重检验校正。

## 主要结论与发现

1. **两类失败高度非冗余**：在 3,807 个错误案例中，纪律失败与黄金读取后失败的同时触发率仅为 [11.2%, 13.1%]（两种实体提取器下稳定），远低于 60% 的坍缩阈值；纪律失败独占份额（46.5-50.2%）是黄金读取后失败独占份额（19.5-21.4%）的两倍以上。
2. **Read-Gate 有效恢复跳读失败**：在自愿策略下零读取终结的子集上，强制读取使 LLM-Acc 提升 **+14.9 至 +19.9 个百分点**（McNemar p < 10⁻⁴）；完整最小推理单元上提升 **+3.2（HotpotQA）/ +5.3（2Wiki）/ +9.4（MuSiQue）**。
3. **收益与残余纪律错误成正比（H2 成立）**：最小推理单元增益呈单调模式（纪律错误越高，增益越大）；medium 推理单元纪律错误低，增益为零或负（2Wiki 为 −7.0）。
4. **不只是上下文注入**：ctx-inject 无法复现 Read-Gate 的增益（2Wiki 上甚至净负 −7.4 pp）；通道差异不显著，剩余增益与代理**自发执行的读取动作**相关（动作承诺解释）。
5. **Read-Gate 与推理努力产生不同特征（H3 成立）**：Read-Gate 主要修复"是否检查证据"（Pdisc OR 0.38），在匹配读取曝光后对 Ppost 无测量效应（OR 1.00）；推理努力同时降低两个指标（Pdisc OR 0.22，Ppost OR 0.51）且二者交互显著。
6. **隐藏思考预算不保证证据检查**：Gemini 2.5 Flash 开启 1024-token 思考预算后，三数据集上零读取终结率反而上升（+5.7 / +24.8 / +42.6 pp），配对正确数净减 44/67/73。
7. **成本-精度权衡**：Read-Gate 加在最小推理上可弥合 20-24% 到 medium 推理的 LLM-Acc 差距，但无法替代更强推理。

## 优点

- **问题识别新颖且重要**：将"证据前终结"从一般推理失败中独立出来，首次系统化定义为轨迹级程序性属性，填补了代理式 RAG 评估的盲区。
- **分解框架操作性强**：完全基于保存轨迹的确定性测量，可复现、无需推断潜在模型意图；多标签分析避免了互斥分配的信息丢失。
- **干预极简且通用**：Read-Gate 不改变模型、检索器或推理预算，仅修改环境规则，是"最弱可行不变量"，可直接部署于任何具有离散工具动作边界的代理系统。
- **机制验证扎实**：通过三臂消融、四臂通道-动作分解、提示控制、跨评判器一致性（κ=0.924）、跨模型系列（Qwen2.5）验证，排除了上下文注入、提示效应、评判偏倚等替代解释。
- **统计分析严谨**：配对设计 + McNemar + bootstrap + 聚类稳健标准误 + 置换检验 + FDR/Bonferroni 校正，对 11 项关键检验全部通过校正。
- **可复现性高**：发布全部代码、复现脚本及 33,950 条原始轨迹，承诺无需 API 访问即可复现每个数字。
- **诚实标注边界**：作者明确区分主实验（n=1,000）、边界消融（n=100）与方向性证据（跨系列 n=200），不做过度声明。

## 不足与局限

- **实验覆盖范围窄**：
  - 主实验限于成本敏感型控制器（gpt-4o-mini、gpt-5-mini），未覆盖更大规模前沿控制器；
  - 所有数据集均为英文维基百科式多跳 QA，非英文设置和其他 RAG 领域未验证；
  - 四臂动作-通道分解仅在 MuSiQue 单数据集、单一骨干上进行，泛化性待证。
- **框架适用范围有限

**框架适用范围有限**：Read-Gate 仅适用于具备离散搜索/读取动作边界的工具型代理系统；对采用隐式检索或端到端记忆融合的架构（如长上下文内嵌检索、RAG 与生成一体化模型）并不适用。其"动作层面强制约束"的设计哲学能否迁移到这些无显式动作边界的场景，论文未给出方案。
- **证据质量度量粗糙**：将"黄金证据是否出现在读取块中"作为标准，依赖于数据集提供的黄金支持文档标注。对于缺乏该标注的开放域任务，Epost 的判定需要代用规则，但论文未验证代用规则在无标注数据上的可靠性；低证据覆盖率阈值（0.8）也仅基于单数据集的经验选择，未见理论依据或充分的敏感性分析。
- **控制器代表性不足**：主实验仅使用 OpenAI 闭源模型，且均为成本敏感型小模型；跨系列验证（Qwen2.5）虽补充了开源的证据，但只跑了 n=200 且无 Read-Gate 配对验证，无法确认门控收益在更大开源模型上的稳定性。
- **对"不读就错"因果链的直接证据较弱**：虽然 Read-Gate 实验证明了强制读取能提升精度，但该设计无法直接区分"受益于读取到的信息"与"受益于被强制多执行思考循环"两种机制；四臂探针虽部分排除了上下文注入解释，但多出的迭代本身也可能带来额外推理机会。
- **检索质量中介效应未分解**：Read-Gate 的收益可能取决于当前检索 top-5 中确实含有可读证据；若检索器质量下降，强制读取可能只是强制读取噪声块，增益会衰减。论文未在检索器弱化条件下检验该边界条件。
- **未见真实用户场景验证**：所有实验基于人工构造的多跳 QA 基准，未覆盖真实代理工作流中常见的搜索查询失败、工具返回错误、长会话状态污染等生态级失败模式。

## 对领域的影响与启示

- **评估范式的转变**：论文最核心的贡献不是某个具体干预，而是将代理 RAG 的评估从"答案正确率"推向"轨迹级过程合规性"。其四桶错误分解框架为社区提供了一种可复用的诊断语言：纪律失败、黄金读取后失败、检索失败、歧义残余——这套词汇有望成为后续代理评估工作的标准分类。
- **环境级对齐的可行性示范**：Read-Gate 证明了在不动模型权重的前提下，仅通过修改环境执行规则就能显著改变代理行为，这为"轻量级行为约束"（而非微调或提示工程）提供了一条新路径，尤其适用于推理成本敏感、模型不可微调的场景。
- **推理努力与工具纪律的二维解耦**：论文通过 H3 的验证表明，增加模型思考预算和加强工具使用纪律是两个正交的"杠杆"，可以分别作用于失败空间的不同区域。这一发现对成本优化的实际部署具有直接指导意义：与其无条件增加推理预算，不如先以近乎零成本的规则约束消除纪律失败。
- **对"思考时间越长越好"的警示**：Gemini 隐藏思考预算实验的结果提醒社区，推理时计算增加并不必然转化为更好的工具使用纪律，甚至可能加剧跳过读取的行为；对代理而言，"想得多"与"查得勤"必须分开衡量。

## 未来工作方向

- **将门控扩展为自适应策略**：当前 Read-Gate 是"一刀切"的二元约束（搜索后必须读取才能作答）。未来可研究基于置信度或时间预算的自适应门控，在低风险问题中绕过读取以节省延迟。
- **多步证据链的细粒度监控**：将当前"至少读取一个黄金块"的宽松标准升级为"是否读取了支撑最终答案的完整证据链"，并设计链级（trajectory-wide）的纪律度量。
- **检索质量与门控的联合优化**：探索当检索 top-k 质量不足时，Read-Gate 是否应触发二次搜索而非强制读取，以及如何让模型具备"意识到证据不足并主动发起新检索"的能力。
- **跨语言与跨任务的泛化验证**：将分解框架与门控机制迁移到非英语多跳 QA、金融/法律文档问答、以及带工具调用的编码代理等场景。
- **训练信号回传**：将纪律失败作为奖励塑形（reward shaping）的信号，通过 RL 微调让模型内化"先读后答"的偏好，而非依赖外部运行时强制——这将检验 Read-Gate 的约束能否被"学习"而非"执行"。

## 总评

本文的核心贡献可概括为：**将代理式 RAG 中此前被混淆为通用推理错误的一类失败类型（证据前程序性失败）分离出来，证明其具有独立的发生机制、可检测的属性标签与可修复的干预手段**。其最大的方法论价值在于提出了完全基于可观测轨迹的确定性错误分解框架，使得"代理是否真正读了证据"成为可度量、可复现、可比较的工程指标。Read-Gate 作为一种最小干预，证明了环境级规则约束在改善工具使用纪律上的有效性，但其收益边界也清楚表明：纪律约束只能消除"不查就答"的错误，无法替代真正更强的推理能力。总体而言，这是一篇问题定义清晰、实验设计严谨、结论克制的实证研究，对代理 RAG 的评估与部署实践具有直接参考价值。
