## 摘要
大型语言模型（LLM）代理越来越多地被委以自然语言工作流指令（例如零售支付政策），这些指令不仅规定了要实现的结果，还规定了允许的步骤、分支和工具交互。然而，当这些指令作为提示上下文提供时，模型同时控制着过程选择和步骤执行。随着交互的累积，代理可能跳过必需步骤、采取不支持的分支，或以不支持的参数或效果执行有效步骤——我们将这种失败模式称为工作流不一致。在这项工作中，我们提出了COVENANT，一种用于工作流一致代理执行的编译器-解释器架构。我们的关键见解是将工作流指令视为源程序而非提示。COVENANT将指令转换为工作流抽象语法树（WAST），并将其降级为工作流控制流图（WCFG）。在运行时，控制器逐节点解释WCFG，在提交控制器状态或推进图之前，对照从指令中提取的要求检查每个提议，并返回诊断反馈以供修复。为了评估COVENANT，我们使用了来自三个现有基准的120个案例，涵盖七个工作流场景。与最先进的LLM代理相比，COVENANT将基准成功率从50.00%提高到83.33%，并将工作流不一致失败率从42.50%降低到15.83%（相对降低62.75%）。这些结果表明，COVENANT显著缓解了工作流不一致，将LLM代理的一致性从孤立的提示遵循推进到复杂多步骤工作流的可靠执行。

## Abstract
Large language model (LLM) agents are increasingly entrusted with natural-language workflow instructions (e.g., retail-payment policies) that specify not only what outcome to achieve, but also which steps, branches, and tool interactions are permitted. When these instructions are supplied as prompt context, however, the model retains control over both procedure selection and step execution. As interactions accumulate, an agent can skip required steps, take unsupported branches, or execute a valid step with unsupported arguments or effects--a failure mode we call workflow misalignment. In this work, we propose COVENANT, a compiler-and-interpreter architecture for workflow-aligned agent execution. Our key insight is to treat workflow instructions as source programs rather than prompts. COVENANT converts the instructions into a workflow abstract syntax tree (WAST) and lowers it to a workflow control-flow graph (WCFG). At runtime, a controller interprets the WCFG one node at a time, checks each proposal against requirements extracted from the instructions before committing controller state or advancing the graph, and returns diagnostic feedback for repair. To evaluate COVENANT, we use 120 cases from three existing benchmarks, spanning seven workflow scenarios. Compared with state-of-the-art LLM agents, COVENANT improves benchmark success from 50.00% to 83.33% and reduces the workflow-misalignment failure rate from 42.50% to 15.83% (62.75% relative). These results show that COVENANT substantially mitigates workflow misalignment, moving LLM-agent alignment beyond isolated prompt following toward reliable execution of complex and multi-step workflows.

# COVENANT：面向一致代理执行的自然语言工作流编译

## 1. 核心问题与整体含义

**研究动机与背景**:
- LLM 代理被越来越多地应用于需要多步推理、工具调用和外部环境交互的复杂任务，这些任务往往受自然语言编写的工作流指令（如标准操作流程 SOP、服务政策、合规流程、工具使用协议）约束。
- 现有做法将工作流指令作为提示上下文交给模型，然而模型同时控制**过程选择**（走哪条分支、按什么顺序执行）与**步骤执行**（参数、工具调用细节），随着交互累积，极易产生两类典型的**工作流失配**失败：
  - **轨迹失配**：跳过必需步骤、选择不支持的流程分支或改变预期顺序。
  - **执行失配**：选对了流程路径但错误执行该步骤，如伪造无证据支持的参数值。
- 现有的一些工作流遵循系统（如 AgentLTL、FlowAgent）通常假设指令已被改写为规范或半结构化形式，这在真实场景中难以满足；人工将自然语言指令转为指定表示会带来昂贵的编写与维护成本。
- COVENANT 的核心见解是：**将工作流指令视为源程序而非提示**，借鉴传统编译器理论，把自由文本指令编译为可解释执行的结构化表示，从而从机制上约束代理沿指令允许的路径执行。

## 2. 方法论

**核心思想**：构建「编译器-解释器」架构，将自然语言工作流指令离线编译，并在运行时由控制器监督代理逐步执行。

**总体架构包含两条主线**：
- **离线编译阶段**：将指令构建为工作流抽象语法树（WAST），再降级为工作流控制流图（WCFG）。
- **运行时受控执行阶段**：控制器（解释器）持有 WCFG 光标，逐节点向目标代理暴露当前节点的任务与上下文，校验代理提议后方提交状态并推进遍历，失败则返回诊断反馈要求重试。

**离线编译的两阶段**：
1. **Stage I：层次化 WAST 构建（三段式前端）**
   - 词法分析：按标题、编号步骤、段落边界切分指令文档，使用 schema 约束的 LLM 为每个块标注程序性角色。
   - 语法解析：以定义的语法为输出约束，从各块提取有序动作、守卫条件及显式备选分支。
   - 语法定向构造：确定性将动作映射为步骤节点、守卫备选映射为分支节点、源码顺序映射为 `seq`，LLM 仅提供局部语义解读，全局树组装由编译器控制。
2. **Stage II：WCFG 降级**
   - 将 WAST 转为带类型节点和有守卫边的控制流图：顺序动作映射为 `block`，守卫转为 `decision`（true/false 后继），分支汇合处插入 `merge`，最终输出成为 `exit` 节点的字段。
   - 该降级是**路径保持的**：WCFG 的每条 entry-to-exit 路径与 WAST 的每条路径一一对应，从而保证控制流层面的对齐（Appendix B 给出形式化定义与定理证明）。

**运行时控制算法（Algorithm 2 核心逻辑）**：
- 控制器持有活动节点光标，只向目标代理暴露该节点任务、相关交互历史、辅助指令和响应 schema。
- 运行代理获得结构化结果 `(r, h)` 后，依次执行：
  - 协议检查（ParseAndProtocolChecks）：验证控制器-代理交换格式。
  - 语义属性检查（SemanticChecks）：对照编译期间绑定的节点属性（如源对齐、约束满足、候选覆盖、目标一致、输出契约、最终迹一致）验证提议、状态更新或输出。
- 仅当所有检查通过时才提交状态并推进 WCFG 光标；失败则丢弃补丁、保留当前节点、返回反馈重试；重试耗尽则阻断执行。

**形式化定义**：
- 工作流对齐（Definition 1）：策略π与环境Env 诱导的执行轨迹满足 `τ ∈ T(W,I)`（T(W,I) 为工作流允许的交互轨迹集）。
- 定理 1（路径保持）：正常化 WAST 降级所得 WCFG 的可行路径语言与 WAST 路径语言完全一致。
- 定理 2（WCFG 路径可靠性）：若前端提取满足路径可靠性前提（未发明指令禁止的动作顺序或分支结果），则 WCFG 的每条可行路径在控制流层面都被源工作流许可。
- 定理 3 与 4（控制器保证）：所有提交的状态更新均通过全部启用的阻塞检查；被拒绝的补丁不会污染已提交的控制器状态。

## 6. 主要结论与发现

- **端到端效果**：全部 25 个配对单元均获得改进。最强配置（Hermes Agent + GLM-5.1）成功率从 50.00%（60/120）提升至 83.33%（100/120）；3,000 个配对实例的总体成功率从 43.20% 升至 73.10%（+29.90 点）。
- **失配率下降**：可归因工作流失配率平均从 51.03% 降至 22.60%（相对降低 55.72%）；用案例簇自举的 95% 置信区间为 [21.73, 35.27] 点绝对降幅。论文摘要表述的最佳配置失配率从 42.50% 降至 15.83%（相对降低 62.75%）。
- **两类失配均显著下降**：轨迹失配率从 12.93% 降至 5.60%（−56.70%），执行失配率从 38.10% 降至 17.00%（−55.38%）。
- **场景层级增益**：状态依赖（+65.75 点）、参数规范化（+46.95）和零售（+38.45）增益最大；**航空是唯一负增益场景**（−4.00），主要因 airline_0029 任务在 25 个单元中 24 个发生退化——COVENANT 只取消一个符合条件的预订、遗漏强制确认或在不适用政策下继续执行。
- **消融发现**：最大的增益来自控制器拥有的 WCFG 遍历（+28.24 点），属性检查与修复机制提供额外 +3.53 点。
- **压力测试**：分支点增多使对齐率从 80% 降至 25%；单步工具交互次数增加使对齐率从 100% 降至 66.7%，验证了工作流失配随指令复杂化而加剧的假设。

## 7. 优点

1. **问题定义清晰**：将自然语言工作流遵循形式化为「完整轨迹 T(W,I) 的成员问题」，分轨迹失配与执行失配两类，便于量化与归因。
2. **思想新颖且系统**：借鉴传统编译器三阶段前端与 LLVM 类图 IR 的低级化思想，并将其应用于 LLM 代理的工作流遵循，给出形式化语法与路径保持定理，而非仅凭经验设计。
3. **LLM 角色分离合理**：LLM 只做局部语义解读，编译器负责全局树组装；运行时控制器拥有遍历权和提交权，显著降低模型自由发挥导致的漂移。
4. **配对 + 分层实验设计**：5 代理 × 5 模型全部配对比较，规模可观；消融逐层揭示增益来源，受控压力测试独立验证两个结构压力的影响；统计推断使用 clustered bootstrap，考虑了案例聚类相关性。
5. **诚实的局限分析**：明确披露航空场景退化、前端无端到端可靠性保证、消融跨版本等弱点，可信度较高。

## 8. 不足与局限

1. **前端可靠性无保证**：自然语言 → WAST/WCFG 的编译阶段没有端到端正确性保障；论文明确承认该语义验证留待未来工作。若编译产物本身存在错误（如遗漏约束、误解条件），运行时的完美执行也无法纠正。
2. **语义验证器可能出错**：属性检查依赖 LLM 验证器，可能拒绝正确结果或接受错误结果；部分属性仅作审计而不作为阻塞检查，覆盖不完整。
3. **航空场景存在退化**：未显式建模重复多预订闭包与策略依赖的拒绝/转接条件，导致部分完成或在不适用策略下继续执行，是唯一的负增益场景；说明当前方法在复杂、多目标、密集策略依赖的工作流上存在盲区。
4. **可推广性受限**：实验仅覆盖七个场景，受控压力测试是结构简化的合成压力，不能代表真实工作流中所有依赖关系；真实部署环境中的外部动作副作用（已执行但后来被拒绝的调用留在历史中）无法回滚。
5. **评估公平性细节**：单机对照系统采用非配对比较且部分系统存在案例覆盖缺口；失配标注由单一模型（GLM-5.1）完成，存在自查偏差的可能；消融实验横跨两个实现版本，结论强度受限。
6. **开销问题**：墙钟时间 2.48× 的开销主要来自多次验证、修复重试与控制器协调，对延迟敏感的生产场景可能构成部署障碍。
