## 摘要
多智能体系统（MAS）越来越多地被部署到复杂任务中。当输出错误或不令人满意时，用户必须通过检查智能体轨迹来手动定位智能体错误（即失败归因），并提供反馈以改进输出（即修复）。尽管最近有一些MAS失败归因的工作，但从此类错误中恢复的自动化机制仍未得到充分探索。为了填补这一空白，我们提出了MARS，一个基于搜索的框架，将MAS修复表述为蒙特卡洛树搜索（MCTS）过程，并通过诊断引导的扩展和分类增强的评估来导航潜在大修复空间。与标准MCTS通过完整展开来评估整个模拟不同，MARS使用部分展开评估智能体轨迹以减少token消耗。此外，我们引入了StateMAS，一个大规模MAS修复基准，包含1,310条可重放的多智能体失败轨迹，涵盖四种智能体架构和四种LLM后端。在StateMAS上的实验表明，MARS在所有设置中一致优于最先进的方法，绝对改进幅度从3.0%到12.1%，同时保持相当的token消耗成本。消融研究进一步证实，分类增强评估和诊断引导的扩展对于实现这些性能提升至关重要。

## Abstract
Multi-agent systems (MAS) are increasingly deployed to solve complex tasks. In case of incorrect or unsatisfactory outputs, users have to manually locate agent mistakes by inspecting agent trajectories (i.e., {\em failure attribution}) and provide feedback to refine the outputs (i.e., {\em repair}). Despite some recent work in MAS failure attribution, automated mechanisms to recover from such mistakes remain largely unexplored. To bridge this gap, we propose MARS, a search-based framework that formulates MAS repair as a Monte Carlo Tree Search (MCTS) process and navigates the vast space of potential repairs via diagnosis-guided expansion with taxonomy-augmented evaluation. Unlike standard MCTS, which evaluates a complete simulation via full rollout, MARS evaluates the agent trajectory using partial rollout to reduce token consumption. Furthermore, we introduce StateMAS, a large-scale MAS repair benchmark with 1,310 replayable multi-agent failure trajectories spanning four types of agent architectures and four LLM backbones. Experiments on StateMAS demonstrate that MARS consistently outperforms state-of-the-art methods, achieving an absolute improvement from 3.0\% to 12.1\% across all settings, while maintaining a comparable token consumption cost. The ablation study further confirms that taxonomy-augmented evaluation and diagnosis-guided expansion are critical to achieving these performance gains.

## 2. 方法论

- **形式化定义**：MAS被建模为元组 \(M = \langle N, S, A, T \rangle\)，其中 \(N\) 为智能体集合，\(S\) 为可重放全局状态空间，\(A\) 为联合动作空间，\(T\) 为状态转移函数。一次运行产生轨迹 \(\tau=(s_0, a_0, s_1, a_1, \ldots, s_T)\)。修复干预定义为 \(\delta=(t, \phi)\)，即回滚到第 \(t\) 步并执行修复操作 \(\phi\)，搜索目标是找到干预序列 \(\Delta^*\) 以逐步修正错误。
- **核心思想**：将MCTS用于MAS修复搜索，树节点对应系统状态，搜索通过反复执行“选择-扩展-评估-反向传播”来探索不同修复路径。与标准MCTS不同，MARS使用**部分展开**（partial rollout）而不是完整展开，从而显著降低token消耗。
- **三大关键设计**：
  1. **部分展开与动作空间**：
     - **Rollback**：将轨迹截断到故障步，丢弃后续错误步骤，保留有效前缀并恢复状态。
     - **Guided Repair**：从回滚点恢复，在下一智能体步骤提示中注入修复指导 \(\phi\)，然后运行 \(L\) 步。
     - **Continuation**：不加指导，从当前状态继续运行 \(L\) 步，用于延伸有潜力的部分轨迹。
  2. **分类增强的评估与诊断**：
     - 基于MAST taxonomy归纳的**14种失败模式**（如步骤重复、不遵守任务规范、忽略同伴输入、过早终止等），设计为LLM评估器的检查清单。
     - LLM法官对轨迹进行诊断，输出诊断反馈 \(f\) 和分数 \(r \in [0,1]\)；分数采用**五级粒度评分规则**（Verified Completion 1.0、Strong Progress 0.8–0.9、Moderate Progress 0.5–0.7、Limited Progress 0.2–0.4、Failure/Divergence 0.0–0.1）。
     - 诊断反馈存储在节点中，供后续扩展使用；部分轨迹不会被误判为失败，只按当前进度计分。
  3. **诊断引导的节点扩展**：
     - 动作选择器在扩展前先审查节点存储的诊断反馈，修正可能的误判；如果确认失败则生成回滚步骤和修复建议，否则选择Guided Repair或Continuation。
     - 节点选择采用UCT公式：\(UCT(c) = \frac{Q(c)}{N(c)} + C \sqrt{\frac{\ln N(p)}{N(c)}}\)。
- **算法流程**（文字描述）：从失败轨迹初始化根节点 → 在预算内循环：使用UCT选择可扩展节点 → 动作选择器决定动作并创建子节点（部分展开） → LLM法官给出分数和诊断 → 反向传播更新Q和N → 若得分达到1.0则提前终止，否则继续。最终返回得分最高的轨迹作为修复结果。

## 7. 局限性与潜在风险

- **评估器可靠性风险**：
  - 论文依赖LLM作为法官对部分轨迹打分，而LLM对模糊进度的评分可能不稳定；若评委误判导致低质量节点被保留，修复搜索可能朝错误方向收敛。
- **修复能力边界**：
  - 干预动作局限于“回滚+指导”和“继续运行”两类，无法执行更深层的修改（如修改交互协议、更新系统提示、合并记忆等），因此对某些超出动作空间支持的失败类型无效。
- **计算成本仍然偏高**：
  - 尽管部分展开控制了单次rollout长度，但每轮搜索需同时运行多个分支的智能体交互和LLM评估器，整体token开销仍远高于单次重试（通常为几十倍），在长轨迹与复杂任务上的实际部署成本值得考虑。
- **状态可重放的假设约束**：
  - MARS要求系统状态可保存、可回滚、可重放，这依赖确定性环境和外部API的可重复调用；在真实网络环境、实时数据或不可逆副作用下，该假设可能不成立。
- **基准自建带来的潜在偏差**：
  - StateMAS的失败轨迹收集与MARS的修复设计由同一团队完成，失败模式的标注与评估提示可能隐含对MARS设计更友好的偏向，外部评测的公平性有待第三方验证。
