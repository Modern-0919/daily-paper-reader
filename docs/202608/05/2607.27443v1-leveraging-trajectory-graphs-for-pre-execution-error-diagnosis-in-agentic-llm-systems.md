## 摘要
基于大语言模型（LLM）的智能体在广泛的复杂交互任务中表现出卓越的性能。然而，它们往往难以应对具身智能等领域中常见的长期交互任务。这些环境中的复杂性和巨大的动作空间导致复合错误，一个次优动作就可能导致整个轨迹偏离，使智能体在低效或不可恢复的路径上耗尽有限的步数预算。为了在不进行昂贵微调的情况下解决这一难题，我们从软件调试中汲取灵感，通过分析执行日志来预先捕获错误。我们提出了 Trajectory Graph Copilot，一个新颖的框架，通过在动作执行前诊断潜在的动作错误，充当 LLM 智能体的“副驾驶”。其核心 Graph Debugger 将历史轨迹建模为概率图，并使用图神经网络来识别经常导致失败的序列动作模式。作为一种主动的诊断沙盒，我们的方法对可能有缺陷的动作提供早期警告，促使智能体自我纠正。这种动作前的错误诊断可防止代价高昂的错误，显著提升智能体成功完成长期任务的能力。在四个基准测试上使用三种 LLM 智能体进行的大量实验表明，平均通过率提高了 14.69%。

## Abstract
Large Language Model~(LLM)-based agents have demonstrated exceptional performance across a wide range of complex interactive tasks. However, they often struggle with long-horizon interactive tasks common in domains, such as embodied AI. The complexity and vast action spaces in these settings lead to compounding errors, where a single suboptimal action can derail an entire trajectory, causing the agent to exhaust its limited step budget on inefficient or unrecoverable paths. To overcome this without costly fine-tuning, we draw inspiration from software debugging, where execution logs are analyzed to preemptively catch errors. We propose \textit{Trajectory Graph Copilot}, a novel framework that acts as a ``copilot'' for LLM agents by diagnosing potential action errors before they are executed. At its core,\textit{Graph Debugger} models historical trajectories as a probabilistic graph and uses a Graph Neural Network to identify sequential action patterns that frequently lead to failure. Functioning as a proactive diagnostic sandbox, our method provides early warnings on potentially flawed actions, prompting the agent to self-correct. This pre-action error diagnosis prevents costly mistakes, significantly enhancing the agent's ability to complete long-horizon tasks successfully. The extensive experiments on four benchmarks with three LLM agents demonstrate a $14.69\%$ pass ratio improvement on average.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 问题建模：POMDP 与步骤级错误诊断

- 将LLM智能体的长视野任务交互建模为部分可观测马尔可夫决策过程（POMDP），定义为元组 M = (G, S, A, J, R, O, γ)。
- 将复杂任务分解为多个有序里程碑（milestones），动作质量取决于它推进到下一里程碑的进度。
- 定义六类细粒度错误标签空间 Y = {1, ..., C}：
  - **N.E.（No Error）**：动作正确指向下一里程碑；
  - **I.A.（Illegal Action）**：环境不允许的非法动作；
  - **R.A.（Repeated Action）**：重复执行过且结果相同的动作；
  - **I.T.（Incorrect Target）**：拿错目标物体或去错目的地；
  - **P.M.（Precondition Not Met）**：前置条件未满足但执行了依赖该条件的动作；
  - **C.M.（Condition Met, Action Not Taken）**：条件已满足且关键步骤可执行，但智能体执行了无关动作。
- 诊断目标为学习映射函数 f：(o₀, a₀, ..., oₜ, aₜ) → yₜ，提供远丰富于轨迹级稀疏奖励的步骤级反馈。

### 2.2 图构建（Graph Construction）

- 由于正式的状态空间难以在语言观测下直接建模，论文采用 **动作中心图（action-centric graph）** 而非状态中心图。
- 将观测（observation）内嵌为边属性，形成图 G = (V, E)，其中 V ⊆ A（动作节点），E ⊆ O（观测边）。
- 使用 NLTK 做文本预处理，对动作去重建立唯一节点集合，再按轨迹中的先后顺序连接节点。
- 使用预训练 BERT 初始化动作和观测嵌入。

### 2.3 潜在错误诊断（Potential Error Diagnosis）：TextGCN + GNN 节点分类

- 借鉴 TextGCN 思路，将轨迹视为"句子"，将错误检测转化为**轨迹节点的分类任务**。
- 邻接矩阵 A 定义（式1）：

```
A_ij =
  1  若 v_i, v_j ∈ A 且 [v_i, o, v_j] 是某轨迹 ξ 的子序列
  1  若 v_i ∈ A 且 v_j 是轨迹节点
  0  其他
```

- 同一动作对之间的多条观测取 BERT 嵌入的平均值作为边属性。
- 采用 K 层 GNN 进行 K 轮消息传递，更新规则为：

```
a_v^(l) = AGG^(l)( { h_u^(l-1) : u ∈ N(v) } )
h_v^(l) = COMBINE^(l)( h_v^(l-1), a_v^(l) )
```

- 最终对节点嵌入做 softmax 得到分类概率 Z = softmax(H)，以交叉熵损失训练（式2）。
- 测试时通过**动态图注入**（test-time graph injection）将新轨迹节点加入已有训练图，无需重训 GNN，且可局部化到 K 跳邻域内推理。

### 2.4 上下文学习反馈（In-Context Learning Feedback）

- 不微调底层LLM，而是在推理时通过 ICL 将结构化反馈信息增强到提示词中。
- 无反馈时：P_agent(A_{i+1} | O₀, A₀, ..., Oᵢ, Aᵢ)；
- 有反馈时：Graph Debugger 先评估候选动作 A_{i+1}，若判定为错误则生成反馈信号 Yᵢ，智能体按修正后的条件分布 P_agent(A'_{i+1} | ..., A_{i+1}, Yᵢ) 重新生成动作。
- 默认配置：每步最多 3 次尝试、置信度阈值 0.6、反馈中包含 3 个代表性失败示例。

### 2.5 理论分析（Theoretical Analysis）

- **Assumption 4.1（条件充分性）**：存在表示 S = MB_G(Y)（Y 在图构造下的马尔可夫毯），使得 Y ⊥⊥ X \ S | S，即动作标签仅由有限步骤决定，与马尔可夫决策过程一致。

## 6. 论文的主要结论与发现

1. **图方法显著优于序列方法**：Graph Debugger 在四个基准的错误检测准确率上全面超越文本分类、检索、RAG 和 LLM-as-judge 方法，平均高出文本分类方法 5% 以上，与理论分析（更低贝叶斯风险、更低样本复杂度）一致。
2. **一体化框架有效提升智能体成功率**：Trajectory Graph Copilot 在四个基准和三个LLM上平均提升 Pass Ratio **14.69%**，优于 TF-IDF、GTR、Gemma3（RAG）和 GPT4o（LLM判官）等反馈基线，也优于 ReAct 和 Reflexion 两种提示方法。
3. **LLM-as-judge 检测精度低但反馈仍有效**：即便 LLM 判官的错误检测率很差，其提供的分析仍有助智能体改进，说明"有用的分析"和"正确的标签"可以解耦。
4. **GR 与 PR 并不直接相关**：反馈机制鼓励动作多样性，即使 GR 低于基线（如 TextWorld），PR 仍可提升。
5. **零样本设置优于一样本/三样本设置**：额外样本可能引入提示偏差，反而损害 LLM 判官性能。
6. **消融结论**：有向图优于无向图（POMDP 依赖本质是有方向的）、BERT 嵌入优于 one-hot、反馈放在用户提示中效果最佳、尝试次数存在最优值（过多尝试反而降低性能）、置信度阈值影响较小（检测器足够强时）、过多错误样本会引入偏差损害 GR。

## 7. 优点：方法或实验设计上的亮点

- **范式创新**：从"事后整条轨迹学习"转向"执行前步骤级诊断"，类比软件调试（debugger），思想清晰、类比自然且有启发力；
- **图建模的合理性**：以动作中心图+观测为边属性，在设计上规避了 POMDP 状态不可观测和自然语言状态难离散化的困难，是一个实用的折中方案；
- **理论支撑**：不只是经验方法，还提供贝叶斯风险排序和样本复杂度的理论证明（基于马尔可夫毯充分性、数据处理不等式、Fano 不等式），为图方法的优势提供理论依据；
- **测试时动态图注入**：无需重训即可对未见轨迹实时诊断，具备实际部署价值；
- **模块化设计**：Graph Debugger 作为独立"诊断沙盒"，不直接给出正确动作，避免了对固定数据集的微调偏差，保留并鼓励 LLM 自身的推理能力，利于泛化；
- **不做环境特定错误假设**：六类错误定义不绑定特定环境，易于迁移到新环境；
- **实验丰富且严谨**：多种群规模、消融组合、5 次重复方差检验、标注质量交叉验证（Kappa 系数）、噪声鲁棒性分析，全面且扎实。

## 8. 不足与局限

- **数据收集成本**：方法需要预先收集大量带标注轨迹数据（论文明确承认此为局限性），在历史轨迹数据稀缺的新任务上训练成本较高；
- **无持续更新机制**：轨迹池和动作中心图未在工作中实现动态更新，虽然作者将其列为未来方向；
- **评价指标单一化**：PR 是核心指标，但 GR 与 PR 的关系未完全厘清，且 GR 只是动作合法性的粗粒度指标，不能反映动作质量；
- **中等规模 LLM 局限**：反馈评估主要在 GPT4o-mini、Qwen2.5-14B、Gemma3-27B 上进行，未覆盖超大规模模型（如 GPT-4o 全量、Claude、Gemini Ultra 等）在超大模型上的适用性；
- **标签依赖 LLM + 规则过滤**：虽然用 GPT-OSS-120B 交叉验证达到了较高的 Kappa 值，但标注流程仍有残余噪声风险；
- **资源信息不完整**：未报告详细的训练时长、总 GPU 消耗量或推理开销对比，图构建和 GNN 训练的工程成本难以精确评估；
- **TravelPlanner 上部分基线退化明显**：RAG 和 LLM-as-judge 在 TravelPlanner 上表现出现明显反转或崩塌（如 Qwen2.5 系列的准确率低至 0.95%~31%），说明这些基线在长观测环境下的脆弱性虽被揭示，但也暗示该环境的特殊性对方法泛化性的检验尚不充分；
- **理论假设的适用边界**：Assumption 4.1 的马尔可夫毯条件在复杂长程依赖下未必严格成立，理论结论的有效范围有待更深入验证。
