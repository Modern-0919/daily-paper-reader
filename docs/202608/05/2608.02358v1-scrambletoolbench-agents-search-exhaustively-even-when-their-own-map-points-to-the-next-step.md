## 摘要
为了在开放世界环境中稳健运行，自主智能体应能仅通过交互推断陌生系统的行为，即使在缺少文档的情况下也是如此。然而，现有的工具使用基准在静态环境中暴露语义化的工具模式，使智能体能够依赖先验知识而非自主发现。为解决这一局限，我们引入了ScrambleToolBench，一个交互式终端基准，旨在隔离行为推理。通过移除语义线索并强制实施连续任务课程，该基准要求智能体完全通过试错交互来发现隐藏的工具行为。该基准还引入了动态挑战，包括映射漂移、随机动作失败和时间执行窗口，以评估智能体能否在环境变化时修正和调整其假设。我们对最先进语言模型的评估表明，成功的初始发现并不能转化为稳健的适应。当面临映射漂移等结构变化时，智能体无法使用循环追踪等演绎策略，反而表现出信念惯性或退化为穷举搜索。增加测试时推理只会放大这种昂贵的暴力搜索，而非实现演绎恢复。虽然为智能体配备持久记忆能减少复合错误，但它们仍然无法高效推断结构变化，这凸显了当前智能体推理中的不足。

## Abstract
To operate robustly in open-world environments, autonomous agents should be able to infer the behavior of unfamiliar systems through interaction alone, even in the absence of documentation. However, existing tool-use benchmarks expose semantic tool schemas in static environments, allowing agents to rely on prior knowledge rather than autonomous discovery. To address this limitation, we introduce ScrambleToolBench, an interactive terminal benchmark designed to isolate behavioral reasoning. By removing semantic cues and enforcing a continuous task curriculum, the benchmark requires agents to uncover hidden tool behaviors entirely through trial-and-error interaction. The benchmark further introduces dynamic challenges, including mapping drift, stochastic action failures, and temporal execution windows, to evaluate whether agents can revise and adapt their hypotheses as the environment changes. Our evaluation of state-of-the-art language models reveals that successful initial discovery does not translate into robust adaptation. When faced with structural changes such as mapping drift, agents fail to use deductive strategies such as cycle tracing, and instead exhibit belief inertia or fall back to exhaustive search. Increasing test-time reasoning only amplifies this expensive brute-force search rather than enabling deductive recovery. While equipping agents with persistent memory reduces compounding errors, they remain unable to efficiently infer structural changes, highlighting a gap in current agent reasoning.

### 1. 核心问题与整体含义

- **研究动机**：在真实开放世界中，API文档往往不完整、过时或不可用，部署的系统可能与文档描述不符，且存在网络超时、服务迁移等动态变化。自主智能体应当能够仅通过与环境的交互（输入输出观察）推断工具行为，而非依赖函数名等语义线索或先验知识。
- **现有基准的缺陷**：当前工具使用基准（如ToolBench、MCP系列、SWE-bench、OSWorld、Terminal-Bench等）普遍存在两个问题——(1) 暴露语义化工具命名（如`read_file`），使模型可利用记忆化的先验知识而非推理；(2) 假设环境结构静态稳定，一旦工具被理解就保持不变，无法测试智能体在环境漂移下的适应性。
- **核心问题**：当前最先进的LLM智能体是否真正具备**行为推理（behavioral reasoning）**能力？即在无语义线索、且环境规则动态变化时，能否通过试错形成假设、检验假设、并在环境变化后修订假设？
- **整体含义**：论文揭示了一个关键差距——成功发现工具行为并不等于能适应工具行为的变化。模型倾向于坚持旧信念（belief inertia）或退化为穷举搜索，而非利用已知结构进行演绎推理。

### 2. 方法论：ScrambleToolBench基准

**核心思想**：创建一个"最坏情况"评测环境，通过彻底的语义混淆强制智能体进行纯粹的试验-错误式探索，并通过动态环境挑战测试假设的鲁棒性。

**关键技术细节**：

1. **四维语义混淆机制（Scrambling）**：
   - 函数标识符：随机化为`fn_3d8a`等无意义别名，初始模式完全省略参数定义
   - 参数键：赋予`arg_0`等通用名称，类型信息仅通过schema错误暴露
   - 输出字段：以函数特定前缀混淆（如`out_c2b`），隐藏可预测的结构信息
   - 执行状态：每集随机化成功/失败标记，成功字段系统性注入有效响应

2. **连续任务课程（Continuous Task Curriculum）**：每个episode包含N=5个顺序任务，共享连续上下文，任务间可重用已发现工具知识，预算跨任务累计（每任务100步）。三个明文元命令`submit_solution`、`skip_task`、`end_episode`作为导航锚点。

3. **三种正交动态环境挑战**：
   - **映射漂移（Mapping Drift）**：任务间以漂移比例（实验中ρ=0.25，即28个函数中7个）对函数标识符进行循环排列重新分配，模拟API迁移；元命令不受影响
   - **随机动作失败（Stochastic Action Failure）**：每次有效调用以概率p_fail=0.15返回超时消息，模拟瞬时网络故障；不消耗动作预算
   - **时间执行窗口（Temporal Execution Window）**：触发命令后限k=10步内完成序列并提交，超时则重置环境状态和所有中间变量

4. **循环追踪（Cycle Tracing）恢复策略（理论算法）**：
   - 核心观察：若旧标识符x调用后返回的是另一已知函数f'，由于映射是双射，f'的旧标识符x'必指向排列链的下一步。反复追溯该链即可在k-1=6次额外调用内找到目标函数的新标识符
   - 期望恢复成本公式：$$ \mathbb{E}[\Delta] = \left(1 - \frac{\binom{M-k}{r}}{\binom{M}{r}}\right)(k-1) = 4.25 \text{ extra actions} $$
   - 循环追踪在$k-1 < M/2$时优于随机穷举（本基准中6 < 14，满足条件）
   - 参考发现成本：完整操作发现所有工具需$A_{ref}^{disc} = 9 + 2(19) = 47$次调用

5. **持久记忆增强基线（+ Memory）**：维护两个结构化数据库——"任务配方"（参数化逻辑步骤序列）和"工具知识"（混淆标识符→推断行为、参数约束、置信度），每步序列化注入系统提示，支持模型在单个JSON响应中协同生成记忆更新，将学习与执行解耦。

### 3. 实验设计

- **基准环境**：Python模拟器（非Docker），提供28个核心API工具（文件系统、网络诊断、数据处理等）+ 3个受保护元命令 + 20个程序化任务模板（系统管理、诊断、网络安全场景），模板与工具集组合可程序化生成大量不同任务。
- **模型覆盖**：
  - 开源模型：Qwen 3.6系列（27B、35B-A3B）、Gemma 4系列（26B-A4B、31B）、GPT-OSS系列（20B、120B）
  - 专有模型：GPT-5.4/Mini、Gemini 2.5 Flash/Pro、Gemini 3.1 Flash Lite/Pro、Gemini 3.5 Flash、Claude Sonnet 4.5/5
- **渐进式难度条件**：Unscrambled（无混淆对照）→ Base（混淆基础）→ +Drift（映射漂移ρ=0.25，独立）→ +Failure（随机失败p=0.15，独立）→ +Window（时间窗口k=10，独立）→ +All（三者组合）
- **对比方法**：15个无记忆模型 + 4个代表性模型上的+Memory配对变体
- **评估指标**：Episode完成率（P_ep，所有5个任务成功比例）、平均解决任务数（T_avg）、动作效率、重试率、失败模式分布、陈旧工具调用数

### 6. 主要结论与发现

1. **语义线索依赖严重**：无混淆环境中模型高效完成任务（平均P_ep=0.93，约25-27步），但去除语义线索后多数模型崩溃至0.00完成率，暴露缺乏通用发现能力；仅Gemini 3.1 Pro、Gemini 3.5 Flash、Claude Sonnet 5保持1.00。
2. **动态环境导致性能雪崩**：映射漂移使基准平均P_ep降至0.32；随机失败降至0.23；时间窗口降至0.26；三者组合后平均完成率从93%骤降至3%，Claude Sonnet 5从完美表现跌至0.00。
3. **智能体无法利用演绎恢复策略**：面对映射漂移，模型不会使用循环追踪（理论预期4.25步的恢复成本），实际恢复开销达参考成本的5-9倍（如Claude Sonnet 5高推理为7.52×）。链跟随率（11.9%-14.1%）与随机基线（10.6%）无实质差异，即使记忆提供了可逆向查询的表也无法触发演绎推理。
4. **推理努力会放大穷举搜索而非促进演绎**：增加测试时推理可提升任务完成率（Gemini 3.1 Pro在Drift下P_ep从0.10升至0.90），但这是通过减少失败搜索实现的，并未导致链跟随率提升；Claude Sonnet 5高推理下较Gemini 3.1 Pro消耗3.5-4.6倍token。
5. **持久记忆是双刃剑**：+Memory平均恢复+0.09完成率和+0.59任务（+All条件下）；减少重复探索和累积错误（Gemini 3.1 Pro的+All完成率从0.20升至0.50）。但效果依赖模型自身的记忆更新策略，Claude Sonnet 4.5中记忆反而增加陈旧调用（2.38→2.76），表明不完善的更新策略会锁定过时映射。
6. **信念惯性与错误归因失败**：质量较差的模型无法区分瞬时噪声与结构变化，面对超时很快放弃正确假设；而面对映射失效则反复调用同一个已失效函数（Qwen 3.6 27B在Drift下每任务3.67次陈旧调用）。

### 7. 优点

- **问题定义的精准性**：明确指出"语义先验依赖"与"行为推理"之间的gap，将任务从"记忆测试"转向"推理测试"，设计直击要害。
- **环境动态的工程实现**：三种动态挑战（漂移/噪声/窗口）相互正交、可单独开关，且分别对应不同失效模式（结构变化/瞬时噪声/效率约束），设计极为系统。
- **循环追踪分析的理论深度**：给出了推导完整的恢复算法、期望成本公式（推导出4.25步的解析值）、可行性条件（k-1 < M/2），为衡量智能体是否符合理性标准提供了精准的理论基线，这是多数基准缺乏的严谨性。
- **多维度的行为学分析**：论文超越了简单的正确/错误二元度量，引入了即时/持续重试率、预算耗尽vs提前退出、陈旧工具调用、链跟随率等细粒度行为指标，能刻画模型的错误归因和信念更新机制。
- **记忆架构的实用意义**：将任务配方与工具知识分离的双数据库设计概念简洁、实现轻量，且结果显示了方向性价值，为后续智能体架构（状态外化）提供了实证依据。

### 8. 不足与局限

- **实验规模受限**：每条件仅20个episode，个别模型的失败率极高导致有效样本极少（如GPT-OSS系列在多数条件下0%完成率，表3中大量空项），统计把握度不足；未报告跨多个随机种子的方差不稳定性。
- **外部效度存疑**：基于Python模拟器而非真实操作系统/容器环境；语义混淆(如`fn_xxx`)是最坏情况，但真实API通常提供部分语义线索，实际部署中模型策略可能有差异。
- **循环追踪策略的推导条件过于理想**：算法假设智能体已从Task 1完整发现全部28个函数的映射（参考成本为48步）。但实际上模型在Task 1结束时仅覆盖20-22个函数，论文也承认"never finish discovery"，使得该理论基线在初始条件上对模型并不公平。
- **记忆增强基线评估深度不足**：论文仅测试了4组记忆配对模型，且未展示记忆对token成本的整体影响（仅动作数）；记忆依赖模型的JSON生成可靠性，未消融记忆本身的质量（如记忆写入频率、竞争性记忆条目等）。

- **局限性陈述缺失**：论文正文没有专门的"Limitations"章节，对样本量、模拟器外部效度、成本披露等方面缺少自省性讨论。
