## 摘要
随着基于大语言模型的智能体被部署在复杂、多步骤的工作流程中，一个关键的评估缺口逐渐显现：现有大多数基准仅评判最终结果，无法区分可靠的推理与偶然的成功，也无法将失败归因于特定的流程缺陷，从而阻碍了长周期任务中的归因分析。在本工作中，我们提出了ClawTrack，一个双重评估基准，同时衡量智能体实现了什么（任务分数）以及它是如何实现的（过程分数）。ClawTrack包含8个领域的320个任务，并配有25个以上确定性的模拟服务。一个过程评分器从四个维度（目标对齐、效率、信息利用和结果验证）对每个推理步骤进行评分，并以12,541个任务特定的评分细则为锚点。我们在超过16,000次试验中评估了21个模型，发现：（1）过程分数能有效地将成功与失败归因于特定的推理维度，过滤掉仅凭结果评估中难以发现的侥幸成功；（2）四个维度是互补的，其中结果验证是系统性的瓶颈；（3）该框架在不同的评判大语言模型选择上具有鲁棒性；（4）基于过程的轨迹过滤在不同模型规模上带来一致的训练后改进。

## Abstract
As LLM-based agents are deployed in complex, multi-step workflows, a critical evaluation gap has emerged: most existing benchmarks judge only final outcomes, unable to distinguish reliable reasoning from lucky success or attribute failures to specific process deficiencies, hindering attribution in long-horizon tasks.   In this work, we present ClawTrack, a dual-assessment benchmark that simultaneously measures what an agent achieves (Task Score) and how it achieves it (Process Score). ClawTrack comprises 320 tasks across 8 domains with 25+ deterministic mock services. A Process Grader scores each reasoning turn along four dimensions (goal alignment, efficiency, information utilization, and result verification), anchored by 12,541 task-specific rubric items. Evaluating 21 models over 16,000+ trials, we find that: (1) process scores effectively attribute success and failure to specific reasoning dimensions, filtering lucky passes invisible to outcome-only evaluation; (2) the four dimensions are complementary, with result verification as the systematic bottleneck; (3) the framework is robust to evaluator choice across different judge LLMs; and (4) process-based trajectory filtering yields consistent post-training improvements across model scales.

## 一、论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有的大语言模型（LLM）智能体基准大多采用**仅评估最终结果（outcome-only）** 的范式，将整个多步骤执行过程压缩为对最终状态是否满足任务要求的单一判断。
- **两大缺陷**：
  1. **幸运成功不可区分**：成功结果可能掩盖不可靠的过程——通过低效探索或侥幸捷径到达正确答案的智能体与遵循原则性推理路径的智能体获得相同分数，但前者本质上是脆弱的，难以在重复试验或任务变体中泛化，造成感知能力的虚高。
  2. **失败无法归因**：当智能体失败时，结果导向评估无法定位执行在何处中断、何种推理维度存在缺陷——是目标分解错位、效率低下、信息综合不足，还是缺乏自我验证。不同根因需要完全不同的修复策略。
- **整体含义**：随着智能体被部署在高风险场景中，执行方式直接关乎安全、合规和用户信任，过程盲区正成为一个日益关键的评估缺口。ClawTrack 的核心论点在于：**过程质量是一个独立的、多维度的构念，应被作为一等评估信号加以度量。**

## 二、论文提出的方法论

### 2.1 核心思想
ClawTrack 采用**双评估（dual-assessment）** 设计，同时衡量：
- **任务分数（Task Score）**：智能体实现了什么（最终结果）
- **过程分数（Process Score）**：智能体如何实现它（每一步推理质量）

### 2.2 任务套件（Task Suite）
- **320 个任务**，均匀分布在 8 个真实世界领域（教育、金融、法律、办公、DevOps、零售、旅行、媒体），每个领域 40 个任务。
- **6 种元能力**标注（多标签）：规划（87%）、搜索与检索（83%）、多模态理解、编码、安全判断、适应性。
- **25+ 确定性模拟服务**，基于 Docker 工作区，保证可复现性。
- 任务来源：160 个改编自现有基准（Claw-Eval、WildClawBench、PinchBench、GAIA），160 个为领域标注员新编写。

### 2.3 四层框架架构
1. **任务层（Task Layer）**：任务指令 + 输入工件 + 参考答案 + 任务特定评分细则。
2. **驱动层（Harness Layer）**：在 Docker 工作区启动模拟服务，注入输入文件，记录 ReAct 轨迹、审计日志和环境快照。
3. **评估层（Evaluation Layer）**：两个独立评估器——结果评分器（Outcome Grader）和过程评分器（Process Grader）。
4. **报告层（Reporting Layer）**：聚合多轮试验分数，生成可靠性感知指标、分维度诊断概况、跨模型排名。

### 2.4 评分协议（关键公式）

**任务分数**：
```
s_task = s_safe · (α · s_comp + β · s_rob)
```
- 其中 α = 0.80，β = 0.20；s_safe 为二值安全门槛（乘法门控），s_comp 为完成度，s_rob 为鲁棒性（对工具错误的恢复能力）。

**过程分数（单轮）**：
```
s_proc(t) = g_t · (w_e · e_t + w_i · i_t + w_v · v_t)
```
- 其中 w_e = w_i = 0.40，w_v = 0.20；g_t 为目标对齐（乘法门控，若追求无关子目标则整轮为零）；e_t 为效率，i_t 为信息利用，v_t 为结果验证。

**轨迹级过程分数**：所有轮次的算术平均值：s_proc = (1/T) · Σ s_proc(t)。

**双阈值通过准则**：
```
pass = 1 { s_task ≥ τ_task ∧ s_proc ≥ τ_proc }
```
- 其中 τ_task = 0.75，τ_proc = 0.60，每任务执行 k=3 次独立试验。
- **Pass@k**（至少一次通过）衡量峰值能力；**Pass k**（全部通过）衡量部署一致性。

### 2.5 半自动评分细则生成管线
- 4 个过程维度（目标对齐、效率、信息利用、结果验证）源自现有工具使用智能体推理质量研究的核心共识。
- **分阶段、按轮次**的粒度：按行为阶段（早期探索、信息收集、工具调用、综合、自我验证）分类，每个阶段配备专用评分锚点。
- **专家种子 + LLM 蒸馏**：8 个领域 × 5 名专家 × 5 个代表性任务 = 40 个种子任务，专家人工编写评分细则；用 Claude-Opus-4.8 将 40 个专家细则抽象为可复用的"评分细则生成技能"，然后为剩余 280 个任务生成细则；经自动一致性检查和人工审查。

### 2.6 轨迹过滤用于后训练

## 六、主要结论与发现

1. **峰值能力与一致性可以背离**：Claude-Opus-4.7 在 Pass@3 领先（76.4%），但 Claude-Opus-4.8 在 Pass 3（51.1% vs. 46.7%）和过程分数（0.670 vs. 0.660）上反超，揭示最佳单次试验模型并不等于最可靠模型。

2. **过程质量与任务成功相关但独立**：Pearson r = 0.466，Cohen's d = 0.945。双阈值准则有效过滤了 21.2% 的结果导向评估中不可见的侥幸成功。

3. **四维度中度正交，结果验证为最独立轴且为系统性瓶颈**：维度间相关性 r = 0.49–0.67；结果验证与其余维度相关性 ≤ 0.55，且在全部模型中的分布中位数（0.4–0.7）明显低于其他维度。

4. **框架对评估者选择鲁棒**：4 个不同评判 LLM 的成对任务级相关性均值 r = 0.81（最低 0.774，Gemini 同族最高 0.871），确认是评分细则而非评判模型先验在驱动评估。

5. **过程感知轨迹过滤带来一致的后训练改进**：在 Qwen3 三个规模上，相对于随机采样，过滤策略在 Pass@3 上提升 +10（14B）、+16（30B）、+19（80B），且 Pass 3 提升更显著，证明过程验证的轨迹产生更可靠的行为。

6. **领域专业化显著**：无单一模型主导所有领域。Gemini-3.1-Pro 领跑 Travel（90.0%）但在 Media 仅 20.5%；Claude-Opus-4.7 主导工具密集型领域但在 Education 仅 30.0%；GPT-5.5 最均衡。法律与媒体为最困难领域，DevOps 与零售最易。

- **方法创新性**：首次将过程质量作为一等评估信号，以四维度、五级评分、约 40 个任务特定评分项进行细粒度评分，并明确界定为独立于结果质量的多维构念。

- **评分可靠性**：半自动评分细则生成管线（40 个人工种子 + LLM 蒸馏 = 12,541 个评分项）大幅降低了人工成本；人类验证显示 LLM 评判与人类专家高度一致（Pearson r = 0.912，Cohen's κ = 0.851）。
- **实用性闭环**：将评估框架用于数据筛选，从诊断延伸到优化，展示了评估基准在训练数据整理中的实际价值，而不仅是排名工具。
- **分析深度**：逐轮轨迹案例分析（幸运通过、归因失败）展示了过程评分在可解释性和可操作性诊断方面的独特优势。
- **跨评估者鲁棒性验证**：四评判者交叉验证确保了框架不是单评判模型私有偏见的产物。

## 八、不足与局限

- **模拟环境与真实服务的差异**：依赖确定性模拟服务而非实时 API，冻结的模拟响应可能无法捕捉真实世界服务的全部变异性。
- **单一默认评判模型**：过程评分器默认实例化为 Claude-Opus-4.8，尽管跨评判者一致性高（r = 0.81），默认评判模型的系统性偏差仍可能传播到所有评估中。
- **维度覆盖不完整**：四维度框架（目标对齐、效率、信息利用、结果验证）可能未穷尽过程质量的所有方面，如创造力、用户沟通风格等维度未被评估。
- **评分细则生成的种子偏差**：从 40 个专家编写的种子评分细则中引导，种子集未充分代表的领域或任务类型可能获得较低质量的生成细则。
- **任务难度标注分层不细**：附录中将 medium-hard 并入 hard，可能损失难度细粒度分析的精确性。
- **结果验证维度的权重设计**：权重 0.20 低于效率和信息利用（各 0.40），而实验发现结果验证是最系统性的瓶颈维度——权重设定与瓶颈发现的适配性值得进一步讨论。

**基准博弈风险**：模型开发者如果专门针对 ClawTrack 的四个过程维度（目标对齐、效率、信息利用、结果验证）进行定向优化，可能为了获得高过程分数而过度拟合评分细则的表面特征，忽视过程质量中未被该框架捕捉的其他重要面向（如创造性问题解决、多轮对话中的用户意图澄清、安全推理的深层逻辑等），导致基准逐渐丧失区分度。不过，论文通过跨评判者鲁棒性验证、人类标注一致性检验以及多试验设计，在一定程度上缓解了直接"刷分"的可能性，但基准博弈的风险在长期演进中仍难以彻底消除。

## 九、总体评价

ClawTrack 是智能体评估领域的一项系统性、高质量的推进工作。其核心贡献不在于单一指标的改进，而在于**将"过程质量"从隐性的、直觉性的概念，转化为可操作、可验证、可训练的一等评估信号**。通过四维度的过程评分框架、双阈值通过准则、半自动评分细则生成管线和过程感知轨迹过滤闭环，论文构建了一个从"诊断能力"到"改进能力"的完整基础设施。尽管在模拟环境真实性、维度覆盖完整性和权重设计等方面仍有改进空间，但其方法论的严谨性、实验的充分性和分析的多层次性，使其成为未来智能体基准设计中一个重要的参照系。

## 十、对后续研究的启示

1. **基准设计应转向"过程—结果"双轨制**：结果导向评估可测"能做什么"，过程评估可测"如何做"，两者互补才能全面刻画智能体的可靠性。
2. **过程评分应具备任务特异性与可解释性**：通用评分维度（如四维度）需要结合任务特定评分细则（约 40 项/任务）才能产生有意义的信号，盲目使用通用提示词评估过程质量可能不够充分。
3. **评估与训练反馈应形成闭环**：将过程评分用于数据筛选（而非仅用于排名），是提升智能体可靠性的高效路径，其收益在更大规模模型上更为显著。
4. **多试验设计应成为评估标配**：Peak v.s. Consistent 的区分揭示了单次试验排名的局限性，ClawTrack 的 Pass@3 与 Pass 3 双指标为部署决策提供了更丰富的信息。
