## 摘要
基于大语言模型（LLM）的搜索代理通过与外部环境的多步交互来回答问题。然而，向LLM提供完整的执行轨迹会导致上下文无限增长并引入噪声。现有压缩方法在牺牲重要细节的情况下缩减上下文，且往往在没有修复由错误事实推导出的下游推理的情况下替换错误事实。为解决此问题，我们提出了ReTree，一种用于搜索代理的自我纠正树结构记忆机制。ReTree在保留源链接证据的同时构建有界的逐步推理上下文。它将搜索建模为证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与早期声明矛盾时，ReTree回溯到该声明引入的节点，替换过时证据，重新生成摘要，剪除受影响的子树，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并确保最终声明可追溯至检索到的段落。在四个公开问答和搜索基准上的实验表明，ReTree持续优于全轨迹ReAct，将答案准确率提升最高达25.6个百分点（pp）；全轨迹ReAct的平均最大逐步推理上下文是ReTree的$1.27$--$1.51$倍。这些结果确立了ReTree作为长程搜索中一种有效的自我纠正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

## 1. 核心问题与整体含义

- **研究动机**：基于 LLM 的搜索代理需要通过多步交互来回答复杂问题。然而，若将完整执行轨迹直接送入策略模型，会导致**每步推理上下文随搜索步数线性增长**，并累积无关或冲突的噪声。
- **已有方法的不足**：
  - 直接压缩上下文（摘要、报告式记忆）虽能控制长度，但会丢失事实级溯源信息，且压缩后的内容可能保留错误结论，却无法定位其来源。
  - 当检索到的新证据推翻早期事实时，已有方法通常只替换该事实本身，无法自动修复基于该事实推导出的下游结论，从而造成“错误级联”。
- **整体意义**：论文提出将“检索引发的错误级联”建模为**结构化状态修复问题**，要求搜索记忆同时满足三个条件：有界逐步上下文、声明到来源的可追溯性、依赖一致性修订。该工作为长程搜索代理提供了一种可编辑、可追溯、自纠正的工作记忆抽象。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：提出 ReTree——一种树结构的工作记忆机制，将搜索过程建模为“证据树”。每个节点存储有界摘要、局部引入的原子证据（含稳定标识符与来源 URL）、修订历史，以及父节点指针；边表示子节点状态是由父节点活跃证据推导而来。
- **上下文构建**：策略每次只接收当前节点摘要与 top-5 最相关证据（`C_k(M_t, q) = s_{n_t} ∥ TopK_k(A(n_t), q∥s_{n_t})`），从而保证每步推理上下文为 O(1)，不随轨迹增长。
- **扩展与源绑定**：每次检索最多获取 5 个段落，提取至多 6 条原子事实；通过段落索引而非 URL 生成绑定，避免模型伪造无法验证的引文。若新事实与当前证据兼容，则创建子节点并更新摘要。
- **冲突检测与回溯**：
  - 第一阶段：判断新事实是否与已有事实在同一实体、属性、作用域和时间下不兼容；只有满足条件才提议回溯。
  - 第二阶段：结合分支摘要、目标事实的修订历史，确认修复是否更受支持，以避免振荡。
  - 确认后：定位引入该被反驳证据的节点 `ι(j)`，替换其证据文本与来源，记录修订历史，从修正后的累积证据重新生成该节点摘要，**删除所有后代节点**，并将搜索恢复到该节点继续。
- **依赖一致性**：定义依赖集 `Dep_{t-1}(j)` 为受证据 `e_j` 直接或间接推导影响的状态组件；更新要求这些组件全部被无效或在新证据下重新生成（公式 4）。ReTree 用“祖先关系 + 子树剪枝”实现该原则的保守近似。
- **归属生成**：最终答案的每个声明映射到证据标识符，再经运行级映射到当前证据文本和 URL，最终解析到原始检索段落，支持段落级蕴含验证。
- **计算复杂度**：当前实现中 top-k 证据选择为 O(|A(n)|)，树定位为 O(|T|)，但主要开销在 LLM 调用与检索调用。

## 3. 实验设计

- **数据集**：4 个公开问答/搜索基准：
  - **Bamboogle**（125 题，全量）
  - **FRAMES**（824 题，全量）
  - **2WikiMultiHopQA**（600 题固定子集）
  - **HotpotQA**（600 题固定子集）
  - 合计 2,149 题/方法。
- **对比方法**：
  - **Full-Trajectory ReAct**：保留完整轨迹的标准 ReAct 基线，验证有界记忆的必要性。
  - **FlatUpdate**：与 ReTree 共享摘要、top-k 证据与冲突检测，但使用扁平列表原地更新，不进行依赖定位与子树剪枝；用于隔离“结构修复”的贡献。
  - **ReportMemory**：只维护一段动态生成的 200 词报告和 URL 集合，代表纯合成压缩方法。
- **指标**：
  - 答案质量：Judge Accuracy（GPT-5 按类型约束评估）和 Exact Match。
  - 归属质量：引用精度、召回、F1、未引用率，基于 NLI 段落蕴含检查（用于 600 题 FRAMES 子集诊断）。
  - 上下文与计算：平均最大每步策略上下文、模型调用次数、token 用量。

## 6. 主要结论与发现

- **答案质量**：ReTree 在 4 个数据集上均优于 Full-Trajectory ReAct，Judge Accuracy 相对提升 **8.3–25.6 个百分点**；总体（2,149 题）准确率提高 13.9 pp，EM 提高 7.4 pp。
- **优于有界基线**：ReTree 全面超过 FlatUpdate（每数据集 2.2–4.7 pp）；在除 2Wiki 外均超过 ReportMemory，总体领先最强基线 ReportMemory 3.0 pp。
- **上下文效率**：Full-Trajectory ReAct 的平均最大逐步策略上下文是 ReTree 的 **1.27–1.51×**；ReportMemory 上下文虽最小，但准确率大幅下降，说明单纯压缩不足以保证推理质量。
- **归属质量**：在 600 题 FRAMES 诊断上，ReTree 的 Citation Precision/Recall 为 44.5/41.3，高于 Full-Trajectory ReAct（37.7/27.1）和 ReportMemory（16.8/21.4）；ReportMemory 的未引用率最低（5.9%），但其引用段落与声明的支撑率极低。
- **核心论断**：长期搜索代理的工作记忆不仅应压缩上下文，还需保留“可修订的证据依赖结构”，以实现溯源感知的状态修复。

## 7. 优点

- **问题定义清晰**：将错误级联明确定义为结构修复问题，并给出三个可量化需求（有界上下文、可追溯性、依赖一致性更新）。
- **方法有理论根基**：借鉴真值维护系统（Truth Maintenance System）的依赖导向回溯思想，并将其适配到 LLM 搜索循环。
- **设计细节务实**：
  - 原子事实使用稳定 ID 和段落索引绑定，避免 URL 伪造。
  - 两阶段冲突确认（先冲突候选，后历史感知确认）可降低误回溯与振荡。
  - 摘要限制在 140 词且不复制证据，保持有界上下文。
  - 显式要求至少一次真实检索后才可停止，防止参数化答案混入。
- **实验设计有对比层次**：Full-Trajectory ReAct（无压缩）、FlatUpdate（扁平更新）、ReportMemory（纯压缩）逐步隔离 ReTree 的贡献，具备较好的可解释性。
- **评估细致**：不仅看最终答案准确率，还测量上下文实际大小、引用精度/召回、模型调用数/ token 开销等，全面反映成本和收益。

## 8. 不足与局限

- **硬剪枝可能过度破坏有效状态**：ReTree 将所有后代节点视为被反驳证据的依赖项，即使某些后代事实实际不受影响，也会被删除，导致冗余重检索和重生成。作者也承认选择性无效化是未来工作。
- **依赖冲突判断质量**：冲突判断器是准确性的瓶颈——假阴性会保留污染，假阳性会过度剪枝；尽管有同作用域规则和历史确认缓解，但无法完全避免。
- **外部记忆仍无限增长**：有界上下文不等于总记忆有界；证据存储会随检索持续扩大，线性选择与树遍历在超长轨迹中可能变慢。
- **计算开销**：相比 FlatUpdate，ReTree 多使用 7–11% 的模型调用和 10–13% 的 token，冲突确认、摘要重生成和搜索恢复都会增加成本。
- **实验覆盖有限**：
  - 仅使用 Qwen3-8B 单一模型，未验证在更大/更小模型上的表现。
  - 归属诊断仅在 FRAMES 子集上进行，未覆盖所有数据集。
  - 未报告方差/显著性检验，也未提供不同随机种子下的稳定性。
  - 未评估超参数（如 top-k、摘要长度）的影响。
- **应用范围受限**：ReTree 是针对搜索/问答场景的工作记忆，不拟作为通用长期记忆系统；对于需要无遗漏记忆历史陈述的任务，硬剪枝策略不适用。
