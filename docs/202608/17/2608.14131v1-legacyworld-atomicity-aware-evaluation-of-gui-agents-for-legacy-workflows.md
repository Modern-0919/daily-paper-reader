## 摘要
遗留及类遗留企业系统通常难以现代化，因为关键工作流暴露的可编程接口有限，仍需手动GUI交互。本文报告了一项部署前评估研究，其动机源于legacy-use框架的开发，该框架是一个面向工业的框架，用于使用多模态LLM代理自动化此类工作流。在框架开发过程中，领域专家帮助识别了有状态工作流，在这些工作流中，成功演示并不足够：失败的代理运行仍可能在业务或医疗记录中留下持久的无效更改。因此，我们使用原子性来评估计算机使用代理：一次运行应要么正确完成预期工作流，要么在不产生意外持久副作用的情况下失败。我们构建了一个由领域专家参与的基准测试，包含28个Windows GUI工作流，每个工作流都指定了初始状态、目标状态和特定任务验证器。我们将专家精心设计的提示与从专家黄金路径执行的屏幕录制生成的提示进行比较。在六个托管的计算机使用代理中，我们的结果表明，有用完成、安全失败和非原子副作用是不同的操作特征。我们得出结论，工作流捕获、状态验证器和原子性感知验收测试应成为基于AI的遗留工作流自动化的一等需求。

## Abstract
Legacy and legacy-like enterprise systems often remain difficult to modernize because critical workflows expose limited programmable interfaces and still require manual GUI interaction. This paper reports a pre-deployment evaluation study motivated by the development of legacy-use, an industry-oriented framework for automating such workflows with multimodal LLM agents. During framework development, domain experts helped identify stateful workflows where successful demos are not sufficient: a failed agent run may still leave persistent invalid changes in business or healthcare records. We therefore evaluate computer-use agents using atomicity: a run should either complete the intended workflow correctly or fail without unintended persistent side effects. We construct a domain-expert-informed benchmark of 28 Windows GUI workflows, each specified with an initial state, goal state, and task-specific validator. We compare expert-crafted prompts with prompts generated from screen recordings of expert golden-path executions. Across six hosted computer-use agents, our results show that useful completion, safe failure, and non-atomic side effects are distinct operational profiles. We conclude that workflow capture, state validators, and atomicity-aware acceptance tests should be first-class requirements for AI-based legacy workflow automation.

# 论文总结：LegacyWorld：面向遗留工作流的GUI代理的原子性感知评估

## 1. 核心问题与整体含义

- **背景**：医疗、公共管理、会计等关键领域仍大量依赖遗留系统（legacy systems），这些系统可编程接口有限，必须通过远程桌面或GUI进行人工操作，难以从内部现代化。
- **动机**：多模态LLM计算机使用代理（computer-use agents）为自动化此类GUI工作流提供了新可能，但现有评估（如OSWorld、Windows Agent Arena）主要关注任务完成率，忽视了有状态工作流中一个关键风险：**失败的代理运行仍可能在业务或医疗记录中留下持久、无效的副作用**（如部分表单修改、错误数据库记录、多余文件）。
- **核心问题**：如何在遗留GUI工作流中评估代理的“原子性”——即运行要么**正确完成工作流**，要么**失败且不产生意外持久状态变更**。
- **整体含义**：成功演示不足以支撑部署决策。工作流捕获、状态验证器和原子性感知验收测试应成为AI遗留工作流自动化的一等需求。

## 2. 方法论

- **核心思想**：将“任务完成”与“状态可接受性”分离，用原子性（atomicity）作为评估代理在状态化工作流中安全性的核心指标。
- **任务契约（Task Contract）**：每个工作流被编码为可执行契约，包含：
  - 自然语言指令；
  - 初始状态假设；
  - 目标状态定义；
  - 运行时参数；
  - 期望返回模式（当需要提取ID或数值时）；
  - 允许/禁止的状态变更说明；
  - 任务特定验证逻辑。
- **验证机制**：独立于代理自报结果，分两层：
  - 通用快照检查：文件存在性、目录清单、哈希、窗口状态等；
  - 任务特定验证器：数据库增量（如DSWin的PATIENT.DBF行）、导出报告、返回ID/URL、计算值等。
- **结果四分类模型**：
  - 有效成功（valid success）：代理报告完成且达到目标状态；
  - 无效成功（invalid success）：代理报告完成但留下无效/非预期变更；
  - 有效失败（valid failure）：代理失败/超时但保留基准相关状态；
  - 无效失败（invalid failure）：代理未完成且产生持久副作用。
- **原子性定义**：有效成功 + 有效失败的比例，衡量运行后系统是否处于可接受状态；有效成功率衡量有用任务完成，二者必须分开报告。
- **两种Prompt条件**：
  - 专家精心编写的逐步程序化提示；
  - 从专家“黄金路径”屏幕录制生成的提示：由Gemini 3.1 Pro结合固定元提示和标准任务接口生成程序性指令，无人工编辑或清理；任务契约、验证器保持不变。
- **执行环境**：每次运行在全新Windows虚拟机中，预/后快照对比，临时overlay存储变更后丢弃，保证初始状态一致；统一900秒超时、max_tokens=4096、temperature=0.0。

## 3. 实验设计

- **Benchmark**：LegacyWorld，包含28个Windows GUI工作流，跨多个领域：
  - Admin/ERP：Adempiere（创建催款通知、打开系统、设置工资单）；
  - Dental/Healthcare：DSWin（添加患者、更新电话、添加计费代码等）、Open Clinic（收集患者数据、登记患者）、OpenMRS（登记患者）；
  - Reporting：Crystal Reports（创建PDF、加载报告、打开查看器）；
  - Utility/Developer工具：IrfanView、VS Code、Notepad、Chrome安装等；
  - Reference任务：计算器、Hello World文件保存等。
- 其中**18个任务**经领域专家或运营人员外部验证，确认工作流真实性和目标状态合理性。
- **对比方法**：6个托管计算机使用代理：

  - Anthropic Claude Haiku 4.5；

- **评估指标**：四类结果百分比、不安全副作用率（IS+IF）、原子性（VS+VF）。

## 6. 主要结论与发现

- **RQ1回答**：当前计算机使用代理在专家验证的遗留GUI工作流上仍不可靠，且表现模式分化明显：
  - gpt-5-4：专家提示下原子性100%，但有效成功仅3.6%——保守但无自动化价值；
  - opus-4-6 / sonnet-4-6 / haiku-4-5：有效成功率较高（71%-79%），但伴随少量非原子副作用；
  - kimi-k2.5：有效成功42.9%，但副作用率达35.7%——仅看任务完成会严重低估状态安全风险。
- **RQ2回答**：视频生成提示的主要影响是**降低有效成功而非增加不安全副作用**：
  - 如opus-4-6有效成功从78.6%降至50.0%，但原子性保持89.3%；haiku-4-5原子性在两个条件下均为85.7%。
  - 演示录制可保留原子性，但会降低实用自动化价值；不能替代显式验证。
- **总体结论**：有用完成、安全失败、非原子副作用是三类不同的操作特征，必须分别测量和报告。

## 7. 优点

- **概念创新**：将“原子性”引入GUI代理评估，针对有状态企业工作流的真实部署风险，弥补了现有基准只关注完成率的不足。
- **任务契约设计**：明确初始状态、目标状态、允许/禁止变更和独立验证器，使评估不依赖代理自报，更客观。
- **四分类结果模型**：比单一成功率更具信息量，能区分“安全失败”和“带有副作用的成功”。
- **实践导向的Prompt对比**：比较专家编写与录制生成，探索了可扩展的工作流指定方式，且明确指出录制不是正确性预言。
- **领域专家参与**：18个任务经外部验证，增强任务代表性。
- **可复现性**：公开复制包包含prompt、验证器、运行记录和复现脚本。
