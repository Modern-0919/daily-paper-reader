## 摘要
基于大语言模型（LLM）的多智能体系统（MAS）正在迅速涌现，但其异构的执行轨迹无法为跨方法的评估提供共同基础。仅基于结果的基准测试丢弃了协作信息，而LLM作为裁判的评估则需要额外的、依赖模型的推理，并可能随LLM和评分标准而变化。我们引入了一个可泛化的评估框架，将原生MAS轨迹映射到统一协作图的共享空间中，使得不同方法能够在相同的表示、参考集和指标面板下进行评估。候选图与查询特定的参考森林进行比较。每个森林是基准提供的已验证成功图的集合：它记录了代表性MAS方法完成任务的多种方式，而非规定唯一的最优过程。将该框架实例化为ForestBench，我们从七个公开数据集中筛选出844个需要协作的查询，为每个查询预计算十个成功的、以目标为条件的参考图，并评估六个代表性的MAS框架。受控的主干、参考构建和扰动研究测试了评估的稳定性和范围。一旦基准森林构建完成，ForestBench即可在毫秒内对轨迹进行评分，无需进一步的LLM推理，为比较多样化的MAS协作轨迹提供了可复用的结构基础。

## Abstract
Multi-agent systems (MAS) built on Large Language Models (LLMs) are proliferating rapidly, but their heterogeneous execution traces provide no common basis for evaluation across methods. Outcome-only benchmarks discard collaborations, whereas LLM-as-Judge evaluation requires additional, model-dependent inference and can vary with the LLM and rubric. We introduce a generalizable evaluation framework that maps native MAS traces into a shared space of unified collaboration graphs, enabling different methods to be evaluated under the same representation, reference set, and metric panel. Candidate graphs are compared with a query-specific reference forest. Each forest is a benchmark-provided collection of verified-success graphs: it records diverse ways in which representative MAS methods can complete the task, rather than prescribing a unique optimal process. Instantiating the framework as ForestBench, we filter $844$ collaboration-necessary queries from seven public datasets, precompute ten successful target-conditioned reference graphs per query, and evaluate six representative MAS frameworks. Controlled backbone, reference-construction, and perturbation studies test the stability and scope of evaluation. Once the benchmark forests are built, ForestBench scores a trace in milliseconds without further LLM inference, providing a reusable structural basis for comparing diverse MAS collaboration traces.

## 1. 论文的核心问题与整体含义（研究动机与背景）

**核心问题**：基于LLM的多智能体系统（MAS）飞速发展，但缺乏统一、可复现、过程感知的评估方法，导致不同MAS框架之间无法进行公平、结构化的横向比较。

**现有评估方法的三大缺陷**：

- **仅结果评估（Outcome-only Evaluation）**：如GSM8K、MMLU、HumanEval等基准只对最终答案打分，完全丢弃了MAS赖以存在的协作过程信息。这些基准无法区分"通过有效协作得到正确答案"与"碰巧答对"。
- **LLM-as-Judge评估**：虽然能阅读完整轨迹，但需要额外的模型依赖推理，成本高、可复现性差，且评分随LLM和评分标准（rubric）的变化而变化。
- **原生轨迹异构**：不同MAS框架的事件模式、角色词汇、通信协议各不相同，没有共同的过程级表示基础。

**核心洞察**：

- 图（Graph）是自然的统一表示——将MAS执行建模为协作图，节点是智能体动作，边是信息流依赖，从而消除框架特定的日志约定。
- 一个图只代表一种协作过程，同一任务可通过辩论（debate）、流水线（pipeline）、群体（swarm）等多种方式成功完成，因此需要**参考森林**（reference forest）而非单一参考树来保存成功的多样性。
- 评估应区分**表示**与**评估**：任务准确性继续衡量最终结果是否正确，确定性的图统计量描述结果是如何产生的。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 整体框架概览

ForestBench评估框架包含三个核心组件：

1. **图抽象层**：将任意MAS原始轨迹映射为统一的协作图
2. **参考森林**：每查询预计算的已验证成功协作图集合
3. **确定性指标面板**：基于图的多种结构指标，无需额外LLM推理

### 2.2 图抽象（Graph Abstraction）

将MAS执行查询q产生的时序轨迹τ投影为统一协作图：

**G(τ) = (V, E, φ)**

- **V**：每个原子动作一个节点（消息、工具调用、决策）
- **E**：两个动作之间的每次信息传递一条有向边
- **φ**：节点标签包括发出智能体、规范化角色r（来自共享角色词表）、动作文本内容

**关键性质**：

- 图是**有向无环图（DAG）**：每个原子动作有唯一时间戳，边只指向未来，不会成环。
- 投影是**有损的**：丢弃框架特定的运行时状态和精确的墙钟交错，但保留角色、动作和信息流依赖。
- **不变性**：独立动作的不同交错产生同一偏序，使不同框架的原生轨迹在结构上可比较。

### 2.3 参考森林（Reference Forest）

**动机**：同一任务可以通过辩论、专门化智能体流水线或同级群体等方式成功完成，这些执行在拓扑上差异显著。若仅选一个过程作为黄金标准，会武断地偏向某种MAS范式。

**定义**：

- 每个已验证成功的协作结构视为一棵**参考树**（reference tree），记录一种角色与信息流向正确结果生长的方式。
- 结构不同的参考树共同构成**参考森林**：F(q) = {(G_k, q_k)}_{k=1}^{K(q)}
- 其中G_k是来自代表性协作范式的已验证成功参考图，q_k是参考权重。

**参考森林作为基准资产**：

- 森林不是唯一黄金标准过程，也不枚举所有有效解法。
- 每个参考树都到达验证的目标结果，森林覆盖多种观察到的协作范式。
- 一旦发布，新轨迹可与同一固定成功结构集合比较，无需重新生成参考集。
- **评估范围声明**：评估回答的是一个限定问题——候选的协作结构与基准的已验证成功结构集合关系如何。结构相似性本身不决定"谁普遍更好"。

### 2.4 评估指标

#### 配对图相似度（Pairwise Graph Similarity）

给定候选图G和参考图G′：

**sim(G, G′) = α·s_node + β·s_edge + γ·s_topo**

默认权重(α, β, γ) = (0.4, 0.4, 0.2)。

- **s_node**：规范化角色多重集的Jaccard相似度（角色交集/并集）
- **s_edge**：角色类型化边指纹集合的Jaccard相似度（边交集/并集）
- **s_topology**：尺寸匹配度，公式为 ½ × [min(|V|,|V′|)/max(|V|,|V′|) + min(|E|,|E′|)/max(|E|,|E′|)]，同时惩罚冗长。

对规范化角色而非原始智能体标识符计算，使sim对智能体重命名和独立动作置换不变。

#### Forest Match（森林匹配，主要指标）

**FM(G, F(q)) = Σ w_k · sim(G, G_k) / Σ w_k ∈ [0, 1]**

其中w_k = q_k / max_k' q_k' ∈ (0,1] 为归一化参考权重。

- Forest Match衡量候选与森林中成功结构的整体对齐程度。
- 另报告**Best Similarity = max_k sim(G, G_k)**，衡量与最近参考树的接近程度。

#### 辅助指标（Auxiliary Metrics）

| 指标 | 定义 | 作用 |
|------|------|------|
| **Accuracy** | 最终答案正确率 | 衡量结果正确性 |
| **Node Validity** | V⁻中被至少一个下游动作消费的比例 | 暴露被忽略的工作 |
| **Mean Uptake** | 下游内容语义上使用上游内容的边比例（余弦相似度超过阈值） | 衡量信息实际被采用的程度 |
| **Content Redundancy** | 1 − (规范化唯一内容哈希数 / 总节点数) | 检测重复内容 |
| **Tokens** | 轨迹消耗的总骨干token预算 | 衡量成本 |
| **Efficiency** | 每个活跃智能体的拓扑并行度 | 衡量拓扑效率 |

所有指标都是G(τ)的确定性函数，**无需进一步LLM调用，每条轨迹毫秒级完成**。

**Trace-Suitability Pipeline（TSP）筛选**：为聚焦能展现有意义结构差异的查询，用强筛选LLM沿三个维度打分：

- **深度 d(q) ≥ 5**：所需的不同推理步骤数下限
- **宽度 w(q) ≥ 0.5**：八个能力维度的归一化Shannon熵
- **可分解性 δ(q) ≥ 0.5**：查询是否允许自然划分为独立子任务

三项阈值**同时满足**才保留，最终获得**844个协作必要查询**。

### 3.2 参考森林构建

| Swarm | 0.531 | 0.350 | 0.462 | 1,936 | 1.096 |
| AFlow | 0.538 | 0.347 | 0.507 | 2,432 | 0.844 |
| Debate | **0.569** | 0.316 | 0.284 | 3,227 | **2.258** |

**关键发现**：

1. **准确率单独无法有效区分方法**：六框架准确率跨度仅0.038，但结构指标差异显著。
2. **森林提供区分性结构信号**：Forest Match范围0.316–0.421，远大于准确率差异。
3. **结构性面板暴露最终答案隐藏的差异**：
   - Debate准确率最高但Forest Match最低、Best Similarity最低（0.284）、token消耗最高（3,227），体现"正确但结构离群"。
   - AFlow的Content Redundancy高达0.167（约其他框架的3倍），反映并行求解器的重复内容。
   - Swarm是唯一Node Validity低于1的框架（0.968），说明部分动作未被下游消费。

### 6.2 鲁棒性结论（RQ2：参考森林有效性与鲁棒性）

- **跨骨干稳定**：三种骨干构建的参考森林下六框架聚合排名完全一致，Kendall τ = Spearman ρ = 1.00。
- **留出生成器稳定**：7种留出设置中Kendall τ范围0.60–1.00，6/7设置保持Top-3。
- **条件化影响**：去掉黄金答案条件后绝对Forest Match值变化，但Top-3（MAS-GPT、AutoGen、MetaGPT）完全保持，Kendall τ = 0.867。

### 6.3 指标行为结论（RQ3）

- 结构扰动一致降低Forest Match，最大降幅0.058（节点删除p=0.5）。
- 重复内容注入几乎不影响Forest Match，但被Content Redundancy捕获——体现指标面板的分工设计。
- 非退化权重下排名Kendall τ ≥ 0.73，Top-3在5/5方案中保持；拓扑独权重下τ仅0.20（因去除了角色和边语义）。

### 6.4 失败诊断结论（RQ4）

- **失败分为结构性和内容性机制**：
  - 结构性失败：协作过程规格不足（缺少关键角色、固定模式不适合查询）。
  - 内容性失败：结构合理但求解器/验证器/聚合器引入或接受错误内容。
- 不同

不同框架的失败模式呈现出明显的机制分化。以MAS-GPT和AutoGen为代表的自动化框架，其失败更多源于**结构性原因**——例如关键角色缺失、角色间信息流断裂，或预定义流程无法适配查询的输入输出形态；而以Debate和Swarm为代表的交互式框架，其失败则更集中于**内容性原因**——例如聚合阶段采纳了错误的中间结论，或validator对错误答案的放行。诊断面板还观察到约30%的失败轨迹**同时**具有结构性与内容性异常，这类复合失败往往出现在查询可分解性较高但框架未显式建模子任务依赖的场景。3个诊断LLM对结构性失败的标注一致性较高，而对内容性失败的判断受rubric措辞影响明显；当移除诊断提示中的具体判定标准后，模型对内容性失败的识别率显著下降。这提示结构性诊断（如缺角色、缺边）相对客观可复现，而内容性诊断（如“信息是否被正确采用”）仍需结合下游指标（如Mean Uptake）共同解释，不宜单独作为审计依据。

## 7. 局限性与未来工作

### 7.1 主要局限性

- **参考森林覆盖范围有限**：尽管森林包含6种框架和CoT-SC锚，仍无法穷尽所有有效协作范式。结构新颖但合理的新执行可能因与所有参考树相似度低而获得保守评分，评估对“未收录的创造性协作”存在系统性低估风险。
- **图抽象的有损性**：投影时丢弃了消息语义细节（仅保留动作文本供内容指标使用）和精确的异步交错信息，因此无法捕捉消息长度质量、智能体间说服强度等弱信号；结构相似的图可能在语义质量上差异显著。
- **TSP筛选引入选择偏差**：844个查询均要求深度、宽度、可分解性同时达标，导致评估集中于中等复杂度任务；简单查询和极端复杂查询的结果不能由ForestBench直接外推。
- **结构相似度不蕴含规范判断**：Forest Match衡量与已验证结构的相似程度，但不直接说明某协作过程“更好”；论文明确限定其评估范围，但用户可能误读为质量排名。
- **骨干模型依赖风险**：默认参考森林由DeepSeek-V4-Flash生成，虽然跨骨干鲁棒性测试表明排名稳定，但若未来骨干产生系统性行为偏移，参考集仍需定期重建或扩充。

### 7.2 未来工作方向

- **参考森林的动态更新**：将新验证成功的结构在线融入森林，而非依赖静态预计算集合。
- **语义增强的图抽象**：在节点/边上引入轻量级语义嵌入，使相似度度量能区分“相同结构但内容相反”的协作。
- **跨任务泛化**：探索是否可以从一个查询的参考森林中迁移结构模式，用于少样本提示其他查询的评估。
- **面向递归/循环结构的扩展**：当前DAG假设不适用于带反馈回路的协作；未来可引入时序图变体以支持迭代式MAS。

## 8. 总体评价与结论

ForestBench的核心贡献不在于提出一个新的MAS模型，而在于建立了一个**统一的、可复现的、过程感知的评估协议**。它通过将异构执行轨迹映射为协作图，并以参考森林保存成功的结构多样性，巧妙地将“评估协作”从依赖LLM的主观判断转化为确定性的图统计计算。其指标面板在毫秒级内同时报告结果正确性与结构对齐程度、信息使用效率和内容冗余度，为研究者提供了一个低成本的三维诊断工具。实验证明，Forest Match等结构指标能揭示准确率无法区分的框架差异，且对参考骨干、生成器留出和权重选择均表现稳定。尽管存在覆盖范围和有损抽象的局限，ForestBench依然为多智能体系统提供了当前稀缺的横向可比基础，也为未来更精细的过程评估研究奠定了坚实框架。
