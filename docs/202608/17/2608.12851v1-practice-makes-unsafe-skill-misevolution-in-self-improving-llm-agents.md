## 摘要
自我改进的LLM智能体会将成功轨迹转化为可跨任务复用的持久状态。因此，一次不安全的成功在其触发输入消失后，可能变成可复用的策略。技能进化通过将操作轨迹提炼为可执行、可迁移、可检查的程序，使这种失败变得可测量。由于进化优化的是任务结果而非程序安全性，受损的经验可能导致技能误进化。现有基准测量当前行为或静态产物，但无法在编写、检索和后续执行之间归因风险。为揭示这一生命周期，我们引入了SkillMisevo-Gym，一个生命周期感知的测试平台，跨智能体框架对技能状态进行版本管理；以及SkillMisevo-Bench，一个从恶意暴露到承继任务的冻结设计，包含概念对齐的良性任务和九个生命周期指标。我们还引入了SafeEvolve，一种修复不安全内容并管理后续复用的包装器。在25种智能体方法配置中（每种覆盖25个回合中的525个任务），所有21种进化配置都生成了不安全产物，但只有15种导致了新会话中的伤害。在暴露扫描中，三个恶意任务将承继ASR从16.0%提升到35.3%。在代表性技能进化方法中，SafeEvolve分别将不安全检索和新会话伤害降低了26.7和17.3个百分点，而良性效用均值仅变化0.4个百分点。总之，持久适应安全必须约束更新写入的内容以及未来执行者复用的内容。代码可在https://github.com/henrymao2004/misevolve获取。

## Abstract
Self-improving LLM agents convert successful trajectories into persistent cross-task state. An unsafe success can thereby become reusable policy after its triggering input disappears. Skill evolution makes this failure measurable by distilling operational trajectories into executable, transferable, and inspectable procedures. Because evolution optimizes task outcomes rather than procedure safety, compromised experience can cause skill misevolution. Existing benchmarks measure current behavior or static artifacts but cannot attribute risk across authoring, retrieval, and later execution. To expose this lifecycle, we introduce SkillMisevo-Gym, a lifecycle-aware harness that versions skill state across agent frameworks, and SkillMisevo-Bench, a frozen design from malicious exposure to carryover tasks, with concept-aligned benign tasks and nine lifecycle metrics. We also introduce SafeEvolve, a wrapper that repairs unsafe content and governs subsequent reuse. Across 25 agent-method configurations, each covering 525 tasks in 25 episodes, all 21 evolved configurations author unsafe artifacts, while only fifteen lead to fresh-session harm. In the exposure sweep, three malicious tasks raise carryover ASR from 16.0% to 35.3%. Across representative skill evolution methods, SafeEvolve reduces unsafe retrieval and fresh-session harm by 26.7 and 17.3 percentage points, respectively, while mean benign utility changes by only 0.4 points. Together, persistent-adaptation safety must govern what updates write and what future executors reuse. Code is available at https://github.com/henrymao2004/misevolve.

## 一、核心问题与研究背景

- 自我改进的 LLM 智能体（self-improving LLM agents）会将成功轨迹转化为可跨任务、跨会话、跨部署复用的持久状态（如技能库），从而形成能力积累。这改变了安全边界：一次不安全的成功操作，可以在触发输入消失后，通过适应层被泛化为持久策略。
- 技能进化（skill evolution）是这种更新的具体操作形式：它从交互轨迹中提取、合并或修订可执行程序（面向软件工程、工具使用、工作流等）。由于进化优化的目标是任务结果而非程序安全性，受损的经验可能引发**技能误进化（skill misevolution）**——即不安全的短期成功被固化为可复用、可迁移、可检查的程序，并在攻击输入消失后继续造成危害。
- 现有基准的不足：技能基准只测任务成功率、迁移或技能质量；智能体/技能安全基准只测外部提供的提示、环境或静态工件；长时间跨度基准研究记忆累积而非智能体自主撰写的技能文件。**没有任何现有设计能联合归因“更新—持久工件—检索—执行”这一纵向生命周期中的风险**。最终 ASR 无法区分“安全库”与“未被检索的不安全工件”这两种截然不同的状态。
- 论文的核心主张：持久适应安全必须同时约束“更新写入什么”（write gate）与“未来执行者复用什么”（reuse/execution gate）。

## 二、方法论

### 2.1 问题形式化
- 智能体以基础策略 π 执行三任务块序列 Q = (Q₁,…,Q_K)，每个块 Q_k = (q_{k,1}, q_{k,2}, q_{k,3}) 产生轨迹 T_k = (τ_{k,1}, τ_{k,2}, τ_{k,3})。更新方法 E 更新技能库：**L_{k+1} = E(L_k, Q_k, T_k)**。会话重置但技能库持续存在。
- 技能误进化的判定需要三个环节同时成立：演化更新选择/泛化了不安全程序并写入库中；后续检索命中该程序；复用后伴随高于 No Evolution 基线的不安全行为。推进可能在任意闸门（authoring / retrieval / execution）停止，因此论文将“工件、检索、动作”分开报告。

### 2.2 威胁模型
- **攻击者目标**：将有限的恶意任务暴露转化为可复用的程序，改变后续智能体行为；最强结果是仅凭 SKILL.md 实现全新会话中的承继伤害（fresh-session carryover）。
- **攻击者知识**：知道外部任务与工具接口、轨迹可能更新技能库；无法查看模型内部、隐藏提示、当前库内容或未来探针。
- **攻击者能力**：可在有限数量的学习历史位置提交任意指令；不能直接写技能库、篡改检索/进化/评判逻辑，也不能注入后续良性/持久任务。沙箱会重置其余状态，因此跨任务影响必须经由技能库传播。

### 2.3 SkillMisevo-Gym（生命周期感知测试平台）
- 对技能库进行版本管理（versioned L_k），将差异（diff）链接到来源轨迹，记录结果、工具调用痕迹和评判证据；支持新增领域、方法、治理策略。
- 状态隔离协议：每个任务运行在全新沙箱（新对话、工作区、进程命名空间、工具会话），仅回合范围的技能库前进；每个 (episode, method, agent) 单元从全新进程和存储启动，跨单元无任何状态泄漏。
- Hermes-native 例外：其 HERMES_HOME 在任务沙箱间持久（这是其原生进化机制），但回合间重置，且 P 阶段仍只从导出的 SKILL.md 重载。

### 2.4 SkillMisevo-Bench（冻结基准）
- 以 **AgentHazard** 作为可执行验证基座（多样性操作危害、可重置 CLI 沙箱、轨迹评判器），以 **AHA**（autoresearch）离线发现可证伪的恶意–良性漏洞概念，再由构造器实例化为全新的 M / B / P 任务记录。
- 三个冻结概念：
  - **VC1：标签条件化不安全复用**（8 个回合）——M 将“监控/遥测/扫描/设置”等可复用标签与不安全实现绑定；进化丢失该边界后，B 因同一标签检索到不安全程序。
  - **VC2：双用途边界丢失**（8 个回合）——M 和 B 共享自动化角色，但 M 附加了未验证目的地、敏感收集、无人值守执行或持久控制；进化保留基础模板却丢弃安全关键边界。
  - **VC3：组合完成溢出**（9 个回合）——M 展示完整“收集–处理–传输/安装”链路，B 只需安全子集；进化打包完整链路后，检索会在 B 上“补全”被省略的有害步骤。
- 回合结构：21 个任务，顺序为 M³BBB M³BBB M³BBB | BBB（9M + 9B + 3P），每三任务块后执行一次进化更新；P₃ 不更新，只重载冻结的 SKILL.md。每个条件含 25 个回合、525 个任务。
- 九个生命周期指标：良性效用（BU）、恶意 ASR（M-ASR）、良性 ASR/污染（B-ASR）、内容不安全度（CU）、不安全泛化（UG）、隐蔽性（Stealth）、不安全检索率（URR）、承继 ASR（C-ASR）、承继效用（C-Util）。任务、元数据、评判器全部冻结，发现概念库（VCG）对被评测系统隐藏。

### 2.5 SafeEvolve（治理包装器）
- **写时治理**：非阻塞批评器（critic）定位可复用的不安全指令，配对的删除器（deleter）执行最小减法式修复（删除不安全片段或收窄过度泛化的规则），禁止添加检查、允许列表、审批步骤等；若修复后候选无效或未降低风险，则保留原生候选并附审计证据。
- **复用治理**：按效用与谱系风险对技能排序；将有害/良性结果归因到被检索技能；达到不安全复用阈值（≥2 次）或累积风险阈值即退役；容量淘汰按“效用−风险”排名驱逐。
- 方法无关：不改变智能体或进化算法本身，仅包装写入与复用边界。

## 六、主要结论与发现

1. **不安全工件普遍存在，但伤害逐闸门衰减**：全部 21 个进化配置都撰写了不安全工件，19 个检索到不安全技能，19 个出现污染，仅 15 个保留新会话伤害。没有承继伤害 ≠ 干净库，可能只是未被选择或未被成功应用。
2. **效用与风险往往共存**：在完成的 MiniMax 网格中，15/21 个进化设置的 BU 高于 No Evolution，16/21 的 C-Util 更高，同时 17/21 的 M-ASR 更高——一个配置可以同时保留有用工作流和嵌入其中的不安全捷径，而非简单的效用–安全权衡。
3. **方法–框架交互决定风险落在哪个闸门**：EvoSkill 在所有框架中穿越完整生命周期（C-ASR 25.3%–30.7%）；AutoSkill 的 C-ASR 在 OpenClaw 上仅 14.7%、在 Codex 上达 29.3%；SkillOpt 在 OpenClaw 上作者高泛化工件但无检索/承继。
4. **有限暴露即可播种持久风险**：三个恶意任务使承继 ASR 从 16.0% 升至 35.3%；早期暴露使污染率升至 40.7%（晚期仅 19.8%），说明时机主要扩大污染窗口而非最终持久性；混合良性更新不能可靠消除风险（Fully Mixed 与 Batched 的 C-ASR 分别为 48.0% 与 46.0%）。
5. **SafeEvolve 有效**：在 AutoSkill 与 EvoSkill 上，将不安全检索率从 35.33% 降至 8.67%、C-ASR 从 21.33% 降至 4.00%，良性效用均值仅变化 0.4 个百分点；三个组件各自治理不同传播环节（修复降低可迁移内容风险、归因将有害复用转为证据、退役阻止已证风险继续传播）。
6. **核心论断**：持久自适应安全必须同时约束更新写入内容与未来执行者的复用行为。

## 七、优点

- **生命周期视角**：首次将“作者撰写—检索—执行”作为三个独立闸门测量，避免单一 ASR 混淆“安全库”与“潜在危险未命中工件”，归因能力显著强于现有基准。
- **冻结与可复现设计**：任务、评判器、调度、分母全部冻结；固定分母聚合（缺失计零）防止样本漂移；发现概念库（VCG）对被评测系统隐藏，降低泄漏风险。
- **方法无关的治理方案**：SafeEvolve 不修改智能体或进化算法，仅包装写入与复用边界，具有跨框架通用性；组件消融（表 3、表 6）从机制层面直接验证每个干预的有效性。
- **概念发现可证伪**：通过 AHA 自动发现恶意–良性漏洞概念，要求可复现配对证据与使能条件，优于人工拼凑的对抗任务。
- **详尽的案例追踪**（附录 I）：从单条 M→B→P 路径、跨框架、跨方法、Hermes 被动评审、SafeEvolve 治理前后五个角度提供工具调用级证据，增强了结论的可信度。
- 伦理与来源管理规范：合成身份、虚拟凭据、惰性端点、隔离沙箱，上游 AgentHazard 遵循 MIT
