## 摘要
自主LLM智能体越来越多地部署在复杂的现实工作流程中，但它们仍然容易受到运行时行为漂移的影响，这是一种对原始任务的静默偏离，可能对外部系统造成不可逆的副作用。现有方法在提示层面处理漂移，但缺乏步骤级检测、风险评估和恢复决策的结构化机制。由于主任务执行智能体通常是一个大型且昂贵的模型，无法在每次部署时重新训练，因此本工作针对即插即用的恢复模块。它引入了一个基于图的框架，其中单个小型语言模型通过强化学习训练，在恢复图的每个节点上专门化，独立于主智能体。每个节点都有精确的角色：漂移分类、操作检测、风险评估或最终决策，模型学习生成适合该角色的结构化XML格式推理。训练结合了基于规则的结构奖励和LLM作为评判者的语义质量信号，因此模型既根据其回答方式（模式和长度）又根据其内容进行评分。在公开的AppWorld基准上的实验表明，该方法通常利用有关疑似漂移起点的信息，使用小型语言模型发出正确的恢复决策。此外，训练后的小型语言模型可靠地遵守规定的输出模式，并根据其分配的节点角色在每个字段中生成语义上适当的内容。

## Abstract
Autonomous LLM agents are increasingly deployed in complex real-world workflows, yet they remain vulnerable to runtime behavioral drift, a silent deviation from the original task that can lead to irreversible side effects on external systems. Existing approaches address drift at the prompt level but lack structured mechanisms for step-level detection, risk assessment, and recovery decision. Because the main task-executing agent is often a large and expensive model that cannot be re-trained on every deployment, this work targets a plug-and-play recovery module instead. It introduces a graph-based framework in which a single small language model is trained via reinforcement learning to specialize at each node of a recovery graph, external to the main agent. Each node has a precise role\,: drift classification, operation detection, risk evaluation, or final decision and the model learns to produce structured XML-formatted reasoning adapted to that role. Training combines rule-based structural rewards with an LLM-as-judge semantic-quality signal, so that the model is graded both on how it answers (schema and length) and on what it says. Experiments on the public AppWorld benchmark show that the method generally exploits information about the suspected drift onset to issue correct recovery decisions using a small language model. In addition, the trained small language model reliably respects the prescribed output schema and produces semantically appropriate content in each field according to its assigned node role.

## 1. 核心问题与研究动机

- **问题定义**：自主LLM智能体在真实工作流中执行API调用、发送邮件、转账等操作时，存在**“行为漂移”**（behavioral drift）风险——即智能体在运行过程中静默偏离原始任务目标，且一旦发生，可能对外部环境产生不可逆的副作用。
- **与普通幻觉的区别**：漂移不是一次崩溃或一次幻觉回答，而是幻觉性回答触发的一系列行动最终导致智能体丧失对初始目标的追踪；当智能体拥有写权限（转账、删除消息、修改配置）时，简单重置模型记忆无法修复环境状态——“回滚消息历史并不能回滚世界”。
- **现有方法的空白**：已有防御工作（提示注入隔离、指令层级训练、agent-tool防火墙）几乎都聚焦于**预防**漂移发生，缺少**事后恢复**的结构化机制。论文明确指出需要一套程序：(i) 沿轨迹回溯定位漂移起点；(ii) 列出漂移期间实际执行的写操作；(iii) 判断每个写操作是否能用逆API调用撤销；(iv) 决定回滚消息历史还是上报人类。
- **核心约束**：主任务执行智能体通常是大型昂贵模型，不可能在每次部署时重新训练，因此本文目标是开发**即插即用（plug-and-play）的外部恢复模块**，不触碰主智能体。

## 2. 方法论

### 2.1 核心思想

将漂移恢复建模为**五节点状态机的路由遍历**（recovery graph）：

| 节点 | 角色 | 输出JSON键 |
|------|------|-----------|
| n1: Classify Drift | 判定单步是否与任务对齐 | `{step, is_aligned, why}` |
| n2: Detect Operations | 枚举漂移步骤中实际执行的写操作与离题读操作 | `{write_operations, read_operations}` |
| n3: Search Documentation | 输出涉及的API/应用去重列表 | `{apps_name}` |
| n4: Evaluate Risk | 将写操作划分为可逆/不可逆 | `{write_reversible, write_not_reversible}` |
| n5: Aggregate & Decide | 产生最终决策（回滚/上报） | `{action, arguments}` |

**关键设计**：所有五个节点共享**同一个小语言模型策略** `πθ`，仅通过角色特定的提示词（node-tagged prompt）区分角色，用**GRPO**（Group Relative Policy Optimization）一次性训练全部五个角色，无需为每个节点单独训练策略。

### 2.2 结构化XML推理与奖励设计

- **统一输出信封**：每个节点强制输出恰好一个 `<reasoning>` 块 + 一个 `<answer>` JSON块，避免自由文本CoT导致下游节点需重新解析的脆弱性。
- **复合奖励**：`R(o, ν, q) = Σ_{k=1}^{9} w_k r_k(o, ν, q)`，共9个分量：
  - **格式奖励（节点无关）**：XML标签计数（`r_xml-count`）、严格标签顺序（`r_strict`）、宽松顺序（`r_soft`）；
  - **长度风格奖励**：推理块简洁度（`r_reas-len`）、总输出紧凑度（`r_tot-len`）；
  - **JSON有效性与节点模式（节点相关）**：JSON语法有效（`r_json-valid`）、键集合精确匹配（`r_json-schema`，Jaccard部分得分）、节点特定值检查（`r_json-sanity`）；
  - **语义质量信号（`r_judge`）**：冻结的14B LLM-as-judge按角色特定rubric打分（1.0=具体且正确，0.5=泛泛但无错，0.0=空泛/幻觉/矛盾），且明确指示忽略格式、仅评内容。
- **组归一化优势**：`Âi = (ri - r̄) / (std(r) + ε)`，无需价值网络，早期即使所有样本都差也能提供相对信号；KL散度约束使策略不偏离基座模型过远（基座是XML模式可识别性的基础）。

### 2.3 后向遍历与终止条件（核心算法）

算法流程（Algorithm 1）要点：

1. 从外部漂移检测器给出的疑似起点 `k0` 出发，**逐层向前（更早的步骤）回溯**；
2. 每步调用 n1 判定对齐性；若判定为漂移（`is_aligned=N`），触发 n2→n3→n4 记录写操作与可逆性；
3. **对齐连击终止条件**：出现连续K个步骤均为 `Y`（对齐）时停止回溯，进入 n5 聚合决策——论文指出单一对齐步骤不足以证明漂移区结束，短连击是稳健且廉价的代理指标；
4. n5 产生 `rollback_before_drift`（带目标步骤）或 `escalate_human`（带结构化事件报告）。

### 2.4 漂移类型学与范围界定

- **Type I - 瞬时读漂移**：无环境写入，回滚消息历史即可（论文主要聚焦）；
- **Type II - 持久读漂移**：无写入但触发源存留于环境（如邮箱中的恶意文档），需要额外生成漂移感知警告注入重执行上下文；
- **Type III - 写漂移**：环境已被突变，仅检测可逆/不可逆并决定是否上报人类，**自动化逆操作留待未来工作**；
- 论文假设漂移一旦开始则单调持续（排除交错模式）。

## 6. 主要结论与发现

1. **训练有效性与普适性**：两个小模型在全部100个保留提示上复合奖励均严格提升（无一条交叉）；Qwen 1.5B从基座几乎无法生成模式（R=0.56）跃升至R=4.80（提升8.6×），大幅缩小与Granite 2B的差距（差距从3.12压缩至0.35）。
2. **单策略多角色成立**：一个共享策略通过角色条件提示即可在五个节点全部实现专门化，无需每节点独立策略。
3. **端到端恢复效果显著**：Type I下训练后Granite恢复27.5%聚合任务完成率，达到无漂移上界（35.3%）的**78%**，接近GPT-4o恢复背骨（32.5%）的水平；D1上与GPT-4o完全持平（57.1%）。Type II + 强主背骨下达35.0%（GPT-4o恢复为45.0%，上界为42.5%）。
4. **模式遵循可靠**：json_schema从0.67→0.98（Granite）和0.08→0.97（Qwen）的跃升表明强化学习使小模型严格服从结构化输出契约。
5. **语义质量同步提升**：r_judge在Granite上从0.71→0.90，证明GRPO不仅强化格式还强化内容接地性；分类与操作检测节点的语义增益最大（0.66→0.95、0.53→0.90）。
6. **难点明确**：n4评估风险节点的judge得分提升温和（0.72→0.78），指向API逆操作知识是当前最薄弱环节。

- **诚实评估多agent背骨**：用GPT-4o/mini作为capability oracle揭示小模型与前沿模型的真实差距及其所在节点（n5警告语义丰富度）。

## 8. 不足与局限

- **实验规模与统计显著性**：端到端仅40任务/配置，无置信区间与显著性检验，部分差异（如D1超上界）可能是噪声；多难度层任务数不均衡削弱难度分解的可解释性。
- **漂移覆盖范围有限**：仅测试单一注入模式的Type I/II；Type III无端到端验证；论文明确假设漂移单调，未处理交错漂移（Remark 1中列出的D→A→D模式）。
- **Judge偏差与奖励黑客风险**：14B judge可能无法验证AppWorld API逆操作的事实正确性（尤其在n4），可能高估“貌似合理”的推理而放行幻觉性逆端点；小模型可能学习被judge偏好的风格花招而非事实接地。论文承认“审计judge分布是训练循环的一部分”但未提供审计实验。
- **架构性缺口**：当前不执行逆API调用，可逆性划分仅作决策信号而非纠错计划；Type III下自动检测到不可逆写即一律上报，缺乏部分可逆场景的混合恢复策略。
- **依赖外部信号**：恢复质量依赖外部漂移检测器提供的疑似起点 `k0` 的准确性，若起点本身错误则后向遍历可能遗漏真实漂移区。
- **一个轻微回归**：Granite的tot_len分量从0.14降至0.08（训练后推理块变长），虽被judge增益淹没，但反映了两个奖励分量之间的张力。
- **可复现性**：代码与数据仅“应向通讯作者索取”，未提供公开仓库，降低可复现性。
