## 摘要
现实世界中的数据科学涉及长期工作流，涵盖数据整理、探索、建模、可视化和验证，并且需要在真实操作环境中协调使用笔记本、IDE、终端、浏览器和数据库等工具。然而，现有基准缺乏真实计算机交互，也未评估智能体是否能在实际计算环境中执行完整的端到端数据科学工作流，未能捕捉数据科学实践中多阶段、多工具的特性。我们提出了DSAgentBench，这是首个在真实计算机环境中评估智能体能否自动化完整数据科学工作流的基准。DSAgentBench包含275个多样化任务，覆盖整个数据科学生命周期，反映了实践中所需的复杂性和工具协调。每个任务要求基于中间输出进行决策并协调使用工具，同时包含一个确定性评估器，用于验证分析正确性、视觉输出和模型性能，而非仅验证代码执行。我们使用15个闭源和开源模型进行了大量实验，结果表明即使是最强的智能体Claude-4.6-Sonnet，其任务成功率也仅为56.70%，而所有开源智能体的成功率均低于1%，频繁在工具编排、操作系统基础和多步推理上失败。这些结果揭示了当前智能体系统与真实数据科学工作流之间的巨大能力差距，使DSAgentBench成为开发有根基、可验证、自主数据科学智能体的基础。我们在https://github.com/vis-nlp/DSAgentBench上发布了DSAgentBench。

## Abstract
Real-world data science involves long-horizon workflows that span data wrangling, exploration, modeling, visualization, and validation, and require coordinated use of tools such as notebooks, IDEs, terminals, browsers, and databases within real operating environments. Yet existing benchmarks lack real-computer interaction and do not evaluate whether agents can execute complete end-to-end data-science workflows in realistic computing environments, failing to capture the multi-stage, multi-tool nature of data-science practice. We introduce DSAgentBench, the first benchmark to evaluate whether agents can automate full data-science workflows inside real computer environments. DSAgentBench contains 275 diverse tasks covering the entire data-science life-cycle, reflecting the complexity and tool coordination required in practice. Each task requires grounding decisions in intermediate outputs and coordinated tool use, and includes a deterministic evaluator that verifies analytical correctness, visual outputs, and model performance rather than code-only execution. Our extensive experiments with 15 closed- and open-source models show that even the strongest agent, Claude-4.6-Sonnet, achieves only 56.70% task success, while all open-source agents remain below 1%, frequently failing at tool orchestration, OS grounding, and multi-step reasoning. These results reveal a substantial capability gap between current agentic systems and real data-science workflows, positioning DSAgentBench as a foundation for developing grounded, verifiable, autonomous data-science agents. We release DSAgentBench at https://github.com/vis-nlp/DSAgentBench.

## 2. 方法论

DSAgentBench 的核心思想是**将智能体置于真实操作系统环境中，要求其完成覆盖数据科学生命周期的端到端任务，并以确定性评估器验证所有最终产出**。

**关键技术细节**：

- **任务构建**：从多个权威来源（如 Kaggle、GitHub、UCI ML Repository）筛选和构建了 275 个真实任务，覆盖四个核心阶段：
  1. **数据准备**（data preparation）：数据加载、清洗、类型转换、缺失值处理等。
  2. **探索性数据分析（EDA）**：生成数据摘要、统计指标和可视化图表。
  3. **建模**（modeling）：训练机器学习模型并优化性能指标。
  4. **可视化与验证**：输出符合要求的图表，并对分析结果进行验证。
- **任务分级**：按复杂度将任务划分为**基础**、**中级**和**高级**三个难度层级。高级任务通常涉及多个数据集、多步骤链条，或要求跨工具协作（如结合网页数据和本地数据分析预测）。
- **真实环境交互**：所有任务在**容器化的 Ubuntu 环境**中运行，智能体通过终端命令、Python 脚本、文件读写等方式与真实操作系统交互，而非仅调用 API 或操作合成界面。
- **确定性评估器**：每个任务配备可重复执行的评估脚本，从三个维度验证产出：
  - **分析正确性**：如在数据准备阶段，通过设定容差（tolerance）来对齐智能体输出与参考答案，计算错误率、数值有效性、数据类型正确性等指标。
  - **可视化输出**：检查图表的存在性、文件格式等视觉产出属性。
  - **模型性能**：验证模型是否达到指定指标阈值（如 R²、准确率）。
  - 评估器拒绝简单地"代码能运行即通过"，而是**验证结果本身是否真实正确**。
- **运行流程**：每个任务以文字描述（含路径、目标和限制条件）作为输入，智能体需在真实环境中自行探索、编写代码、执行并迭代直至完成（或达到步数上限），最后输出结果，由手工设计的 evaluate_predictions.py 脚本评分。

## 3. 实验设计

**基准结构**：

- 275 个真实环境任务，覆盖数据科学全生命周期，每类任务有评估器和参考实现。
- 任务级别划分及数量：基础任务 101 个、中级 109 个、高级 65 个。
- 所有任务在 4 个不同环境配置（环境 A/B/C/D）中运行，以测试泛化性。

**对比方法**：

- **15 个模型**，分为两大类：
  - **闭源 API 模型**：Claude-4.6-Sonnet（最强）、Claude-4.5-Sonnet、Claude-4.1-Sonnet、Claude-3.7-Sonnet、Claude-3.6-Sonnet、GPT-5.2、GPT-5.1、GPT-5、GPT-4.1、Gemini-2.5-Pro。
  - **开源模型**：Qwen3-72B-Instruct、DeepSeek-V3-0324、DeepSeek-V3、Llama-3.3-70B-Instruct、Qwen3-32B-Instruct。
- **评估指标**：以**任务级成功率**为主要指标——智能体必须"完全正确地"完成任务的所有要求，且产出结果通过确定性评估器验证，才算成功。同时报告各阶段成功率和不同难度层级的表现。

**实验维度**：

- 按任务难度（基础/中级/高级）分别报告成功率。
- 按数据科学阶段（准备/EDA/建模/可视化）报告崩溃点（阶段级成功率和主要失败原因）。
- 对部分模型（如 Claude-4.6-Sonnet）进行**消融实验**（如禁用浏览器工具、去除 OS 交互能力的变体），以分析各能力模块的贡献。

## 6. 主要结论与发现

1. **总体上，智能体距离真实数据科学自动化还很远**。最强模型 Claude-4.6-Sonnet 的任务成功率仅为 **56.70%**，这意味着即使最先进的模型，也无法完成近一半的真实数据科学任务。
2. **开源模型严重落后**。所有开源模型成功率均低于 **1%**（如 Qwen3-72B-Instruct 约 0.72%、DeepSeek-V3 0%），与闭源前沿模型存在数量级差距，说明开源智能体尚不具备执行真实端到端数据科学工作流的能力。
3. **失败模式高度集中**：
   - **工具编排**：智能体难以在多个工具（终端、文件系统、Python 库、浏览器）之间有效切换和串联操作。
   - **操作系统基础能力（OS grounding）**：在真实 Linux 环境中导航文件系统、理解环境上下文、使用命令行等基础操作是高频失败点。
   - **多步推理**：数据科学任务链条长，智能体在长程推理过程中容易丢失目标或出现累积性错误。
4. **不同难度的阶梯式递减**：成功率随任务复杂度升高而显著下降，表明当前模型在处理简单单一步骤时已有一定能力，但在复杂、多阶段任务中仍力不从心。
5. **评估方式的有效性**：仅检查"代码可运行"是不够的，用确定性评估器验证分析结果正确性，能够更真实地暴露智能体系统能力的短板。

## 7. 优点

- **首个真实环境端到端数据科学基准**：DSAgentBench 突破了既有基准停留在合成环境、仅测单一步骤的窠臼，要求智能体在真实操作系统内完成完整工作流，评估范式更具实际意义。
- **评估体系严谨、可复现**：采用手工设计的确定性评估器，逐项量化各阶段的分析正确性、可视化输出和模型性能，定义了严格的"成功"标准（全局正确才算成功），避免了"部分完成即通过"的宽松评估。
- **任务覆盖面广且贴近实践**：任务从真实数据源构建，覆盖数据科学生命周期的所有主要环节，并且支持多个环境配置，充分反映了实际项目中的多样性。
- **细粒度失败分析**：不仅报告最终成功率，还提供阶段级崩溃分析和失败类别（多步推理、工具编排、OS 交互）的统计，为后续改进提供了清晰的行动方向。
- **发布开源**：将基准完整开源，便于社区复现和扩展，有助于形成统一的评测标准。

## 8. 不足与局限

- **开源模型评估缺乏梯度**：所有开源模型成功率均低于 1%，大量任务对开源模型来说难度过大，导致基准无法有效区分不同开源模型的相对水平，对开源模型的发展指导意义有限。
- **计算资源信息缺失**：未披露 GPU 型号、数量和推理时长，影响实验可复现性和成本评估。
- **消融实验有限**：仅对 Claude-4.6-Sonnet 进行了消融，没有覆盖不同规模的模型，难以判断结论是否具有普遍性。
- **任务规模与置信度**：275 个任务虽规模可观，但相比现实世界中无限变化的数据科学项目，仍属有限样本，领域覆盖和结论泛化性有一定局限。
- **评估维度的局限性**：检查要点主要集中于输出文件的正确性（数值、图表、模型指标），对中间分析过程的合理性、代码质量、效率等方面未作评判。
- **实验公平性**：闭源模型使用 API 访问，而开源模型在本地推理，二者在推理基础设施、上下文长度处理和工具调用能力上可能不一致；且模型默认的 agent 框架、prompt 模板等细节对结果的公平性亦有潜在影响。
- **偏置风险**：任务构建时的数据源选择和评估指标定义可能隐式偏向某些模型/库的操作方式，存在一定的任务构建偏置。
