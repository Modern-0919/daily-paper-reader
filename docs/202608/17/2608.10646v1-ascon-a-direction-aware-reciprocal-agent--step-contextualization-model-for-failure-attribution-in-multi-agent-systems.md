## 摘要
基于LLM的多智能体系统（MAS）中的故障归因旨在通过识别有责任的智能体、错误步骤和故障模式等目标来回答谁导致故障、何时发生以及为何发生。现有方法主要集中于为特定归因目标开发专用模型，而对它们之间证据依赖关系的关注有限。尽管这些归因目标不同，但它们依赖于来自MAS轨迹的共同诊断证据，包括任务约束、智能体角色、行为历史和智能体间交互。这种共性促使我们开发一个统一表示模型，将轨迹证据聚合到单个智能体和步骤表示中，进而可适应不同的归因目标。为此，我们提出了ASCon，一种面向多个故障归因目标的方向感知交互智能体-步骤上下文化模型。ASCon引入方向感知图注意力建模执行上下文，掩蔽步骤到智能体注意力构建行为感知的智能体表示，以及智能体条件化步骤上下文化将智能体上下文融合回步骤表示。所得的上下文化表示通过轻量级目标特定头实现不同的归因目标。实验表明，ASCon在微观准确率上将错误智能体检测提升5.83%以上，错误步骤检测提升10.63%以上，故障模式检测的宏F1提升14.73%以上。同时，在域外场景中，它还能显著增强基于LLM的方法的归因能力。

## Abstract
Failure attribution in LLM-based multi-agent systems (MAS) aims to answer who caused failures, when they occurred, and why by identifying responsible targets including faulty agents, erroneous steps, and failure modes. Existing methods have primarily focused on developing dedicated models for specific attribution targets, with limited attention to the evidential dependencies among them. Despite these attribution targets are different, they rely on common diagnostic evidence from MAS trajectories, including task constraints, agent roles, behavioral histories and inter-agent interactions. This commonality motivates us to develop a unified representation model that aggregates the trajectory evidence into individual agent and step representations, which can subsequently be adapted to different attribution targets. Accordingly, we propose ASCon, a direction-aware reciprocal \textbf{A}gent--\textbf{S}tep \textbf{Con}textualization model for multiple failure attribution targets. ASCon introduces direction-aware graph attention to model execution context, masked step-to-agent attention to construct behavior-aware agent representations, and agent-conditioned step contextualization to incorporate agent context back into step representations. The resulting contextualized representations enable different attribution targets through lightweight target-specific heads. Experiments show that ASCon can improve faulty-agent detection by 5.83\%+ in micro-accuracy, faulty-step detection by 10.63\%+ in micro-accuracy, and failure-mode detection by 14.73\%+ in Macro-F1. Meanwhile, it can also substantially enhance the LLM-based methods' attribution capabilities in out-of-domain scenarios.

- **核心问题**：MAS 故障归因需要回答三个问题——**谁（who）** 导致了故障、**何时（when）** 发生、**为何（why）** 发生，对应根因智能体、错误步骤和失败模式三类归因目标。

- **整体含义**：论文提出 **ASCon** 模型，通过将轨迹证据聚合到步骤与智能体两个层面的上下文化表示中，统一支持智能体级、步骤级和失败模式级归因，并以轻量级头部适配不同监督信号，从而降低多目标归因的建模复杂度并提升整体性能。

## 2. 方法论

### 2.1 核心思想

- 将 MAS 轨迹建模为**有向步骤图**和**有向智能体图**，用图注意力机制捕获执行上下文；
- 通过**掩码步骤到智能体注意力**将步骤级行为证据“向上”聚合为行为感知的智能体表示；
- 再将智能体表示“向下”注入到各自步骤表示中，形成**步骤—智能体交互式上下文化**；
- 最终针对不同归因目标（根因智能体、错误步骤、失败模式）设计轻量级预测头。

### 2.2 关键技术细节

- **方向感知图注意力（DGAT）**：
  - 同时建模每个节点的**入边邻居**（前驱上下文，用于判断是否异常）与**出边邻居**（后继影响，用于区分根源故障与下游后果）；
  - 对入边和出边分别计算注意力分数并归一化，再与自变换信息融合更新节点表示。
- **上下文步骤表示**：
  - 步骤文本经预训练编码器得到语义嵌入，在步骤图上叠加多层 DGAT，得到包含任务约束和前后执行上下文的步骤表示；
  - 将执行该步骤的智能体表示投影到步骤空间，并与步骤表示做**逐元素相乘**，再经 MLP 和 LayerNorm 得到**智能体条件步骤表示**。
- **行为感知智能体表示**：
  - 引入用户节点 `a0`（对应查询步骤 `s0`）以注入任务约束；
  - 构造**智能体-步骤分配掩码矩阵**，只允许智能体关注其自身执行过的步骤；
  - 通过掩码缩放点积注意力对步骤表示做加权聚合，得到行为感知的智能体表示；
  - 再叠加全局轨迹表示，形成初始智能体表示，并在智能体交互图上应用 DGAT，获得最终智能体表示。
- **目标特定归因头**：
  - **根故障归因**：对每个智能体和步骤分别做二分类（`sigmoid`），训练时用二元交叉熵，推理时取概率最高者；
  - **失败模式归因**：融合智能体表示与其关联步骤表示，同时预测智能体是否为故障智能体以及其失败模式类别分布，损失为 BCE + CE。

## 6. 主要结论与发现

- **ASCon 在根故障归因上显著优于最强基线 StepFinder**：agent 宏准确率提升 3.38%（81.58% vs 78.20%），step 宏准确率提升 7.57%（63.90% vs 56.33%）；在代码和智能体任务上的步骤级准确率提升超过 11 个百分点。
- **在失败模式归因上全面领先**：相较 Aegis-SFT，Pair 级 μF1 提升 13.95%、MF1 提升 11.09%；Error 级 μF1 提升 12.19%、MF1 提升 14.73%，证明其对少见失败模式的判别力更强。
- **域外泛化能力突出**：在 Who&When 上，ASCon 预测作为辅助证据可大幅提升 LLM 方法的步骤定位能力（如 DeepSeek-V4-Pro 步骤微准确率提升 21.20%），说明其学习到的故障证据具有较强的可迁移性。
- **消融结果验证了各组件的互补性**：方向感知图注意力、掩码步骤到智能体注意力和智能体条件步骤表示均对最终性能有正贡献；其中 BiGRU 替代 DGAT 带来的下降最大，表明显式建模方向关系比顺序编码更有效。
- **普通图结构已足够**：用 LLM 推断的依赖图替换 vanilla 有向边并不能一致带来增益，反而可能因噪声边损害细粒度步骤定位，说明 ASCon 可通过有监督表示学习自动捕获必要依赖。

## 7. 优点

- **统一框架设计新颖且实用**：将三种归因目标纳入同一模型，共享轨迹证据的表示学习，避免了为每个目标单独设计模型带来的成本和目标间信息割裂。
- **对上下文的方向性建模有理论依据**：区分前驱（判断异常）和后继（评估后果）符合故障归因中“根源 vs. 结果”的语义差异。
- **注意力机制设计精细**：掩码步骤到智能体注意力既能限定在智能体自身行为上，又能自适应该步骤对故障判断的重要性。
- **轻量高效**：参数量 <10M，可在消费级 GPU 上训练，却能达到甚至超过 LLM 级基线的部分指标。
- **域外增强效果显著**：ASCon 不依赖 LLM 推理能力，反而可以作为外部证据注入给 LLM，弥补 LLM 在未见分布上的弱点，实际应用价值较高。
- **实验设计较完整**：除主实验外还进行了消融、图结构泛化、实时检测和 OOD 测试，使结论更可信。

## 8. 不足与局限

- **评估基准有限**：虽然 TracerTraj、Aegis-Bench 和 Who&When 覆盖了多种任务，但仍属于特定生成/收集的轨迹数据，未在真实工业系统或更多样化的 MAS 协议上验证，泛化到实际部署环境仍需谨慎。
- **对编码器依赖较大**：步骤和角色表示由 Qwen3-Embedding-0.6B 生成，该编码器的语言理解能力可能成为瓶颈，尤其对罕见表述或多语言场景可能表现不佳。
- **实验公平性存在一定风险**：LLM 基线与 ASCon 参数量差距悬殊，虽能说明 ASCon 的轻量优势，但也意味着两者不宜简单比较；同时未报告 LLM 推断图实验和实时检测实验的完整细节（如 LLM 推理成本、检测阈值等）。
- **多故障场景处理仍有挑战**：在失败模式归因中，Agent 级 MF1 相对提升较小（3.10%），说明模型对少样本故障智能体或高度不平衡的类别仍有改进空间。
- **消融与分析深度不足**：消融结果只给出整体指标变化，缺乏对各组件在具体任务类型（如代码 vs. 数学）上的差异分析；对错误模式误判的更细粒度分析也缺失。
- **未讨论在线推理成本**：虽然实时检测实验中 ASCon 表现最好，但论文没有给出在截断轨迹上的推理延迟，无法判断其是否满足真正实时场景要求。
