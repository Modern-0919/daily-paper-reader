## 摘要
使用工具的LLM代理通常在工具调用可靠成功的环境中进行训练和评估，但部署后的工具可能发生瞬时、持续或静默的故障。因此，稳健的恢复不仅仅需要重复重试：代理可能需要重试同一路径，切换至备选方案，或认识到已无可行路径。我们提出了BENCH2ROBUST框架，该框架将无故障的工具使用基准转换为具有场景可控可解性的受控随机环境，其中任务回合明确要求在可用路径耗尽后重试、切换或停止。我们使用BENCH2ROBUST研究两种互补的干预措施：通过贝叶斯工具记忆（BTM）提供的结构化运行时恢复上下文，以及课程控制的强化学习。在来自4个模型家族的7个模型以及两个多轮基准家族中，工具故障产生了近乎普遍的鲁棒性差距。在保留的Retail任务上，BTM在无需重新训练的情况下将鲁棒性提升了最多16.8个百分点，而强化学习学习到的互补恢复行为在推理阶段不使用BTM的情况下仍然有益。将两者结合，在错误注入下达到了40.8%-45.5%的鲁棒性，同时保持了无故障时的性能。这些结果表明，稳健的工具使用受益于将特定环境的恢复知识与学习到的恢复行为相结合。

## Abstract
Tool-using LLM agents are commonly trained and evaluated in environments where tool calls succeed reliably, yet deployed tools can fail transiently, persistently, or silently. Robust recovery therefore requires more than repeated retries: an agent may need to retry the same path, switch to an alternative, or recognize that no viable path remains. We present BENCH2ROBUST, a framework that converts failure-free tool-use benchmarks into controlled stochastic environments with scenario-controlled solvability, where episodes explicitly require retrying, switching, or stopping after available paths are exhausted. We use BENCH2ROBUST to study two complementary interventions: structured runtime recovery context through Bayesian Tool Memory (BTM), and curriculum-controlled reinforcement learning. Across 7 models from 4 families and two multi-turn benchmark families, tool failures produce a near-universal robustness gap. On held-out Retail tasks, BTM improves robustness by up to 16.8 percentage points without retraining, while RL learns complementary recovery behavior that remains beneficial without inference-time BTM. Combining the two reaches 40.8-45.5% under injection while preserving failure-free performance. These results suggest that robust tool use benefits from combining environment-specific recovery knowledge with learned recovery behavior.

## 1. 论文的核心问题与整体含义

- **研究动机**：工具使用型 LLM 代理通常在工具调用“可靠成功”的环境中训练与评估，但实际部署中工具会经历瞬时失败、持续失败或静默失效。面对失败，代理不能只会盲目重试，还需要能判断何时重试同一路径、何时切换备选工具、何时放弃（上报人工）。已有随机失效注入方法无法明确某个 episode 到底需要哪种恢复行为，导致难以区分“好的恢复策略”和“运气好”。
- **核心问题**：如何构建可训练、可评估的工具失败恢复环境，使代理学会策略感知的恢复行为（retry / switch / abstain）？
- **整体含义**：论文提出 **BENCH2ROBUST** 框架，将无失败基准转化为带“场景控制可解性”的随机失败环境；结合 **贝叶斯工具记忆（BTM）** 与 **课程化强化学习** 两种互补干预，显著提升工具使用鲁棒性，且不损害无故障性能。

## 2. 论文提出的方法论

- **BENCH2ROBUST 框架**：
  - 在代理与工具执行之间注入一个适配层，将任意 `tool_call(name, args) → response` 基准转化为受控随机环境。
  - 形式化为 POMDP：`Z_inj(ot | st, at) = Σ P(ν) 1[ot = Cν(o*_t)]`，即观测被按概率扰动；每个工具调用有 60% 概率保持干净，40% 概率被注入 9 种失败之一。
- **场景控制可解性（Scenario-Controlled Solvability）**：
  - **S1（retry_works）**：没有路径被永久阻断，重试即可恢复。
  - **S2（switch_needed）**：主路径被 episode 级永久阻断，必须使用备用等效工具。
  - **S3（impossible）**：所有相关路径被阻断，继续使用工具无法完成任务，应上报/升级。
  - 阻塞是确定性的、贯穿整个 episode，且独立于随机注入预算（B ≤ 5，同一工具连续随机失败 ≤ 2）。
- **替代工具路径**：为 Retail 新增 5 个工具（如 `search_product_by_name` 作为 `get_product_details` 的备用路径），BFCL 中也构造自然等效类。
- **贝叶斯工具记忆（BTM）**：
  - 包含三部分：Beta 后验可恢复性统计、领域相关 fallback 映射、启发式约束（如失败后至少重试一次、切换后验证数据、不可逆操作前确认字段、仅在路径耗尽后上报）。
  - 作者明确说明，BTM 的“贝叶斯”成分仅用于累积经验统计；消融表明推理阶段的增益主要来自 fallback 映射与约束，而非后验数值本身。
- **奖励设计**：
  - 完成任务：`1.0 · eff(τ) · rep(τ)`，其中 `eff` 惩罚超长 episode，`rep` 惩罚重复调用。
  - 未完成任务：给予部分奖励 `0.3 · matched_actions / total_required · rep(τ)`。
  - 奖励中**没有**对正确放弃的正向激励，因此 S3 仅作为训练场景，不作为完整“学习到放弃”的证据。
- **课程化 RL 训练**：
  - 5 个阶段：先学 R ETRY（100% S1），再逐步引入 S WITCH（20%→40% S2），加入 A BSTAIN（10% S3），最后完整混合（30/45/25）。
  - 使用 DAPO 算法，带 KL 约束（系数 0.02）避免策略崩溃；使用非对称裁剪、动态组过滤、组相对优势（G=16 rollouts，8 clean + 8 injected）。

## 6. 论文的主要结论与发现

- **鲁棒性缺口普遍存在**：几乎所有模型/任务组合在注入下性能大幅下降（最高 −46.7pp）；模型规模扩大不能消除脆弱性。
- **BTM 提供最大的零训练增益**：在保持集上，BTM 使 4B 基础模型从 20.1% 提升至 36.9%（w/o alt，+16.8pp），从 31.9% 提升至 43.6%（w/ alt，+11.7pp）。
- **RL 在无推理 BTM 下仍保留恢复能力**：RL 策略去掉 BTM 后仍比基础模型高 +6.3/+6.9pp；RL 在真实 S2（需要切换）场景成功率更高，过早升级率更低。
- **BTM 与 RL 互补**：RL+BTM 组合达到最高 40.8%/45.5%（w/o alt / w/ alt），且干净场景性能与基础模型一致（63.9% vs 64.3%）。
- **BTM 增益主要来自结构而非信念**：静态 fallback 映射 + 约束贡献了大部分提升；真实后验值与随机打乱后验值差异不超过种子噪声。
- **不同失败机制各有侧重**：BTM 对显式瞬时错误（超时、限流、服务器错误等）增益最大；RL 对持久显式错误（auth/schema drift）和静默错误（事实错误、过期数据）贡献更大；BTM 在事实错误上甚至有小幅负效应。

## 7. 优点

- **问题定义清晰**：用 S1/S2/S3 将“重试、切换、放弃”转成环境层面的显式可解性标签，突破了以往随机注入无法区分恢复策略质量的瓶颈。
- **框架适配性强**：BENCH2ROBUST 可无缝接入多个公开基准，并支持标注替代工具路径，便于作为训练环境复用。
- **干预设计互补**：结构化运行时上下文（BTM）与课程化 RL 分别提供环境知识与可复用行为，组合效果最佳。
- **实验体系完整**：包含跨模型、跨基准、消融、敏感性、效率、错误类型分解等大量分析；作者对指标和局限讨论诚实，不夸大“学习到放弃”。
- **可复现性好**：给出完整训练配置、注入参数、BTM 提示模板，并承诺开源框架、领域注册表、信念计算脚本和评估工具。

## 8. 不足与局限

- **抽象与停止信号不完整**：奖励设计未包含对正确放弃的正向激励，因此论文只将 S3 作为训练条件，未声称完全学到了放弃行为。
- **干预对比为整体配方**：主结果比较的是 BTM+RL 组合配方，无法完全分离课程、KL 稳定、奖励塑形等各自贡献。
- **实验统计有限**：Qwen3-8B 复现只有点估计，无多种子置信区间；跨基准迁移增益较小且部分领域（Telecom）接近能力下限。
- **模拟故障而非真实轨迹**：9 种噪声是模拟的“严重压力测试”配置，不代表真实 API 故障率；缺乏真实事故数据验证。
- **效率代价**：注入条件下恢复行为带来显著 token 开销（干净 70K → 注入 108–123K），可能不适合延迟敏感场景。
- **潜在偏差**：RL 可能部分内化了 BTM 中的措辞/启发式，而非完全独立的策略泛化；错误类型分析测量的是任务通过率而非“是否真正识别损坏值”，不能完全排除静默错误被错误消费的可能。
- **转移性受限**：跨域迁移增益有限，BTM 在事实错误上可能因增加重试反而降低效率，说明其适用性依赖错误类型和域结构。
