## 摘要
智能体技能是扩展LLM智能体可复用指导的事实标准机制。技能可以塑造智能体的任务执行，包括规划、工具使用、问题求解和验证。先前工作报告了智能体技能的结果不一：一些技能提高了任务成功率，而另一些则没有效果，增加了令牌使用和执行时间，甚至降低了成功率。本文通过对任务失败和成本回归归因于特定加载技能，对技能诱发的智能体失败进行了全面分析。我们引入了一个差分分析框架，通过将目标技能引导的运行与解决相同任务或更廉价解决该任务的无技能或语义匹配技能参考运行进行比较，将失败或回归归因于技能。我们在SkillsBench和SWE-Skills-Bench上实例化该框架，产生了307个技能诱发的失败，包括125个功能失败和182个效率回归。我们还构建了SkillTriage，一个基于分类法的归因工具，它标准化成对案例，提取差分证据，并生成分诊报告。我们的主要发现包括：(1) 技能诱发的功能失败很少由明显不相关的技能引起；相反，看似相关的技能往往使智能体错误地实现或忽略任务要求的实现元素。(2) 技能诱发的效率回归不能仅用提示长度来解释。(3) 过度程序中的最大来源是过度验证和繁重的实现流水线，分别贡献了67和30个案例。这表明技能常常将验证检查清单和构建配方转化为强制性工作。基于我们的发现，我们提出了更安全和更具成本意识的技能复用的研究主题和工具改进。

## Abstract
Agent skills are the de facto mechanism for extending LLM agents with reusable guidance. A skill can shape the agent's task execution, including planning, tool use, problem-solving, and validation. Prior work reported mixed results of agent skills: some skills improve task success rates, while others have no effect, increase token use and execution time, and even reduce success rates. This paper presents a comprehensive analysis of skill-induced agent failures by attributing task failures and cost regressions to specific loaded skills. We introduce a differential analysis framework that attributes a failure or regression to a skill by comparing a target skill-guided run against a no-skill or semantically matched skill reference run that solves the same task, or solves it more cheaply. We instantiate this framework on SkillsBench and SWE-Skills-Bench, yielding 307 skill-induced failures, including 125 functional failures and 182 efficiency regressions. We also build SkillTriage, a taxonomy-guided attribution tool that normalizes paired cases, extracts differential evidence, and produces triage reports. Our major findings include: (1) Skill induced functional failures are rarely caused by obviously irrelevant skills; instead, seemingly relevant skills often make the agent incorrectly implement or omit task-required implementation elements. (2) Skill-induced efficiency regressions are not explained by prompt length alone. (3) The largest sources within Excessive Procedure are excessive verification and heavy implementation pipelines, contributing 67 and 30 cases, respectively. This shows that skills often turn validation checklists and construction recipes into mandatory work. Based on our findings, we propose research topics and tooling improvements for safer and more cost-aware skill reuse.

## 论文核心问题与整体含义（研究动机和背景）

- **背景**：LLM智能体系统的核心能力之一是通过“技能”（Agent Skills）注入可复用的程序性知识，以指导智能体在规划、工具调用、代码编辑、验证和停止决策等方面的行为。
- **核心问题**：技能并非总是有益的。已有工作（SkillsBench、SWE-Skills-Bench）观察到技能在某些任务上可提升成功率，但在其他任务上不仅无效，还会增加令牌消耗和执行时间，甚至导致成功率的下降。本文聚焦于回答一个关键问题：**技能如何以及在何种条件下会诱发功能失败或效率回归？**
- **深层含义**：技能是一种被设计为可复用的配置项，一旦加载即嵌入智能体的上下文，影响其全部决策过程。如果技能在内容上存在误导性、不匹配或过度约束，那么复用得越多，负面影响就越被放大——这种“有害性”对社会化技能市场、平台级技能分发和未来智能体系统的安全性构成了实质风险。
- **整体意义**：本文是首个针对技能诱发失败的系统性实证研究，提出了一套可归因、可复用的分析方法论，致力于推动更安全、成本感知的技能封装、筛选和复用机制。

## 方法论

### 核心思想
- 借鉴差分测试（differential testing）思想，构建 **目标运行（target run）** 与 **参考运行（reference run）** 的成对对比实验。参考运行作为“伪基准（pseudo-oracle）”，证明同一任务在相同条件下可以成功或更廉价地解决。
- 仅改变“技能设置”（无技能、目标技能、语义匹配的其他技能），固定其他所有变量（任务、验证器、智能体框架、模型、仓库/容器状态、数据文件、输入），从而将失败或成本差异归因于具体技能。

### 关键技术细节
- **两类失败定义**：
  - **功能失败**：目标运行（带技能）验证失败，而参考运行（无技能/其他技能）验证通过。
  - **效率回归**：目标与参考均通过验证，但目标运行的令牌数或执行时间大幅升高（定义阈值为“两指标比值均大于1.0，且至少一个比值>2.0”）。
- **两阶段归因判定**：
  1. 对比目标/参考轨迹差异，排除基座模型局限、验证器覆盖不足、随机波动等干扰因素。
  2. 通过人工根因分析，将每一种失败归入构建的分类学标签。
- **分类学体系**：
  - 功能失败分为 4 大类和 7 个子类：**适用性不匹配（APM）**、**环境不匹配（EM）**（含BDR、ESM）、**任务实现错误（TIF）**（含OWG、IRF、RRO）、**工件错置（AM）**。
  - 效率回归分为 3 大类和 6 个子类：**上下文膨胀（CO）**（含SBCB、SMB）、**过度程序（EP）**（含EE、HIP、EV）、**依赖解析（DO）**。
- **语义匹配技能收集**：从 smithery.ai 和 skillsmp.com 检索公开技能，用 all-MiniLM-L6-v2 做语义相似度筛选（cosine ≥ 0.7），每个任务最多保留 5 个候选技能，从而扩展对比空间。
- **自动归因工具 SkillTriage**：基于 LLM 的分诊工具，输入标准化后的成对运行数据，提取差分信号（DS1–DS5，覆盖环境、路径、实现、遗漏等维度），结合分类学定义输出根因、证据引用和修复建议。采用 3 次推理并取 2/3 多数投票。

## 实验设计
- **基准数据集**：
  - **SkillsBench**（84 个评估任务，11 个领域，含无技能、精选技能、自生成技能设置）。
  - **SWE-Skills-Bench**（490 个基于仓库的软件工程任务，含无技能和精选技能设置）。
- **扩展后对比空间**：将比较对从原始 826 个扩展到 20,664 个（约 25 倍），包括 with/no-skill 对比和 cross-skill 对比。
- **实验执行配置**：使用 OpenCode 1.15.1 作为智能体运行时，Claude Opus 4.6 作为基座模型。
- **对比对象**：每个任务至多有 6 种技能变体（原始精选技能 + 语义匹配公共技能），互相作为目标与参考进行成对比较。
- **数据标注流程**：从 665 个标记候选（315 功能失败候选 + 350 效率回归候选）中，经过去除歧义、验证器过窄、重复等操作，最终确定 307 个高置信度案例（125 个功能失败、182 个效率回归），并人工共识标注根因。
- **自动归因评估**：在 125 个功能失败和 182 个效率回归上，使用 GPT-5.5 运行 SkillTriage，3 次推理多数投票，对比人工标注标签。

## 主要结论与发现
1. **功能失败的主因不是“技能不相关”，而是“技能看似相关却产生误导”**：
   - 任务实现错误（TIF）占 68.8%（86/125），其中 Incorrect Required-Element Fill（36.8%）和 Required-Element Omission（28.8%）占主导。
   - 工件错置（AM）占 19.2%（24/125），环境不匹配（EM）占 10.4%，适用性不匹配（APM）仅占 1.6%。
2. **效率回归的本质不是“长提示”，而是“过度程序”**：
   - 过度程序（EP）占 62.6%（114/182），其中过度验证（EV）最多（67 例），其次是重型实现流程（HIP，30 例）。
   - 上下文膨胀（CO）占 25.3%，且其中 43/46 例来自强制性技能正文（SBCB）而非附加材料，说明技能加载机制是令牌开销的主要推手。
3. **对技能设计者的警示**：技能常把可选的验证清单、实现步骤转化为强制工作流，导致“过度执行”。
4. **SkillTriage 的实际表现**：
   - 功能失败：类别准确率 93.6%，子类准确率 88.8%；
   - 效率回归：类别准确率 79.7%，子类准确率 72.5%；
   - 错误多集中在邻近分类学边界（如 IRF/RRO、EM/AM 或 EE/HIP/EV）上。

## 优点

- **系统性与深度兼具**：构建了覆盖完整链条的分析流程——从对比空间扩展、语义技能匹配、自动标注，到根因分类和自动归因工具验证。

- **工具落地价值高**：SkillTriage 不只是离线研究工具，更面向智能体平台和技能市场的持续审核场景，具备自动化和可扩展性潜力。

## 不足与局限
- **外部有效性风险**：仅使用两个基准（SkillsBench 和 SWE-Skills-Bench）、一个智能体运行时（OpenCode）和一个基座模型（Claude Opus 4.6），实验结论可能无法完全推广到其他模型、框架、任务分布或技能生态。
- **内部有效性风险**：根因分析依赖人工判断，尽管排除了歧义与验证器过窄案例并采用共识机制，但对“验证器是否窄于任务”“成本变化是否为普通方差”等仍有主观性空间。
- **效率回归阈值敏感性**：以 T=2.0 为阈值，虽然保守但可能忽略了 1.5–2.0 之间的大量轻度回归，无法反映中等成本代价的真实分布。
- **未披露算力与成本**：缺少显式计算资源、API 调用量、推理成本等数据，难以评估方法本身的部署门槛。
- **SkillTriage 仍依赖已确认的失败案例**：该工具属于“事后归因”，无法在不预先执行成对实验的情况下主动发现新失败，尚不能承担技能的实时预防性筛选。
- **失败原因权重可能存在基准偏差**：SWE-Skills-Bench 在数据量上远大于 SkillsBench（490 vs 84），最终数据集中功能性失败可能偏向软件工程场景，跨领域的平衡性有待增强。
