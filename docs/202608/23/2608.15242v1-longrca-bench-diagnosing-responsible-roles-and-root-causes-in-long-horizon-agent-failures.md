## 摘要
当长时程智能体执行失败时，结果级评估仅显示失败结果，却无法揭示决定性错误是在轨迹的哪一步进入的。开发者随后必须检查完整执行过程，以识别责任角色并定位最早的决定性根本原因步骤。现有的故障归因基准主要聚焦于较短的轨迹，对跨数百个记录步骤的诊断研究不足。我们引入了LongRCA Bench，包含跨五个领域的1,140条无注入错误的失败轨迹。它提供了独立评分的人工标注，涵盖责任角色和最早决定性根本原因步骤。中位轨迹包含145步，最强基线仅达到13.2%的精确根因步骤准确率。我们进一步提出了无训练的根因轨迹归因（RCTA）方法，从片段摘要中检索候选错误步骤，并将其追溯到可用的早期交接指令。使用相同的骨干模型、基准实例和评分协议，RCTA达到了51.1%的责任角色准确率和24.1%的精确根因步骤准确率。这些结果凸显了在长轨迹故障诊断中，应将责任角色归因和精确根因步骤定位作为独立目标进行评估的必要性。

## Abstract
When a long-horizon agent execution fails, outcome-level evaluation reveals the unsuccessful result but not where the decisive error entered the trajectory. Developers must then inspect the full execution to identify the responsible role and localize the earliest decisive root-cause step. Existing failure-attribution benchmarks largely focus on shorter traces, leaving diagnosis across hundreds of recorded steps underexplored. We introduce LongRCA Bench, comprising 1,140 failed trajectories across five domains without injected errors. It provides independently scored human labels for the responsible role and earliest decisive root-cause step. The median trajectory contains 145 steps, and the strongest baseline reaches only 13.2% exact root-step accuracy. We further present Root-Cause Trajectory Attribution (RCTA), a training-free method that retrieves candidate error steps from segment summaries and traces them to available earlier handoff instructions. Using the same backbone, benchmark instances, and scoring protocol, RCTA reaches 51.1% responsible-role accuracy and 24.1% exact root-step accuracy. These results highlight the need to evaluate responsible-role attribution and exact root-step localization as separate targets in long-trajectory failure diagnosis.

### 1. 论文的核心问题与整体含义

- **背景**：大语言模型（LLM）驱动的智能体通过长序列的规划、工具调用、协调、执行与验证来完成复杂任务。当执行失败时，现有结果级（outcome-level）评估只能指出任务未成功，却无法定位决定性错误是在轨迹的哪一步进入的，也无法指出哪个工作流角色应为此负责。
- **核心问题**：在长时程（long-horizon）智能体失败诊断中，如何将“责任角色归因”（responsible-role attribution）与“根因步骤定位”（root-cause step localization）作为两个独立任务进行可靠评估？现有故障归因基准大多聚焦于较短轨迹，对跨数百个记录步骤的诊断研究不足。
- **关键洞察**：根因错误可能发生在失败结果之前很远的位置（中位根因到终点距离为48步，最多605步），诊断方法必须区分决定性根因与大量后续传播步骤；同时责任角色不一定是根因步骤的发出者，两个目标应当独立预测与评分。
- **论文含义**：通过构建新基准 LongRCA Bench 和提出无训练诊断方法 RCTA，论文证明了在长轨迹故障诊断中，责任角色归因与精确根因定位需要作为独立目标评估，且现有方法在这两个任务上均远未饱和。

### 2. 论文提出的方法论

#### 2.1 LongRCA Bench 基准构建

- **数据来源**：收集自五个既有基准的成功/失败执行记录——SWE-bench Pro、Terminal Bench 2、TravelPlanner、VitaBench、WebArena Verified，共1,140条无注入错误的失败轨迹。
- **任务定义**：
  - 每条实例包含任务指令、失败轨迹 H = (h₀, …, h_{T-1}) 和源评估器给出的结果。
  - 每条记录有步骤索引和角色名。
  - **责任角色** ρ*：轨迹中应负责的工作流角色（必须出现在轨迹录制角色集合中）。
  - **根因步骤** r*：最早引入与最终失败相关的决定性错误的记录步骤；已修复的错误不算；后续仅执行/传播/暴露既有错误的步骤不算。
  - 两个标签独立预测、独立评分，角色不由所选根因步骤的发出者推导。
- **统一解析**：将不同框架的日志归一化为统一记录序列（索引、角色、内容，及可选的工具/验证器元数据）。
- **人工标注**：22名计算机科学硕士/博士对全部轨迹进行人工评审，每条标注责任角色、最早决定性根因步骤及基于轨迹的理由文本；通过一致性检查与争议复核，最终为1,140条轨迹各生成一套参考标签。

#### 2.2 Root-Cause Trajectory Attribution (RCTA) 方法

- **核心思想**：将“宽泛的轨迹搜索”与“基于原始日志的精确归因”分离——先用分段摘要快速召回少量候选错误步骤，再把候选回溯到更早的手令指令（handoff），最后基于原始文本做最终判定。
- **三阶段流程**：
  1. **轨迹分段（Segmenting）**：以规则化边界（字符/步数限制、完成信号、手令转换、验证器信号）将轨迹划分为连续片段，保留原始步骤ID，每个片段含最多5步重叠上下文；分段不使用语言模型。
  2. **候选召回（Candidate Recall）**：
     - 每个片段调用一次 LLM，生成摘要并建议候选错误步骤（带ID）。
     - 第二次调用将相邻片段摘要聚合为按子目标组织的轨迹大纲（outline）。
     - 池化并对候选步骤优先级排序，保留前 80 个候选，并检索这些步骤的原始文本。
  3. **手令追溯与最终归因（Tracing & Attribution）**：
     - 对执行者/验证者角色产生的候选，检索最近一条发给该角色的手令指令；其他候选则取最近手令作为计划上下文。
     - 最终 LLM 调用对比候选原始文本与手令上下文：若手令已含决定性错误且后续步骤照做未修复，则选手令步骤为根因；若后续偏离手令或引入新错误，则选候选步骤。
     - 已成功修复的错误排除；最终决策仅依赖轨迹内证据。
     - 输出中责任角色与根因步骤为独立字段；程序化验证器检查角色是否出现在轨迹中、根因/证据ID是否有效、引用的手令文本是否真实存在；无效输出重试一次，仍无效则移除不支持字段并标记为弃权/审查。

### 3. 实验设计

- **基准（Benchmark）**：LongRCA Bench，共1,140条失败轨迹，源自5个领域（软件修复、终端任务、旅行规划、服务型工具使用、网页交互），中位轨迹长度145步，最大728步；根因到终点距离中位数48步，最大605步。
- **对比方法（均使用 DeepSeek-V4-Flash 作为推理骨干，同一套1,140条轨迹和同一评分协议）**：
  - **All-at-once**：一次调用将完整轨迹交给模型，输出角色与步骤。
  - **Step-by-step**：顺序扫描轨迹，询问决定性错误是否已发生。
  - **Binary search**：递归二分定位根因区域。
  - **ECHO**：层次化上下文表示 + 共识投票（Banerjee et al., 2025）。
  - **FALAT**：依赖引导搜索决策/工具输出/消息（Rafi et al., 2026）。
  - **RCTA（本文方法）**：上述分段召回+手令追溯方法。
- **评估指标**：
  - **责任角色准确率（Role Acc.）**：显式角色输出与参考角色匹配，绝不从预测根步推断角色。
  - **根因精确准确率（Root Exact）**：预测步骤必须与参考 0-based 步骤完全一致。
  - **根因±5准确率（Root ±5）**：绝对误差 ≤5 步。
  - **根因 MAE（Root MAE）**：按来源加权的有效输出绝对误差均值（非法输出不计入MAE但计为准确率错误）。
- **分层分析**：按轨迹长度分桶（≤100、101–200、201–400、>400）和按根因到终点距离分桶（≤10、11–50、51–100、>100），报告各方法的根因精确准确率（仅描述性分析，不作为因果结论）。

### 6. 论文的主要结论

- **长轨迹根因定位极难**：最强基线 ECHO 的精确根因准确率仅13.2%，即使是最强方法 RCTA 也只有24.1%，远低于责任角色准确率（51.1%）。说明“定位到具体一步”与“识别责任角色”是两种难度不同的能力。
- **RCTA 显著优于所有基线**：
  - 角色准确率：RCTA 51.1% vs ECHO 27.5%（+23.6%）。
  - 根因精确：24.1% vs 13.2%（+10.9%）。
  - 根因±5：37.4% vs 24.7%（+12.7%）。
  - 根因MAE：38.6 vs 50.4（↓11.8步）。
- **依赖引导搜索（FALAT）在长轨迹上效果不佳**：精确根因仅2.8%，低于简单全量提示（7.6%），说明该设置的搜索方式可能不适合超长轨迹。
- **结果随轨迹长度/根因距离非单调变化**：RCTA在≤100步轨迹上精确率30.3%，101–400步降至20%左右，>400步又回升至31.0%（但该桶样本少、来源组成特殊）；按距离分桶也无单调规律，表明复杂度受多因素影响。
- **责任角色与根因步骤应分开评估**：RCTA 角色准确率远高于根因精确率，论文认为这证明了角色归因不能替代事件定位，基准需同时提供两个独立目标。

### 7. 优点

- **基准设计的针对性**：专注于长轨迹（中位145步）且根因可远离终点（中位48步），填补了现有短轨迹故障归因基准的空白；全部轨迹为“自然失败”（无注入错误），更贴近实际部署。
- **独立双任务标注**：责任角色与根因步骤分别人工标注、分别评分，明确禁止从根因步骤推导角色，避免了常见混淆。
- **清晰的操作定义**：论文给出了根因判定的明确规则（手令错误、修复排除、验证器遗漏等），并用于人工标注与方法实现，保证标签一致性。
- **无训练、即插即用的方法**：RCTA 不依赖额外训练数据或领域微调，仅通过分段摘要+回溯手令来提升准确率，便于迁移到其他长轨迹诊断场景。
- **严谨的评估协议**：程序化验证角色/步骤合法性、无效输出重试、MAE采用按源加权有效输出计算；冻结提示词并记录 SHA-256 哈希，保证实验可复现。
- **局限性讨论诚实充分**：论文明确区分描述性关联与因果结论，并列出标注范围、评估时点（离线后验）、骨干依赖等限制。
