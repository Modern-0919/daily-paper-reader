## 摘要
大型语言模型（LLM）智能体现在能够执行涉及复杂工具使用、代码执行、文件编辑和生成制品的长期技术工作流。随着智能体更快地完成更多工作，生产力瓶颈从生成输出转移到审计这些输出是否正确和可信。智能体可观测性系统使细粒度的执行事件可见，但仅凭可见性仍需要审查者重建哪些行动、制品和验证步骤对特定结论是重要的。我们介绍了LEDGER——用于执行审查的分层证据与决策图，这是一个在观察到的智能体会话上构建分层追踪图的追踪与审查系统。LEDGER保留追踪记录，同时将它们分组为证据节点和工作流节点，将制品表示为证据锚点，并添加类型化语义边，将声明与支持行动、制品和检查连接起来。通过数据分析和编码示例，我们展示了生成的追踪如何暴露工作流决策、制品血统、修复步骤、验证覆盖率以及以证据为中心的审计的声明支持路径。

## Abstract
Large language model (LLM) agents can now carry out long-horizon technical workflows involving complex tool use, code execution, file edits, and generated artifacts. As agents do more work faster, the productivity bottleneck shifts from producing outputs to auditing whether those outputs are correct and trustworthy. Agent observability systems make fine-grained execution events visible, but visibility alone still leaves reviewers to reconstruct which actions, artifacts, and validation steps matter for a particular conclusion. We introduce LEDGER - Layered Evidence and Decision Graphs for Execution Review, a tracing and review system that builds layered trace graphs over observed agent sessions. LEDGER preserves Trace Records while grouping them into Evidence Nodes and Workflow Nodes, representing artifacts as evidence anchors, and adding typed semantic edges that connect claims to supporting actions, artifacts, and checks. Through data-analysis and coding examples, we show how the resulting traces expose workflow decisions, artifact lineage, repair steps, validation coverage, and claim-support paths for evidence-centered audit.

### 1.2 核心问题

论文聚焦于以下核心痛点：

- 人类审查通常是**以证据为中心**的：审查者从某个报告结论出发，追问"什么支持它？哪个制品包含相关证据？哪个行动产生或修改了该制品？是否有验证步骤？"
- 从扁平的事件记录中回答这些问题，需要人工重建任务结构和证据关系，成本随会话长度和复杂度急剧增长。
- 现有方法（如事件轨迹可视化、过程评分、监测判断、失败标签等）大多产出分数或标签，**未能直接帮助人类审查者将结论与其背后的证据链连接起来**。

### 1.3 研究意义

- 本工作试图填补"记录捕获"与"证据审查"之间的鸿沟：在可观测性之上构建一个**审查层**，让用户能够从结论反向追溯到支撑它的具体行动、制品和检查步骤。
- 核心主张是：**审查路径应当是"可遍历"的，而不是需要人工重建的**。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 总体框架概述

LEDGER（Layered Evidence and Decision Graphs for Execution Review）是一个**旁路追踪器（sidecar tracer）**系统，在未修改的交互式智能体会话旁运行。它捕获会话记录，将其解析为分层语义追踪图，核心架构如下：

```
捕获层（Capture Layer） → 追踪记录层（Trace Records） → 证据层（Evidence Nodes） → 工作流层（Workflow Nodes） → 制品锚点（Artifacts） + 语义边（Semantic Edges）
```

### 2.2 三层图结构

**第一层：追踪记录（Trace Records）**——确定性基础

- 是最低粒度的观测记录，保留消息内容、工具调用及结果、生命周期边界、制品引用、时间信息以及与原始转录的链接。
- **关键设计原则**：追踪记录是"捕获的证据"而非"推断的解释"。它们是构建审查图的稳定基座，不掺杂语义解读。
- 在Codex实现中，通过**生命周期钩子**（SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、PermissionRequest、Stop）捕获JSON负载，并维护实时转录快照。
- 捕获方式同时保留两层证据：(1) 原封不动的Codex转录JSONL；(2) 规范化的trace.json追踪摘要（将转录行索引为会话/轮次上下文、可见消息、工具调用与结果、生命周期事件、推理摘要等稳定记录类型）。
- **覆盖记录（coverage records）**使缺失或未知的转录行明确可见而非静默丢弃。

**第二层：证据节点（Evidence Nodes）**——可检查的工作单元

- 将紧密相关的追踪记录分组为一个可检查的工作单元。例如，工具调用请求与其结果共享组ID，合并为一个证据节点。
- 证据节点分为两类：
  - **行动节点（Action）**：包括控制（control）、用户消息（user_message）、助手消息（assistant_message）、工具调用（tool_call）等类别。
  - **制品节点（Artifact）**：代表可检查的对象（代码片段、图表、表格、补丁、文件等），作为证据锚点。

**第三层：工作流节点（Workflow Nodes）**——任务阶段

- 将相关证据节点聚合为工作流阶段（如上下文、计划、检查、执行、验证、声明）。
- 解决长会话中"大量小动作只有在更大阶段背景下才有意义"的问题。
- 表格中定义了六类工作流节点：context（上下文）、plan（计划）、inspect（检查）、execute（执行）、validate（验证）、claim（声明）。

### 2.3 语义边（Semantic Edges）

图表使用**六种类型化语义边**，每条边沿轨迹顺序定向，命名源与目标之间的语义关系：

| 边类型 | 关系定义 |
|--------|----------|
| `frames` | 源的需求、约束或计划为目标设定背景 |
| `uses` | 工作单元使用某制品或资源作为输入 |
| `produces` | 工作单元创建或修改某制品、输出或状态 |
| `informs` | 源证据或结果影响目标的后续分析、计划或行动 |
| `checked_by` | 源变更或结果被目标的验证步骤检查 |
| `supports` | 源证据或发现证明目标的声明或已承诺选择是合理的 |

### 2.4 关键设计原则：确定性与推断性的区分

- **追踪记录层**来自确定性的转录解析，独立成立、可信度高；
- **证据层和工作流层**由"追踪构建代理（tracer agent）"阅读记录后进行解释性分组和连线，属于**推断结构**，可能存在不完整、不稳定或错误。
- 系统因此将图定位为**审计辅助工具**而非"真相来源"，界面保留底层记录供用户核查图像构建本身。

### 2.5 与现有方法的区别

- 不同于依赖智能体自我报告的Graph of Trace，LEDGER读取**未修改的交互式会话**发出的记录；
- 不同于LangGraph等在执行前定义控制流的编排图，LEDGER在捕获后构建图以表示**证据关系**；
- 支持直接追溯到模型创建的具体制品（文件、补丁、表格、绘图等）。

## 6. 论文的主要结论与发现

### 6.1 核心结论

1. **证据关系可图化**：智能体会话可以被组织为分层的语义追踪图，使声明（claim）与支持它的行动、制品和检查之间的连接变得可遍历（traversable），而非需要用户手动重建。
2. **分层设计有效**：追踪记录层提供确定的证据基底，证据节点和工作流节点使长会话在阶段级别可审查，制品锚点使审查能延伸到消息流之外的可检查对象。
3. **修复步骤与设计选择可分离**：编码案例中，LEDGER成功将"智能体设计的实现"与"事后修复"区分为不同阶段和独立证据，使审查者能分辨哪些行为来自原始设计、哪些来自事后发现的边缘情况。
4. **验证覆盖可读**：追踪图能显示哪些测试覆盖了哪些行为（首次测试检查有序访问行为，回归测试检查守护逻辑），使审查者能理解声明"背后支撑的边界"而不是仅知道"存在支撑"。

### 6.2 两类审计路径的验证

- **数据分析任务**：追踪图承载了从源文件→清洗步骤→生成表格和绘图→报告得出的日模式的完整制品谱系，错误-修复序列（因可选依赖失败的首次脚本执行→补丁→成功重新运行）在图中清晰可见。
- **编码任务**：追踪图将代码变更追溯到放置它的仓库阅读，并向前连接到验证它的测试；声明通过`supports`边回连到变更文件、文档更新、聚焦测试运行、导入检查和最终diff审查。

## 7. 优点

### 7.1 方法论亮点

1. **明确定位"捕获"与"解释"的分离**：追踪记录是确定性的、独立成立的基底；语义图是推断性的、可被审查的辅助结构。这比大多数将推断结果当作事实展示的系统更诚实和可信。
2. **"可见性≠可审计性"的精准问题定义**：清晰界定了可观测系统与审计需求之间的差距，动机阐述有力。
3. **无需修改智能体**：旁路追踪器设计（通过生命周期钩子和转录副本），不依赖智能体自我报告，适用于现有Codex等系统。
4. **覆盖记录机制**：显式标记未知或未解析的转录行，避免静默信息损失，这是工程上的务实做法。
5. **以证据为中心而非以过程为中心**：不同于过程评分或监测判断，LEDGER保持人类审查者在环，支持从结论反向走查的审计逻辑。
6. **可追溯的图构建过程**：界面包含事件/日志视图，让审查者能区分"智能体错误"与"追踪错误"，提高了图本身的问责性。
7. **制品作为一等公民**：图能连接到消息流之外的具体可检查制品（文件、绘图、表格），这对数据分析和代码开发场景至关重要。
8. **通用性潜力**：设计不特定于Codex，任何暴露类似钩子和记录的编码智能体都可支持。

### 7.2 写入质量

- 相关工作定位准确（区分了可观测性层、评估监测层、解释可视化层）。
- 对局限性的讨论（推断层非确定性）坦诚且有建设性的未来方向。

---

## 8. 不足与局限

### 8.1 方法论局限

1. **推断层不可靠性**：证据分组、工作流识别和语义边标注由追踪构建代理（LLM）推断产生，可能不完整、不稳定或错误。图只能作为审计辅助而非真相来源。
2. **制品的恢复方式较脆弱**：制品节点从工具调用的命令文本和输出中解析路径和交互类型，可扩展性和鲁棒性有限（作者也承认，对复杂文件系统操作或多步骤数据转换可能失效）。
3. **边类型边界模糊**：作者自认`uses`、`informs`、`supports`、`checked_by`在长会话中可能混淆，缺少对时间关系、数据流关系、验证关系和证据关系的显式区分。

### 8.2 实验验证局限

1. **案例数量过少**：仅两个案例，无法验证系统在不同任务类型、不同复杂度和不同会话长度下的表现。
2. **缺乏用户研究**：没有评估真实审查者使用LEDGER相较于传统追踪日志的审计效率、准确率和认知负荷差异，核心价值主张（"审计更快/更好"）未得到实证支持。
3. **缺乏定量指标**：没有图构建准确率、节点/边一致性的量化评估。
4. **缺乏对比实验**：未与Graph of Trace、ReasonGraph等可视化系统进行直接比较。
5. **单一模型验证**：仅使用GPT-5.5，未评估不同LLM作为智能体和作为追踪构建代理时的差异性。

### 8.3 应用限制与风险

- **可扩展性**：极长会话（数百/数千条追踪记录）中的图渲染和导航性能未验证。
- **安全审计场景的适用性**：如果目标是安全关键或安全性与安全性审计，推断性图结构可能造成证据污染风险，需要更强的确定性保障。
- **未披露资源信息**：缺少运行成本、延迟开销（旁路追踪对会话性能的影响未量化）。
- **环境偏置风险**：数据分析和编码均偏向特定领域，对检索、多智能体协作、多模态等其他常见智能体工作流的适配性未说明。

### 8.4 未来方向（论文自述）

- 用确定性/独立可验证结构替代模型推断结构（更强的仪器、结构化工具记录、数据溯源后端如DFTracer）；
- 对数据科学工作流，接入溯源感知后端以暴露表/列/转换级的依赖；
- 重复运行研究测量图上重建的稳定性；
- 扩展图词汇表，显式区分时间、数据流、验证和证据关系，编码不确定性；
- 改进视觉编码：区分确定性与推断性结构、突出无支撑声明和未检查制品、默认显示声明中心或制品中心的子图以减少杂乱。

---

## 总结

LEDGER提出了一个有价值且方向正确的问题——LLM智能体输出的"可审计性"需要专门的审查基础设施——并交付了一个设计合理的原型系统。其"确定性记录基底+推断性语义图+制品锚点+可追溯构建过程"的架构思想，以及"可见性≠可审计性"的核心论判，对智能体可观测性和人机审计交叉领域有积极贡献。但论文目前仍属**系统描述+案例展示**阶段，缺少对核心价值主张（提升审计效率）的实证验证，实验规模和方法论严谨性有待加强。
