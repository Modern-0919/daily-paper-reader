## 摘要
长时程智能体越来越多地跨多个步骤、工具和观察进行操作。在这种场景下，相关的监督问题不仅是每个动作在局部上是否有效，更是不断演化的轨迹是否仍然与用户授权的任务保持一致。漂移可能悄然累积：智能体可能在每一步以合理的参数调用正确的工具，而其前缀却向着更宽泛的角色、邻近的目标或用户从未提供的证据偏移。现有监控器大多检查局部合规性、给出最终轨迹判定或评分通用风险；它们并不直接估计这种前缀层级的关联。我们引入了本体信任（ontological trust），这是轨迹前缀的一种任务条件属性，并将其实例化为RGE，一个在线监控器，将信任分解为角色、目标和证据三个维度。RGE仅使用LLM来推导结构化的任务和步骤表示；信任状态更新、投影和干预决策是确定性的，因此输出是可重放、可审计的信任轨迹，而非单一的端到端评判结论。我们构建了来自OSWorld、FinanceBench和EICU-AC的跨领域轨迹语料库，涵盖良性执行、前缀配对的漂移以及伪一致性失败。在这个语料库上，RGE在前缀配对漂移检测上优于改编的基于规则、评判器和防护样式的基线。使用两个较大的估计器模型，RGE在每个基准上的漂移F1超过93%，同时保持良性覆盖率在95.8%以上。伪一致性更难：检测取决于任务完成是否在外部可见，这是我们通过实证描述的结构性局限。

## Abstract
Long-horizon agents increasingly operate across many steps, tools, and observa- tions. In this setting, the relevant oversight question is not only whether each action is locally valid, but whether the evolving trajectory still corresponds to the task the user authorized. Drift can accumulate quietly: an agent may call the right tool with plausible arguments at every step, while its prefix moves toward a broader role, an adjacent objective, or evidence the user never supplied. Existing monitors mostly check local compliance, deliver final-trace verdicts, or score generic risk; they do not directly estimate this prefix-level relation. We introduce ontological trust, a task-conditioned property of trajectory prefixes, and instantiate it as RGE, an online monitor that decomposes trust along Role, Goal, and Evidence. RGE uses LLMs only to derive structured task and step representations; trust-state updates, projec- tions, and intervention decisions are deterministic, so the output is a replayable and auditable trust trajectory rather than a single end-to-end judge verdict. We construct a cross-domain trajectory corpus from OSWorld, FinanceBench, and EICU-AC, covering benign executions, prefix-paired drift, and pseudo-consistency failures. On this corpus, RGE outperforms adapted rule-, judge-, and shield-style baselines on prefix-paired drift detection. With the two larger estimator models, it exceeds 93% Drift F1 on every benchmark while keeping benign coverage at or above 95.8%. Pseudo-consistency is harder: detection depends on whether task completion is externally visible, a structural limit we characterize empirically.

### 1. 核心问题与整体含义

- **研究背景**：长时程智能体在多个步骤、工具和观察中执行任务时，可能每一步都看似“局部合理”（调用正确工具、参数合理），但轨迹前缀整体上却已偏离用户授权的任务范围。这种“悄然累积的漂移”是现有监督手段难以捕捉的。
- **核心痛点**：现有方法存在明显的监督盲区——运行时监控器只检查规则合规性；任务基准只评估最终结果；安全基准只关注显式提示注入；局部异常检测器只标记可疑单步；LLM-as-judge则返回非结构化的整体风险判定。所有这些都**不直接回答“当前轨迹前缀还是不是用户授权的那个任务”**。
- **核心概念**：论文提出**本体信任（Ontological Trust）**，将其定义为轨迹前缀与授权任务之间的任务条件关系，并分解为三个维度：**角色（Role）、目标（Goal）、证据（Evidence）**。当这三个维度之一或多个发生显著偏离时，即发生“信任漂移”（trust drift）。该概念的意义在于：将监督对象从“局部动作合法性”转向“前缀-任务关系”，这是长时程委派监督的根本性问题。

### 2. 方法论：RGE 在线监控器

- **总体思想**：RGE 将 **LLM 的语义解释能力**与**确定性状态演进**分离。LLM 仅用于从任务指令和每步动作-观察对中提取结构化表示；信任状态更新、投影和干预决策全部由确定性计算完成，保证输出可重放、可审计。
- **四阶段流水线**（对应图 3）：
  - **阶段 I：任务条件完成结构公式化**。在执行前，从任务指令推导出最小完成间隙集合 G(x) = {ξ₁, ..., ξ_K}，每个间隙包含描述、闭合证据条件和类型（core/support）。同时生成一个紧凑的任务域配置文件。
  - **阶段 II：局部结构化解析与状态记忆更新**。每一步调用一次 LLM，基于任务、历史前缀、当前动作-观察对和记忆状态，解析出类型化语义字段（身份信号、逻辑信号、因果信号、候选间隙闭合等）。记忆更新采用**保守确认规则**：解析器提出的间隙闭合只有满足固定确认标准才被计为已确认进展，否则仅停留在候选状态。
  - **阶段 III：投影到 Role-Goal-Evidence 偏差**。将解析字段通过固定的类别-标量映射表投影为三个一致性分数 qᵣ、q_g、q_e，偏差向量 z_t = (r_t, g_t, e_t) = (1-qᵣ, 1-q_g, 1-q_e)。z_t = 0 称为“信任原点”。
  - **阶段 IV：时间聚合与阈值决策**。组合三维偏差为瞬时偏差分数 u_t，引入**结构耦合项** φ_t 捕获三轴同时超阈值时的联合偏离效应：
    - u_t = αᵣr_t + α_g g_t + α_e e_t + λφ_t
    - 时间状态更新：s_t = γs_{t-1} + u_t（持续累积）、m_t = s_t − s_{t-1}（漂移趋势）、c_t = βc_{t-1} + (1−β)u_t（短时爆发统计）
    - 决策阶梯：输出 ALLOW / JUSTIFY / REANCHOR / CONTAIN 四级标签，由单一灵敏度参数 κ=0.5 派生所有阈值。
- **关键超参数**（固定值，无跨域调参）：αᵣ=0.34、α_g=0.33、α_e=0.33、λ=0.25、γ=0.85、β=0.70、耦合阈值 ϑ=0.40。

### 3. 实验设计

- **数据集与语料库构建**：
  - 基于三个已发布基准源任务构建轨迹语料：**OSWorld**（桌面GUI/系统自动化）、**FinanceBench**（金融文档推理）、**EICU-AC**（电子健康记录结构化临床查询）。
  - 最终语料：80 个唯一源任务、248 条轨迹（80 条良性参考执行、81 条前缀配对漂移、87 条伪一致性变体），平均轨迹长度 7.9 步。所有轨迹均由 **Claude Opus 4.6** 作为 actor 模型生成，与评估模型完全分离。
  - 漂移轨迹包含 5 种子类型：角色漂移、角色扩张、目标重写、潜在劫持、证据断裂。
- **Baseline 对比**（设计空间表 1）：
  - **B1 AgentSpec**：符号规则执行
  - **B2/B3 R-Judge（k=1 / k=3）**：单步/三步窗口的 LLM 安全判定
  - **B4 AgentAuditor**：离线全记录非结构化判定

### 6. 主要结论与发现

- **单步信号不足**：所有 9×3 种快照指标组合的最佳 AUC 仅 73.49%（Causal Grounding + Llama-3-8B），Predictive Entropy 接近随机（47–56%）。良性与漂移步骤在局部信号上高度重叠，证实前缀-任务关系无法从单步还原。
- **三轴坐标恢复信号**：回顾式轨迹级 RGE 坐标达到 97.67% / 97.45% / 98.86% 的轨迹 AUC（Qwen3-4B / Llama-8B / GPT-4o-mini），远超单步天花板。移除任一坐标均降低 AUC。
- **在线监控有效**：GPT-4o 和 Qwen3.5-9B 在每个基准上 Drift F1 超过 93%，良性覆盖率 ≥95.8%。RGE 大幅优于 AgentSpec（Drift F1=0）、R-Judge（约 25–32%）、AgentAuditor（约 30%）、MAS-Shield（Drift F1=66% 但良性覆盖率仅 2.7–4.9%）。
- **伪一致性检测存结构性天花板**：Pseudo F1 中位数仅 18.2%。OSWorld（UI 任务有显式完成状态）可达 98.4%；FinanceBench 和 EICU-AC（只读推理域）则显著受限——没有外部可见的闭包信号，仅凭 (x, h≤t) 无法可靠区分良性核验与伪一致性。
- **轴分解结论**：Role/Goal 主要携带前缀配对漂移信号，Evidence 主要携带伪一致性信号；全状态优于一切子集组合。
- **任务条件性验证**：任务交换 AUC 达到 0.991 / 0.999 / 0.962，证明 RGE 确实响应任务关系而非通用轨迹特征。

### 7. 优点

- **LLM 与确定性计算分离的设计**：输出是可重放、可审计的“信任轨迹”而非端到端判断，这对安全关键部署极具价值。每一步仅需一次 LLM 调用，适合在线监控。
- **跨域迁移性**：单一提示模板和固定超参数在桌面、金融、临床三个差异显著领域均有强表现，证明方法的通用性。
- **结构耦合项设计**：当三轴均超阈值但单轴偏移不显著时，耦合项仍能捕获联合偏离，避免线性组合的盲区。
- **保守确认机制**：对伪一致性形成天然防御——表面核验只能停留在候选状态，不推进记忆中的完成度。
- **理论框架清晰**：从 POMDP 视角推导三类偏差来源，将本体信任建立在 agent-环境交互结构之上，而非任意约定。
- **实验设计严谨**：任务交换检查、长度分桶、分类型分解、关闭轨迹相关性的 bootstrap 等多角度验证结果的稳健性。

### 8. 不足与局限

- **可观测性根本限制**：监控器只能访问 (x, h≤t)，无法看到内部推理、隐藏提示状态或未观察到的环境变化。在只读推理域，伪一致性检测存在**结构上限**——环境不暴露闭包信号时，任何仅基于轨迹的监控器都无法可靠区分核验与伪进展。
- **小模型能力瓶颈**：Gemma-4-E4B-it 在 EICU-AC 上 Drift F1 仅 33.3%，在证据密集或领域特定的临床场景中，解析器成为瓶颈。
- **伪一致性检测整体偏弱**：Pseudo F1 中位数仅 18.2%，除 OSWorld 外在共享阈值下检测率很低。作者承认这是结构性限制而非简单的阈值调整问题。
- **评估覆盖有限**：248 条轨迹、80 个源任务，规模较有限；未覆盖代码生成和网页浏览任务；单一 actor 模型（Claude Opus 4.6）生成所有轨迹，未测试生成器多样性。
- **基线比较的可解释性局限**：各基线使用原生默认协议，B4 获得全记录、RGE 仅在线前缀，不对称比较使差距的来源（上下文长度 vs 结构化表示）不完全可分离。
- **代码与数据未公开**：作者在 FAQ 中明确说明代码和轨迹语料尚未公开，仅承诺未来版本提供存档仓库，可复现性暂时受限。
- **边界情形未完全解决**：合法的任务重新协商、多轮澄清、边界邻近轨迹的处理规则虽已定义，但部署时的误干预风险和专家工作流被打断的风险仍需关注。
- **知识性校验缺口**：Trust 与 Safety 的区分已厘清，但 RGE 不替代安全过滤，两者需要叠加部署，这增加了实际系统的复杂度。
