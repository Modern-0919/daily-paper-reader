## 摘要
当模型内部的不确定性信号（如令牌对数概率）不可用时，可靠的网络代理监控变得困难。在这项工作中，我们研究了基于可观察轨迹信号的前缀级风险预测：给定一个不断演变的前缀，估计当前执行是否仍在正轨或趋向于失败。我们推导了两种可观察的轨迹表示：宏观特征总结跨步骤的代理-环境行为和反馈，而微观特征通过重复的黑盒查询衡量意图、行动和预期状态变化之间的一致性。我们不是继承最终结果标签，而是将观察到的延续中未被纠正且与最终失败相关的第一个关键错误标记为关键步骤边界，保留失败轨迹的有效早期前缀作为在轨。在WebArena-Lite和Online Mind2Web网络代理基准测试中，使用五种开源和闭源骨干模型，可观察的轨迹信号与内部信号基线相比具有竞争力。生成的预测器还支持在固定误报预算下的早期干预，并能跨保留的网站类别转移。这些发现表明，可观察的轨迹信号支持有价值的风险预测能力。

## Abstract
Reliable web-agent monitoring is difficult when model-internal uncertainty signals such as token logits are unavailable. In this work, we study prefix-level risk prediction for web agents using observable trajectory signals: given an evolving prefix, estimate whether the current execution remains on track or is tending toward failure. We derive two observable trajectory representations: Macro features summarize cross-step agent--environment behavior and feedback, while Micro features measure the consistency of intention, action, and anticipated state change through repeated black-box queries. Instead of inheriting the final result label, we label the first critical error that remains uncorrected in the observed continuation and is associated with final failure as a key-step boundary, preserving valid early prefixes of failed trajectories as on track. Across WebArena-Lite and Online Mind2Web web agent benchmarks with five open- and closed-source backbones, observable trajectory signals are competitive with internal-signal baselines. The resulting predictors also support early intervention under fixed false-cut budgets and transfer across held-out website categories. These findings show that observable trajectory signals support valuable risk prediction abilities.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：Web Agent（网络代理）在完成多步交互任务时极易出错，一旦走上一条偏离目标、注定失败的轨迹，继续运行会浪费大量 token 与时间。因此需要「前缀级失败风险预测」：利用当前已发生的前缀轨迹，估计整个任务最终失败的可能性，进而支持早期干预。
- **核心挑战一（输入可观测性）**：许多不确定性量化方法依赖 token logits、隐藏状态等模型内部信号，但这些信号在闭源模型或 API 部署中通常不可获取。然而，监控者可以观察到 agent 的决策文本、执行动作和环境反馈。作者要回答的问题是：**这些纯可观察的轨迹信号，是否足够支撑前缀级的失败监控？**
- **核心挑战二（前缀监督）**：任务的最终结果是稀疏的终端标签，若将其简单传播到所有前缀，会把失败轨迹中**本来有效、与成功轨迹类似的前缀**也错误标记为失败。这需要更符合时间语义的、步骤级的关键错误标注。
- **整体含义**：作者主张，即使无法访问模型内部信号，仅依赖可观察轨迹（宏观行为模式 + 微观决策一致性），也能有效预测 Web Agent 的失败风险，支持早期干预与跨网站类别泛化。

## 2. 方法论

作者提出一套「可观察轨迹信号 + 关键步骤监督」的完整方案。

### 2.1 问题形式化

- 定义轨迹前缀 τ≤k = (q, 历史信息, 当前动作后的反馈)。
- 预测目标是前缀级的二分类标签 yi,k：
  - yi,k = 1 当且仅当轨迹最终失败（Fi = 1）且当前前缀已经到达或超过**关键失败步骤** k⋆。
  - yi,k = 0 表示仍处于有效前缀（含成功轨迹的所有前缀以及失败轨迹中关键步骤之前的前缀）。
- 风险定义为 ri,k = P(yi,k = 1 | τ≤k)，由预测器 fθ 将观测信号 z 映射为概率：fθ(z) = σ(w⊤z + b)。

### 2.2 两类可观察轨迹信号

- **Macro（宏观）特征（31 维）**
  - 直接由已发生前缀计算，无需额外模型查询。
  - 包含：当前步数、动作重复与循环数目、动作多样性、动作重复率、最近新动作间隔、执行与定位错误计数、连续错误长度、动作类型分布、目标元素多样性、思考文本中报告的无效动作/错误环境/错误上下文计数、推理文本长度等。
  - 反映跨步骤行为症状（如错误累积、循环、重复点击）。

- **Micro（微观）特征（18 维）**
  - 在每一步对同一上下文重复黑盒查询 N=10 次，要求 agent 给出「意图、可执行动作、预期状态变化」三个结构化输出。
  - 对文本做语义聚类（Qwen-0.6B 编码器 + 凝聚聚类），估计输出的经验分布。
  - 计算 6 个指标：意图熵、状态变化熵、落地熵、条件状态变化熵、意图贡献度、残差动作不确定性。
  - 每个指标按前缀取均值、最大值、当前值三种聚合，得到 18 维。
  - 用于衡量潜伏决策不确定性而非事后行为结果。

### 2.3 关键步骤（Key-Step）监督

- 对失败轨迹，标注**关键失败步骤**：第一个在之后观察中未被纠正、且与最终失败相关的重要错误。
- 使用 LLM-as-judge（Gemini-3.5-Flash）+ 人工审阅提炼的 codebook，两阶段流程：前向逐步扫查错误与恢复，再按时间顺序复核并选取最早的关键错误。
- 关键步骤只用于构造训练标签，预测器本身不预测关键步骤位置；所有信号遵循前缀有效性（不泄露未来信息）。

### 2.4 预测器与训练

- 使用 ℓ2 正则化逻辑回归（与同类基线保持一致）。
- 5 折交叉验证按任务切分；Macro 的计数特征按前缀长度做归一化；特征标准化只基于训练折统计。

## 3. 实验设计

### 3.1 数据集 / Benchmark

- **WebArena-Lite**：165 个任务的可复现 Docker 环境。
- **Online Mind2Web**：300 个任务、136 个真实在线网站，环境更具异质性和动态性。
- 最终保留：774 条 WebArena-Lite + 1409 条 Mind2Web 轨迹，合计 2183 条。

### 3.2 Agent 骨干模型（5 种）

- 开源：Qwen3-VL-30B、Kimi 2.5
- 闭源：GPT-5.2、GPT-5.4-nano、Claude Sonnet 4.6
- 使用 ReAct 风格 agent 框架。

### 3.3 对比基线

- **HTC-Full**：最相关的轨迹级不确定性方法，作者将其改造为前缀版本，但需要内部信号（Claude 上 N/A）。
- **Verbalized Confidence**、动作熵、动作/输出 log-probability：单步标量基线。
- **Stacked L2**：将这些标量输入同样的 ℓ2 逻辑回归，以区分「监督拟合的好处」与「特征本身的信息量」。
- 方法间对比：Macro、Micro、Macro&Micro（M&M）。

### 3.4 评估指标

- **Brier Score**（概率准确性；越低越好）
- **E-AURC**（选择性风险-覆盖率曲线的超额面积；越低越好）
- **AUROC**（判别力；越高越好）
- 另设计**Early-Cut 模拟**：在固定假切率预算（5%–20%）下比较失败检测率；以及 5 个网站类别上的跨类别迁移测试。

## 6. 主要结论与发现

- **可观察轨迹信号在多数情况下能与内部信号基线竞争**：
  - 在 Mind2Web 上 15 个骨干–指标对比中表现优于所有基线；在 WebArena-Lite 上 15 个组合中的 9 个是最优。
  - M&M 在 E-AURC 与 AUROC 上全面打败 Stacked L2，证明优势并非来自同样的监督拟合。
- **Macro 与 Micro 分工不同**：
  - Macro 是更强的独立信号；Micro 在 Mind2Web 上提供明显互补价值（其真实网站非确定性和反馈异质性被 Micro 的重采样一致性捕获），但在 WebArena-Lite 上的增益不稳定。
  - 案例研究显示：Macro 对重复同一动作、循环等行为症状敏感；Micro 对 grounded 决策不一致（如十次采样中动作分布高度分散）敏感；两者结合能降低对有效早期前缀的错误报警。
- **关键步骤监督显著优于最终结果监督**：
  - 在成功轨迹的前缀上，最终结果监督下 false cut 率在 γ=0.5 时高达 87.3%–93.0%，而关键步骤监督把该比例降到 27.6%–28.6%。
- **支持早期干预**：
  - 在 5%–20% 固定假切率预算下，可观察信号的早期切断能力在 8 个操作点中的 7 个超过 HTC-Full。
- **跨类别可迁移**：
  - 在 5 个网站类别中，用其他四类训练的模型与同类别训练的参考几乎持平，AUROC、E-AURC 和 Brier 差距均比类别间波动小一个数量级。

## 7. 优点

- **直击黑盒部署痛点**：不需要任何模型内部信号，只利用 API 可返回的文本、动作、反馈，适用性更广。
- **提出关键步骤标签**：从行为时间角度修正了「把失败传播到所有前缀」造成的错误监督，概念清晰、可操作性强。
- **宏观+微观互补设计**：分别抓住行为的实际后果与潜在不确定性，二者在案例分析和统计消融中均显示出明确分工。
- **标注质量验证充分**：LLM judge 与人标注的按键标签定位 agreement 89.8%，多轮 run 间的标签一致性 90.9%，还做了 majority voting 的形式化等价推导。
- **系统性稳健性测试**：对语义聚类编码器/阈值、采样数量子采样、特征组消融、跨类别转移、时间区域（early/mid/late AUROC）等做了多层次评估。

## 8. 不足与局限

- **Agent 框架覆盖单一**：仅使用 ReAct，不能确认结论在规划型、代码型或重工具型 agent 上同样成立。
- **监督对照组不完美**：Stacked L2 只用了少量标量特征，无法彻底拆开「监督拟合收益」与「特征内容收益」。
- **并非在所有设置中占优**：部分 backbone–benchmark–metric 组合仍是内部信号或具体标量基线更强，尤其 E-Commerce 类别上 HTC-Full 更好。
- **Micro 的成本较高**：N=10 的重复查询和语义聚类带来推理延迟；附录虽然给出 N=5/8 的折中，但并未消除额外开销，且要求 agent 输出结构化意图/转换描述，若 agent 不提供这类文本则无法使用。
- **关键步骤语义有局限**：它识别的是「在观察到的后续中未被纠正」的错误（事后知识），并不等于客观上不可恢复的状态；这是用于监督的近似标签，而非因果保证。
- **环境与任务范围有限**：真实在线网站的分布与 Docker 静态任务差异大，跨 benchmark 的增益并不一致；论文也未讨论对更复杂、更长任务（如代码仓库级或多人机协作）的可扩展性。
