## 摘要
近期的大型语言模型能够发出任务进度信号，智能体框架利用这些信号来决定任务是否应继续或停止，然而模型是否能在任务的每个阶段可靠地报告其任务进度，以及其报告在何处、如何失败，尚未被系统研究。我们在公开基准τ²-bench以及StageIF（一个受控测试平台，其中报告检查点被设置在任务生命周期的各个阶段）上评估了这种能力。两种设置都要求在多个任务阶段进行报告。我们发现，报告的可靠性取决于任务已到达的阶段，而且我们测试的几乎每个部署模型在某些阶段可靠，在其他阶段则不可靠。报告失效的地方并不完全相同。大多数部署模型一旦工作开始进行，准确性就会下降，而在任务完成后则恢复。最新一代模型弥补了任务中途的下降，反而在终点线变得保守。我们的研究揭示了任务进度报告中的能力差距，并提供了一种评估协议，该协议贯穿任务执行的全过程，用于评估这种智能体操作所依赖的能力。研究结果表明，智能体框架不应仅凭模型的状态报告来控制任务流程。

## Abstract
Recent large language models can emit task-progress signals that agent frameworks use to decide whether a task should continue or stop, yet whether a model can reliably report its task progress at every stage of a task, and where and how its reports fail, has not been studied systematically. We evaluate this ability on the public benchmark $τ^2$-bench and on StageIF, a controlled testbed in which reporting checkpoints are placed across the task's lifecycle. Both settings require reports at multiple task stages. We find that reporting reliability depends on the stage a task has reached, and that almost every deployed model we test is reliable at some stages and unreliable at others. Where reporting breaks down is not the same everywhere. Most deployed models lose accuracy once work is under way and recover once the task is done. The newest generation closes that mid-task drop and instead grows conservative at the finish line. Our study exposes a capability gap in task-progress reporting and provides an evaluation protocol that spans the whole course of task execution for this ability on which agent operation depends. The findings indicate that agent frameworks should not control task flow on the strength of the model's state reports alone.

## 2. 方法论

- **总体思想**：给智能体增加报告义务（reporting duty），要求其在指定时机输出结构化的生命周期阶段标签；再通过与任务环境真实状态机械对比，判断报告是否正确。报告正确性不作为决定任务最终成败的标准，二者被刻意分离。
- **四个阶段值**：`NEEDS_INFO`（还在收集信息）、`READY`（准备行动而未变化）、`POST_OBS`（已有行动结果但任务未完）、`COMPLETED`（无剩余事项）。
- **第一套实验——τ²-bench上的原生改造**：
  - 在公开的电信/零售对话式工具智能体基准中添加一条指令：每个面向用户的回复必须附一个阶段标签。
  - 正确答案通过将对话前缀放入全新环境中重放、读取环境状态来“机械化”确定，在解析模型回复前完成，从而独立于模型输出。
  - 由于环境状态无法区分`NEEDS_INFO`与`READY`，这两个状态在行动前检查点被视为可互换。
- **第二套实验——StageIF受控测试台**：
  - 12个脚本化场景（调度与客服各半），每个场景生成5个检查点；其中4个要求报告、1个禁止报告（正确行为是继续调用工具而不说话）。
  - 报告义务被放置在任务生命周期任意位置；正确值在任何模型输出前冻结。
  - 设计四层失败分类：**行为偏移**（该说话却调用工具，divergence）、**报告省略**（omission）、**格式错误**（malformed）、**值错误**（wrong value）。另有“传输失败”不计入模型得分。
  - 使用XML和JSON两种结构化编码，均对应确定性解析器。
- **形式化评分框架**：
  - 检查点定义为 \( c=(i,t) \)，面向对象包括运行时状态 \(X_c\)、模型可见历史 \(H_c\)、模型响应 \(Y_c=(B_c,R_c)\)。
  - Oracel函数 \(G(X_c)=(D_c,Z_c^*)\) 输出“报告义务是否激活”和生命周期真值。
  - 主指标——阶段条件“端到端契约遵从率”：\(\theta_z = \Pr(M_cE_cV_cF_c=1 \mid D_c=1, Z_c^*=z)\)，其中 \(M_c\) 为交互模式正确、\(E_c\) 为报告存在、\(V_c\) 为报告值与真值相等、\(F_c\) 为格式合法。
  - 诊断性指标——条件报告有效性：\(\phi_z = \Pr(E_cV_cF_c=1 \mid D_c=1, Z_c^*=z, M_c=1)\)，临时排除工具调用回合，用于把行为偏移与纯报告失败分开。
  - 正确抑制率 \(\omega\)（在不应报告时不报告）、虚假完成率 \(\mu/\nu\)（任务未完却称`COMPLETED`）。
  - 错误码按优先级：`TRANSPORT > APP_MISS/APP_DIVERGENCE/APP_FALSE_ALARM > MALFORMED > STATE_WRONG > CLEAN`，确保每检查点只有一个归因。
- **有界干预**：除baseline外，提供真实阶段（gold-injected）、常数标签、惰性标签、尾部提醒、思考模式开关、匹配义务等变体；后续还设计2×2×2因子分解，分别操纵“责任归属”“工具可用性”“反馈线索”，并运行验证性rollout比较不同的终止配置。

## 6. 主要发现与结论

- **核心经验规律——可靠性随阶段剧烈变化**：
  - 模型在“任务完成”节点上的报告准确率往往较高，但在最需要人为接管的“进展中”节点上可靠性明显下降。
  - 不同模型失效点不同：有的在信息收集阶段过早宣称完成，有的在行动后错误标记为准备状态，有的在应当沉默时多言。
- **失败模式并非单一，而是分层叠加**：
  - 最普遍的是策略性“多言”：面对报告义务，模型宁可输出一个错误状态并附一段人类可读文本，也不愿意沉默调用工具。
  - 在格式正确的前提下，仍会出现大量“值正确但时机错”“值错但结构对”的组合，说明问题不能被简单归结为格式约束不足。
- **简单干预无法稳定修复缺口**：
  - 无论注入真值状态、提供更明确的标签定义、提醒语言、责任归属变化、工具供给变化，都未能一致消除“模型不知或不愿报告真实阶段”的偏差。
  - 推理开关（思考模式）的影响是混合的：某些模型关闭推理后报告更稳，另一些则相反；说明报告可靠性与推理模式之间没有单调关系。
- **“模型自述进度”不可作为终止判定的充分依据**：
  - 这是全文最重要的操作性结论。报告值与环境真值的一致性波动大，且错误方向偏向于“过早完成”。
  - 系统若要安全停止任务，必须引入独立于模型自述的校验信号（如工具返回体、外部状态、时间限制策略）。
- **责任归属、反馈线索与工具可用性存在交互**：
  - 当系统明确要求模型报告进度、提供工具调用后的反馈线索时，模型能略微改善；但当反馈不足或工具不可用时，改善消失。
  - 行为偏移（该报告却调用工具）在“工具可用”的条件下显著减少，反向说明模型倾向于把“状态刷新”类行为当作沟通替代物。
- **跨语言与跨场景的推广不均衡**：
  - 在英文翻译场景复制中，部分模型表现稳定；在非英语表面上，报告可靠性与格式遵从普遍下降。
  - 模型在结构化任务脚本上的表现优于开放式对话轨迹，提示“报告可靠性”受任务边界明显影响。

## 7. 整体定性判断与推荐程度

- **选题价值高**：论文切中了当前智能体工程中被广泛忽视却决定系统成败的环节——如何由运行时判定“工作是否真正完成”。它不是再堆一个 benchmark，而是对现有 agent 协议提出批判性检验。
- **方法论贡献大**：把“报告义务”引入评测流程，并设计与输出完全无关的机械化真值，是值得后续沿用的实验范式；错误分层与优先级编码也使结果高度可解析。
