## 摘要
逆向工程（RE）对恶意软件分析和漏洞发现等安全任务至关重要，而大型语言模型（LLM）智能体正日益能够自主执行此类任务。夺旗（CTF）逆向工程挑战已成为衡量这一能力的标准代理指标，但评估仅依赖单一标准：智能体是否获取了旗帜。该解决率既无法揭示智能体在逆向工程过程的哪个环节失败，也无法判断成功是源于对二进制文件的分析还是对公开解决方案的回忆。在本文中，我们提出Reveree，一个诊断框架，它从三个层级对LLM逆向工程智能体的轨迹进行评分：解决率、通过八阶段逆向工程模式取得的里程碑进展，以及其动作的行为画像。理解阶段由对结果不知情的LLM评判员（经人类专家验证）评分；所有其他阶段均以确定性方式验证。利用Reveree，我们在88个picoCTF和NYU-CTF挑战上评估了九个前沿模型和四种提示策略。我们发现基础模型主导性能，而提示策略是次要的、依赖模型的因素。令人惊讶的是，更大、更新或更昂贵的模型并非可靠地更强。我们还发现失败集中在逆向工程过程的理解阶段，额外的预算、持久性或推理努力很少能挽救这些失败，这指向能力极限而非资源极限。关于记忆化，虽然模型能仅凭挑战描述复现picoCTF旗帜，但NYU-CTF显示出可忽略的可测量记忆，且大多数成功解题在表面扰动后依然存活，表明真实分析与记忆化并存。我们将Reveree发布给社区。

## Abstract
Reverse engineering (RE) is critical to security tasks such as malware analysis and vulnerability discovery, and large language model (LLM) agents are increasingly able to perform it autonomously. Capture-the-flag (CTF) RE challenges have become the standard proxy for measuring this capability, but evaluation rests on a single criterion: whether the agent captures the flag. This solve rate reveals neither where in the RE process an agent fails nor whether a success reflects analysis of the binary or recall of a public solution. In this paper, we propose Reveree, a diagnostic framework that scores an LLM RE agent's trajectory at three tiers: solve rate, milestone progress through an eight-stage RE schema, and a behavioral profile of its actions. Comprehension stages are scored by an outcome-blinded LLM judge validated against a human expert; all other stages are verified deterministically. Using Reveree, we evaluate nine frontier models and four prompting strategies on 88 picoCTF and NYU-CTF challenges. We find that the base model dominates performance, whereas prompting strategy is a secondary, model-dependent effect. Surprisingly, larger, newer, or costlier models are not reliably stronger. We also find that failures concentrate at the comprehension stages of the RE process, and that extra budget, persistence, or reasoning effort rescues few of them, pointing to a competence limit rather than a resource limit. Regarding memorization, while models reproduce picoCTF flags from challenge descriptions alone, NYU-CTF shows minimal measurable recall, and most solves survive surface perturbation, indicating that genuine analysis coexists with memorization. We release Reveree to the community.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心背景**：逆向工程（RE）是安全任务（如恶意软件分析、漏洞发现、固件分析）的关键环节。该工作本质上高度依赖多步迭代的工具使用与假设驱动分析，长期以来由人工完成，成本高昂。
- **核心问题**：LLM 智能体已表现出端到端自主执行 CTF 逆向挑战的能力，但现有评测体系仅依赖一个非常粗糙的指标——**solve rate（解决率）**，即智能体是否成功捕获 flag。这一指标存在三个严重缺陷：
    1. **在难题上失效（容易触底）**：当挑战难度高、所有模型解决率都趋近于零时，解决率无法区分模型间差异、无法区分"差一点成功"与"毫无进展"。
    2. **无法定位失败原因**：逆向工程包含多个相异的子能力阶段。一个已恢复核心算法、却在最后一步构造求解器失败的任务，与一个从未解析过文件格式的任务得同样的 0 分，但这两种失败需要完全不同的修复方式。
    3. **无法区分推理与记忆（Reasoning vs. Recall）**：公共 CTF 挑战及其题解大量存在于网页中并进入模型预训练数据。模型很可能通过记忆复现 flag，而非真正分析二进制文件。
- **核心意义**：本论文提出 REVEREE——一个可诊断 LLM 逆向智能体行为轨迹的评估框架，能在比 solve rate 更深的层面上区分进展、定位失败阶段、分离真实分析与记忆化，为社区提供一个更可靠、更细粒度的评测工具。

### 2. 论文提出的方法论（核心思想、关键技术细节与流程）

- **整体框架——评估管线**：将"挑战（名称/描述/文件）"与"模型配置 + 提示策略"组合后送入沙盒环境（D-CIPHER harness 与固定 RE 工具集）。Agent 运行产生完整轨迹（thought/action/observation 序列与最终结果），该轨迹由 REVEREE 评分。其中挑战特征、模型、提示策略为可变量，环境与工具集保持不变。
- **核心机制——三层评分体系（Tier 1/2/3）**：
    1. **Tier 1: Solve rate**——保留传统二元结果指标作为基线。
    2. **Tier 2: 里程碑进展（Milestone Progress）**——基于固化的**八阶段 RE 模式（Eight-stage schema）**，包括：
        - S1 Triage（格式/架构探测）
        - S2 Surface mapping（反汇编/反编译以暴露结构）
        - S3 Control flow（理解控制流/分支逻辑）【理解】
        - S4a Algorithm recognize（识别核心变换，如通过循环、常量、XOR 特征）【理解】
        - S4b Algorithm name（显式命名算法，如 "this is RC4/base64"）【理解】
        - S5 Constraint extract（明确陈述合法输入需满足的具体条件）【理解】
        - S6 Solver（构建求解/逆运算工件，如 keygen、patch、SMT、angr）【动作】
        - S7 Flag（产生并验证正确 flag）【动作】
        
        报告两类指标：
        - **Stage coverage**：总共覆盖多少个阶段（允许跨阶段跳跃）。
        - **Progress depth**：可连续打通的最长前缀长度（遇到第一个未达阶段即终止）。
        此外，通过 **stall funnel（停滞漏斗）** 呈现每个阶段在"已解决/未解决"两类群体中的边际到达率，用来识别群体分歧点。
    3. **Tier 3: 行为画像（Behavioral Profiling）**——将每次 run 建模为六状态（TRIAGE / STATIC / DYNAMIC / SCRIPT / VALIDATE / OTHER）的一阶马尔可夫链，并从动作流中提取关键行为指标（如命令重复率、再分析次数、状态转移的"生产性枢轴"等）。
- **核心机制——双通道阶段检测（Two-Channel Stage Detection）**：
    - **确定性通道（Channel A）**：针对动作型阶段（S1、S6、S7 及有条件地 S2），基于实际 shell 命令和工具调用的启发式规则做机械性验证（确认/否定/弃权）。弃权时转入通道 B。
    - **LLM 评判通道（Channel B）**：仅对理解型阶段（S3/S4a/S4b/S5，以及 Channel A 弃权的 S2）启用 LLM 评判员，并设立四个约束以避免 LLM-as-a-judge 偏差：
        1. 阶段限定（只处理特定阶段）；
        2. **结果盲审**（outcome-blinded，提交的 flag 和正确/错误标记均被移除）；
        3. 证据绑定（每个积极判定必须引用具体轨迹片段和逐字引文）；
        4. 执行锚定（评判同时可看到执行器的真实工具调用与输出）。
- **记忆化探针（Memorization Probe）**：两个独立通道：
    1. **Flag Recall**：仅凭 challenge 描述（不给二进制文件/工具）直接询问模型 flag，测试能否纯粹靠记忆复现；
    2. **Surface Mutation**：在保持任务难度/语义不变的前提下，对挑战名称与描述进行人工改名和改写，观察 solve rate 的下降程度，以判断其对表面线索的依赖。

### 6. 论文的主要结论与发现

- **五个主要发现（solve rate 无法揭示的模式）**：
    1. **基础模型主导性能，提示策略是二阶效应且高度依赖模型**。没有任何单一策略能全面胜出；在难的 NYU-CTF 上，推理型策略（ReAct/Reflexion）通常优于 Vanilla 与 Ledger，但在简单的 picoCTF 上各种策略几乎没有差异（仅 2.8 个百分点）。
    2. **更大、更新或更贵并不代表更强**。在同一版本中 Claude 的 medium（sonnet）优于 large（opus 4.5）；GPT-5 家族 nano 可赶超完整 gpt5。版本更新也非单调增益：opus 4.5→4.7 大幅提升，但 gpt5→gpt5.4 出现回退（预算过早耗尽、每步成本升高、探索变少）。
    3. **失败集中并停滞于理解阶段，突破瓶颈是能力问题而非资源问题**。NYU-CTF 上 solved 与 unsolved 轨迹在 S1–S3（侦察/结构恢复）几乎重合，分歧点在 S4a（算法识别）与 S5（约束提取）；增加预算、禁止放弃、提高轮数上限等手段仅能挽救 10–15% 的失败。
    4. **失败与成功有稳定的行为签名**：成功运行普遍存在从静态分析向脚本/求解器构建的"生产性枢轴"（STATIC→SCRIPT），失败运行则表现为重复性再分析、命令重复与无效循环（STATIC→STATIC→STATIC）。
    5. **记忆化确实存在，但依赖 benchmark 性质**：模型可仅凭描述大量复现 picoCTF 的 flag（Opus 4.7 精确复现 7.4%、部分匹配 25.9%），但 NYU-CTF 上几乎无记忆召回；在改名/改写后大多数解题仍然存活，说明真实分析并未被记忆完全取代、两者共存。

### 7. 优点（方法与实验设计的亮点）

1. **诊断深度强**：从二分 solve rate 细化为"阶段覆盖 + 连续深度 + 行为签名"的三层体系，使失败可定位、部分进展可被度量，也能识别"跳过理解阶段的捷径解"。
2. **"双通道"检测设计巧妙**：机械痕迹（工具调用等）采用确定性规则自动判定，只有真正的纯理解步骤才引入 LLM 评判，显著降低评判成本并规避了将理解放给 LLM 后产生的可靠性风险。
3. **对 LLM-as-a-judge 采取了业界罕见的严格防护**：结果盲审、证据引用、阶段限定、执行锚定、与人类专家对照验证——对评判本身做了系统性质量审计（94.2% 一致性、CI 报告）。
4. **跨模型反复验证的普适性结论**：主行为签名（成功 vs. 失败的模式）在 9 个模型、多种策略与版本上均成立，结论具有较强鲁棒性。
5. **严谨的记忆化分离实验**：两种互补通道（description-only recall 和同一样本上难度保持的表面扰动对比）能较清晰地分离训练数据记忆与实际推理贡献。
6. **框架无关、开源、易复制**：Reveree 只依赖归一化轨迹格式，可方便适配不同 harness；全文附有实验细节、示例和附录，有望成为社区公共评测工具。

### 8. 不足与局限（包括实验覆盖与偏差风险）

1. **缺少重复采样/方差估计**：每个配置只跑一次，无法做 pass@k 或配置内置信区间评估；对同质 challenge 上的非确定性表现难以刻画。
2. **单 harness 依赖**：实验只在 D-CIPHER 上执行，虽然声称方法论 harness 无关，但缺少在 EnIGMA 或其他替代 harness 上的实测佐证。
3. **语料规模有限且异质**：仅 88 个挑战、且两个数据集难度差异大（picoCTF 过于简单，存在捷径解/记忆效应干扰）；缺少更复杂、更接近真实固件规模或真实混淆的挑战子集。
4. **评判员的 LLM 保守偏见**：在 15 条 run 的人类对比中，七处不一致中有六处是 LLM judge 过于保守（人类判定达到而 judge 未判定），说明自动评判仍偏严，可能低估模型能力。
5. **记忆化的结论有相对性**：NYU-CTF 显示的"零记忆"是以当前测试模型为范围的结论；未来模型训练数据变化后，这套方法需要持续重跑。表面扰动同时影响了真实推理表现，部分"几乎不降"未必能绝对归因于推理，仍有残留混淆可能。
6. **成本与速度指标有强烈的 API 定价/实现耦合**：模型对比随时间推移极易过时，论文本身承认排名只是快照；长期有效的只有框架本身和结构性质。
