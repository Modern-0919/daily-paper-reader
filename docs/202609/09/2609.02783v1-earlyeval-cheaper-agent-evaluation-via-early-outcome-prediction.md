## 摘要
对LLM智能体的评估对于指导其开发至关重要，但这一过程已变得昂贵得令人望而却步：对智能体基准进行一次前沿模型的评估可能需要花费数百至数千美元，并且这一成本在迭代开发周期中被反复支付。以往的工作主要集中于基准蒸馏，减少了评估任务的数量，但并未触及每个保留任务的执行成本。在这项工作中，我们引入了早期结果预测，这是效率的一个补充维度，转而削减每个任务内部的成本。我们的关键见解是，智能体的最终结果往往在执行完成之前就能从其中间行为中明显看出。我们将这一思想实例化为EarlyEval，这是一个轻量级框架，它基于行为、文本和参考解决方案特征训练一对LightGBM成功与失败分类器，并在任一分类器越过校准的置信阈值时立即终止智能体运行，从而引入可忽略不计的每步开销。在SWE-bench Verified、TerminalBench和Toolathlon这三个基准上，EarlyEval可以消除13%至26%的智能体步骤，并在89%至97%的预测准确率下，最多节省44.1%的输入令牌和29.4%的输出令牌，同时对单个智能体的解决率的扰动平均仅为一到两个百分点。

## Abstract
Evaluating LLM agents is essential for guiding their development, yet it has grown prohibitively expensive: a single pass of a frontier model over an agentic benchmark can cost hundreds to thousands of dollars, a price paid repeatedly across iterative development cycles. Prior efforts, centered on benchmark distillation, reduce the number of evaluation tasks but leave the cost of executing each retained task untouched. In this work, we introduce early outcome prediction, a complementary axis of efficiency that instead cuts cost within each task. Our key insight is that an agent's final outcome is often evident from its intermediate behavior well before execution completes. We instantiate this idea in EarlyEval, a lightweight framework that trains a pair of LightGBM success and failure classifiers over behavioral, textual, and reference-solution features, and halts an agent run the moment either classifier crosses a calibrated confidence threshold, adding negligible per-step overhead. Across three benchmarks, SWE-bench Verified, TerminalBench, and Toolathlon, EarlyEval can eliminate 13%-26% of agent steps and up to 44.1% input tokens and 29.4% output tokens at 89%-97% prediction accuracy, while perturbing per-agent resolve rates by only one to two percentage points on average.

## 1. 论文的核心问题与整体含义（研究动机和背景）

LLM Agent（智能体）评估是指导其迭代开发的核心工具，但评估成本已高到形成实质性资源门槛：

- **评估成本急剧膨胀**：以SWE-bench Verified为例，使用OpenHands框架对前沿模型单次完整评估需数百美元；更长的基准（如SWE-bench Multimodal）单次评估最高可达2,270美元。在典型开发周期中，团队会对多种提示词、脚手架与模型变体反复运行几十次评估，成本成倍累积。
- **已有降本路径不完整**：先前的“基准蒸馏”（benchmark distillation）方法（如Anchor Points、tinyBenchmarks等）专注于从基准中筛选代表性任务子集，**只减少任务数量，未削减每个保留任务的内部执行成本**，而执行保留任务所需的步骤和token开销依然高昂。
- **新的切角**：论文的核心洞见是——**在许多任务中，agent的最终成败在其自然执行完成之前，就已能从中间行为轨迹中被高度可靠地预判**。例如，当agent在SWE-bench任务中已正确应用了一行关键代码修改后，后续的反复测试已无法改变成功结局；反之，当agent面对相同错误信息不断重试相同编辑时，失败结局事实上早已注定。

基于这一观察，论文提出**早期结果预测（Early Outcome Prediction）**——一个与基准蒸馏正交的评估降本维度，在**单个任务内部**根据已观测轨迹提前判定结果并终止运行，从而同时节省步骤、输入token和输出token。

## 2. 论文提出的方法论

### 核心思想

EarlyEval以**逐前缀（prefix）分类**的方式构建预测器：给定一个agent在任务上的完整轨迹 τ = (e₁,…,e_T)，将其分解为前缀 τ:k = (e₁,…,e_k)（k=0,1,…,T），每个前缀标记最终二进制结果 y ∈ {0,1}。训练分类器后，对新的agent运行逐步监控，一旦分类器跨过置信阈值即以预测结果替代真实结果并提前终止执行；若两者都未达标，则允许运行继续直到自然完成。

### 方法流程的两阶段结构（见图2）

1. **阶段一（离线预测器构建）**：从基准基准上已有的历史评估数据中，对每个完整轨迹构造全部前缀，提取多模态特征向量 φ(τ:k) ∈ ℝᵈ，与最终标签配对训练两个独立的LightGBM分类器。
2. **阶段二（在线逐步推理）**：对每步已累积的轨迹提取特征向量 → 输入成功与失败分类器 → 输出置信度 p+ 和 p− → 经双阈值决策规则比较，触发停止则记录预测结果。

### 三族特征工程（表II）

| 特征族 | 内容 | 维度（组数） |
|---|---|---|
| **行为特征** | 活动计数（步数、工具调用、各类编辑/测试/git操作）、上一步结构、事件时间结构（编辑/测试/错误等的首次出现步与间隔）、工作模式（读编辑比、卡滞与重复信号、提交前是否测试）、错误与测试状态指示 | ~115维（5组） |
| **文本特征** | 任务提示的TF-IDF经SVD降至64维；完整动作历史与最近动作各降为128维；全部环境反馈与最近反馈各降为128维 | ~448维（5组） |
| **参考解特征**（仅当基准发布gold patch时启用） | gold补丁属性（规模、hunk数、文件数、测试数等）+ 前缀与gold解的结构重叠度（文件、API符号、测试名的Jaccard重叠与命中数） | ~82维（2组） |

无参考解基准（TerminalBench、Toolathlon）自动禁用参考解特征族，仅依赖行为和文本特征。

### 预测模型细节

- **双分类器架构**：成功预测器 h+（目标为y=1）与失败预测器 h−（目标为y=0）分离训练，允许正负证据独立积累，并显式形成一个“两低即模糊、继续运行”的置信区间。两者在同一特征向量上使用相同的LightGBM超参数配置（学习率0.03、31叶、最大深度6、行列抽样等），样本按1/(T+1)加权以使不同长度轨迹对目标函数的贡献相等。
- **概率校准**：使用Platt缩放（一维逻辑回归）将LightGBM原始得分映射为校准概率 p = σ(a·logit(s) + b)，使阈值跨分类器和跨验证折具一致语义。
- **双阈值决策规则**：设成功阈值 s 和失败阈值 f，若 p+ ≥ s 或 p− ≥ f，则在首次越线的步骤停止；若同一时刻双越线，以更早越过的一侧为准；均未到达则继续。阈值暴露了**精度—效率的旋钮**：高阈值→高准确率但少节省；低阈值→更多步骤削减但评分偏差更大。
- **防泄漏处理**：训练/验证按任务划分，同一轨迹的所有前缀严格保留在同一侧；并在评估时执行**留一agent（leave-one-agent-out）**协议，每次将一整组agent配置排除在训练集外。

## 6. 论文的主要结论与发现

- **RQ1**：在推荐的阈值设定下，EarlyEval在SWE-bench Verified（阈0.95）削减26.0%执行步骤、32.7%输入token和28.7%输出token，Δ|Pass@1|仅1.1个百分点；在Toolathlon（阈0.90）削减23.0%步骤、44.1%输入token和29.4%输出token，Δ|Pass@1|仅0.9个百分点；在TerminalBench的无同模型设定下（阈0.90）可达25.4%的步骤削减，Δ|Pass@1|为2.1个百分点。总体预测准确率为89%–97%。
- **成功率预测器与失败率预测器的效能不对称**：失败分类器在所有基准上精度都高（可达96.7%–99.4%），而成功分类器仅在SWE-bench可靠（88–94%）；在Toolathlon上成功分类器几乎从不触发。双机制的步骤削减近似等于两种单分类器削减的算术和（表明正负证据几乎不在同一轨迹上共现）。
- **Threshold单调性**：降低阈值从0.95到0.75可将SWE-bench节省从26%提升至63.4%，但Δ|Pass@1|从1.1%升至4.1%——提供明确精度—效率调节接口。
- **RQ2**：早期停止后的排名与完整排名高度一致——SWE-bench ρ=0.991（81%精确秩不变），Toolathlon ρ=0.994（70%不变），TerminalBench无同脚手架设定ρ=0.994（70%不变）；更困难的TerminalBench无同模型设定ρ=0.959（59%不变）。
- **RQ3**：行为特征族是早期停止的主要驱动力（移除后覆盖率从34.8%降至23.4%、步骤节省降至16.4%），但对应的预测信号在其内部各子组间冗余分布，单个子组移除后性能几乎不变。**完全去除参考解特征只带来轻微退化**（覆盖率降至32.1%），解释了为何EarlyEval可拓展至无金标准的基准。
- **RQ4**：LightGBM在覆盖率（34.8%）、准确率（95.0%）、步骤节省（26.0%）与最小评分偏差（1.1pp）四个维度上均优于MLP、两类逻辑回归与LoRA微调Qwen模型；只对原始TF-IDF做逻辑回归因覆盖率过低（2.4%）而无实际价值。
- **脚手架结构比模型更难泛化**：TerminalBench无同脚手架设定中，成功分类器峰值精度从82.7%降至69.0%，可获得的步骤节省从25.4%缩至17.7%——脚手架决定轨迹的行为节奏，是行为特征最大变异性来源。

## 7. 优点

1. **问题定位精准且与现有工作互补**：明确区分了“减少任务数量”与“减少任务内成本”两个正交轴，提出新降本范式而非替代蒸馏。
2. **代价极低、即插即用**：LightGBM在CPU上亚毫秒每次评估，每步开销可忽略；代码与数据公开发布（GitHub），便于复现和采纳。
3. **特征设计丰富而克制**：多模态特征覆盖行为、文本与参考解三类，文本经TF-IDF+SVD压缩至低维但保留较高信息带宽，保证语义边界与推理速度之间的平衡。
4. **防泄漏意识极强**：留一agent评估、按任务划分训练/验证、同一轨迹的前缀不跨划分，以及TerminalBench双向泄漏控制，在评估有效性上具备很强的可信度。
5. **评估体系完善**：不只看预测准确率，还看覆盖率、步骤/token削减与对下游排行榜排名（Spearman ρ与精确秩保持）的影响，从多维度衡量框架可用性。
6. **结论实用性强**：提供阈值调节的精度—效率旋钮，明确告知哪些情况下适合用EarlyEval（迭代开发提供快速信号），哪些情况不适合（最终官方benchmark score，应跑完整评估）。

## 8. 不足与局限

1. **依赖历史轨迹池**：需以目标基准上已有大量已标注轨迹为前提，对“全新、尚无任何run的基准”无能为力——论文对该适用范围的界定是诚实的，但实质上限制了早期评估的可迁移性。
2. **仅在离线设置验证，未考虑分布漂移**：模型能力快速更迭，来自旧agent的轨迹模式对新模型（尤其是能力显著更高的前沿模型）的可预测性可能退化。实验将所有agent留一，但仍在同一时间段收集的数据池内。
3. **特定agent架构泛化有限**：TerminalBench的“无同脚手架”实验表明，当测试agent在训练池中完全没有相同脚手架时，效能显著下降，在阈值较高时只能节省约1.3–17.7%的步骤，距实践可用的强节省尚有差距。
4. **成功分类器在部分基准上不可用**：Toolathlon场景下以0.85以上阈值几乎无成功轨迹可触发，提示该框架在两基准上主要依赖失败信号（即保守停止），牺牲部分期待中的正例节省潜力。
5. **报告偏重于平均数而非尾部风险**：对个别极长轨迹的极端高token削减、对个别估计偏差较大agents缺乏逐条case研究分析。
6. **与最终完整评估之间的偏差仍有系统性欠账**：在全部场景中early-stop会系统性地低估（负ΔPass@1），论文给出均值偏差范围但未讨论偏差如何随阈值和各agent内在成功率分布变化。
7. **架构对比不够全面**：未对比更新的树模型（如XGBoost、CatBoost）、非LightGBM集成方法或小型嵌入模型judge（非LLM）的可行性，基线覆盖面可再广。
