## 摘要
在软件工程中部署的LLM智能体会以高昂代价失败：它们会自信地犯错，而这种错误行为只有在成本高昂的执行和重试之后才会被发现。我们提出推测性不确定性（SU）方法，仅凭黑盒智能体的输出词元，无需访问logits、权重、激活或重复采样，即可获取其可预测的失败信号。通过逆向利用推测解码，一个轻量级开放权重草稿模型在单次前向传播中为智能体已生成的轨迹打分。我们从这些推测性交叉似然出发，通过分离推理片段和动作片段来提取阶段感知特征，并针对一个可验证的目标进行校准。SU生成一个失败可能性分数，可供路由、人工干预或额外的测试时算力等任何下游策略直接使用。为证明该信号具有实际效用，我们在软件工程智能体Qwen3-Coder-480B和闭源的Claude 3.5 Sonnet上实例化了其中一种策略——执行前否决门控，将部署中的执行错误率降低了6–8个百分点，token成本降低了14–19%，且无需重新训练即可迁移到分布外基准，并跨智能体模型进行泛化。

## Abstract
LLM agents deployed for software engineering fail expensively: they act confidently wrong, and bad actions are recognized only after costly execution and retry. We present Speculative Uncertainty (SU), a method that recovers a predictive failure signal for a black-box agent from its output tokens alone, with no access to logits, weights, activations, or repeated sampling. Inverting speculative decoding, a small open-weight draft model scores the agent's already-generated trajectory in a single forward pass. From these speculative cross-likelihoods we extract phase-aware features by separating the reasoning and action spans, and calibrate them against a verifiable objective. SU produces a failure-likelihood score that any downstream policy, such as routing, human intervention, or extra test-time compute, can consume directly. To show the signal is actionable, we instantiate one such policy, a pre-execution veto gate, on software engineering agents Qwen3-Coder-480B and closed-source Claude 3.5 Sonnet, cutting execution error rate by 6-8 percentage points and token cost by 14-19% in deployment, transferring to out-of-distribution benchmarks without retraining, and generalizing across agent models.

## 一、核心问题与研究动机

- **问题的严重性**：在软件工程场景中部署的 LLM 智能体经常以“自信但错误”的方式行动——它们在提出错误动作时毫无征兆，只有当环境抛出异常、代码运行失败、上下文被耗尽、重试成本已经付出之后，失败才被识别。在生产规模下，这种静默失败极大推高了 API 成本和延迟。
- **现实约束**：
  1. 最强力的已部署智能体通常是**闭源 API 服务模型**，不暴露 logits、权重或激活值，白盒方法无法使用；
  2. 基于采样的不确定性估计需要在每一步进行多次生成，在智能体长时程任务中成本不可承受。

  这两条约束排除了大多数传统不确定量化工具（如单轮校准、白盒探针、采样一致性等），催生了从**黑盒输出 token 中直接恢复失败信号**的需求。

## 二、方法论：Speculative Uncertainty（SU）

### 核心思想

- **反转推测解码**：传统推测解码用小模型生成 token 来加速大模型；SU 将其反转——小模型不生成，而是以“教师强制”（teacher-forcing）方式对智能体**已经产生的轨迹 token** 逐一代数打分，计算交叉似然。
- 智能体完全不需要暴露内部状态，草稿模型只读取其文本输出，单次前向即可恢复丰富的不确定性信号。

### 关键技术细节

**1. 推测性交叉似然信号**

对于轨迹中每个 token \( y_t \)，草稿模型 \( q \) 在给定前缀条件下输出三个信号：

- \( s_t = -\log q(y_t | x, y_{<t}) \)：**推测性惊异度**（speculative surprisal）
- \( g_t = \log q(\hat{y}_t | x, y_{<t}) - \log q(y_t | x, y_{<t}) \)：**推测性差距**（speculative gap），其中 \( \hat{y}_t \) 是草稿模型的最优 token
- \( H_t = -\sum_{v \in V} q(v | x, y_{<t}) \log q(v | x, y_{<t}) \)：**推测性熵**（speculative entropy）

**为什么黑盒代理有效**：在推测解码中，token 被接受的概率为 \( \alpha_t = \min(1, p(y_t|\cdot)/q(y_t|\cdot)) \)。当 \( q \) 与 \( p \) 足够对齐时，高推测惊异度意味着 \( p \) 在该点的接受率也低，因此 \( s_t \) 可以作为 \( p \) 自身不确定性的可用替代信号。

**2. 阶段感知特征提取**

- 观察到智能体轨迹存在**阶段结构**：高熵的“推理阶段”之后是语法和工具调用约束下熵显著降低的“行动阶段”。
- 整体平均（如 HTC 的做法）会把行动阶段的失败相关信号淹没在推理阶段的噪声中。
- SU 将推理与行动 span **分开统计**，对每个阶段 × 每种信号计算 8 种统计量（均值、方差、最大、最小、偏度、趋势、前/后 10% token 均值），加上两个 span 长度，构成 **50 维特征向量**。

**3. 校准器与下游策略**

- 使用 ℓ1 正则化的逻辑回归将特征映射为校准的成功概率 \( \hat{y} = F^*(φ(W_i)) \in [0,1] \)。
- **否决门策略（Veto Gate）**：当预测失败概率较高（即成功概率低于阈值 τ）时，在执行前阻断该动作，触发一次更便宜的重规划（replan），而不是“执行→失败→重试”的高昂循环。

### 对比方法

- **Verbalized Confidence**：智能体自述的置信度
- **Last-TP / Global-TP**：最后一块/全轨迹的平均对数概率（需要白盒 logits）
- **HTC (Holistic Trajectory Calibration)**：基于智能体自身 log-probability 的轨迹级校准器
- **SU-Uniform**：消融版本，不区分阶段直接混合特征
- **SU（无训练）**：未对齐的草稿模型（消融）

### 评估指标

- 判别力：AUROC、P@R80
- 校准质量：ECE、MCE、Brier 分数、NLL、BSS
- 部署影响：错误率变化（pp）、token 成本变化、真/假否决率、任务成功率

### 充分性判断

## 六、主要结论与发现

1. **黑盒失败信号可恢复**：通过对齐的小型草稿模型，仅从智能体输出 token 即可获得接近白盒 HTC 的失败预测能力（SWE-Bench Verified AUROC 从 Verbalized Confidence 的 .57 提升至 .77，接近 HTC 的 .82）。
2. **草稿对齐至关重要**：未对齐的草稿模型几乎无效（.61 AUROC），对目标智能体轨迹进行蒸馏后显著改善（.77）；但 SFT 和 TF 蒸馏两种目标的效果差异很小（相差仅 1 个点）。
3. **阶段分离带来显著收益**：分开提取推理/行动阶段特征比混合提取高 5–6 AUROC。
4. **部署价值在于成本与错误减少，而非任务成功率提升**：
   - 执行错误率降低 6–8 个百分点（SWE-Bench Verified：21%→15%；DA-Code：14%→6%）；
   - Token 成本降低 14–19%；
   - 但任务成功率几乎不变或轻微下降（49%→44%，64%→63%）——因为否决门将执行-失败-重试循环替换为更便宜的重规划，但重规划并不保证能恢复任务。
5. **跨智能体迁移可行**：在开放权重 Qwen 语料上训练的草稿迁移到闭源 Claude 3.5 Sonnet 时仍显著优于基线（.69 vs. .60 AUROC），且接近混合语料训练效果（.75）。

## 七、优点与亮点

1. **方法优雅且适用于现实约束**：逆向推测解码是一个概念简洁但非常巧妙的思路——利用现成的“小模型评分大模型”机制，绕过了黑盒访问限制和采样成本，恰好命中生产环境的两大刚需。
2. **阶段感知特征提取有充分的实证基础**：附录 A 的熵分析清晰地展示了推理/行动阶段的熵差异及其与失败信号的反向关联，为方法的核心设计提供了理论支撑而非凭直觉。
3. **彻底的黑盒兼容性**：推理时仅需输出 token，无需智能体的任何内部信号；即使草稿训练需要目标智能体输出，论文证明了可以在开放权重代理模型上蒸馏后迁移到闭源模型。
4. **部署导向清晰**：除给出概率分数外，还实现并评估了具体下游策略（否决门），量化了实用收益（错误率与 token 成本）；同时明确指出该策略只是框架的一种消费方式，框架本身与下游策略解耦。
5. **校准器可审计**：线性模型 + ℓ1 正则化，50 个特征中有稀疏可检查的子集被选中，便于审计和部署。
6. **诚实的边界讨论**：明确承认否决门降低任务成功率的事实（因结构原因），没有夸大方法的收益范围。

## 八、不足与局限

1. **单一目标与领域验证**：所有实验都集中在代码执行成功与否这一目标上。虽然框架理论上适用于其他可验证目标场景（如 SQL agent、web agent），但缺少定量证据。
2. **统计稳健性不足**：单次运行、无种子方差、无显著性检验——这意味着结论中的小幅差异（如 .76 vs .77 的 AUROC 差异）可能不具备统计意义，读者需谨慎解读。
3. **任务成功率轻微下降**：否决门以牺牲少量任务成功率为代价换取错误率和成本的大幅降低。在许多应用场景中，任务成功率可能是更重要的指标，这种 trade-off 在具体产品决策中需仔细权衡。
4. **草稿成本假设依赖场景**：论文假设 4B 草稿的每步开销≈100ms 可忽略不计；但若目标任务需要更大草稿模型才能获得可用的信号，成本平衡将被打破。该假设并非普遍适用。
5. **框架适用范围不确定**：需要轨迹中具有可识别的推理/行动阶段结构，且必须存在外部二元 oracle。并非所有智能体任务都满足这些前提（例如自由对话式 agent 或没有明确执行反馈的任务）。
6. **校准缺口**：SU 的输出存在残余误校准（ECE 高于恒定基线）；作者建议在使用概率值本身的下游策略中需先行再校准（如温度缩放或保序回归），但未在本文内完成这一步骤。
7. **对种子和框架的依赖未被探索**：训练/测试均只使用 OpenHands 框架生成轨迹，不同的 agent 框架可能改变推理-行动阶段结构，从而影响方法效果。
