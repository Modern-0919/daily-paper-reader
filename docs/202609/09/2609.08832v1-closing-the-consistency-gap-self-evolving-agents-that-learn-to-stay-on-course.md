## 摘要
由大型语言模型（LLM）驱动的智能体在平均水平上可能表现准确，但在实际生产中却不可靠，这种差异虽已被观察到，但在很大程度上仍未得到解决。当同一任务被重复执行五次时，使用 GPT-4.1 的 ReAct 智能体在 AppWorld 基准上五次全部成功的概率仅为 53%，尽管其单次运行的平均通过率为 77%。我们将这 24 个百分点的差距称为一致性差距，并认为解决这一问题是可信 AI 智能体部署的先决条件。我们提出了一种自我进化的智能体框架，通过识别智能体轨迹中不稳定的、低一致性的步骤，并将其转化为智能体在后续运行中可以利用的情景记忆来缩小这一差距。其核心是一个一致性分析器，用于精确定位轨迹在多次执行中可能发生翻转的位置和原因；以及一个指导生成器，将诊断结果转化为有针对性的指导方针，存储到记忆中，并在未来处理类似任务时注入智能体的执行过程。在使用 ReAct/GPT-4.1 的 AppWorld 上，我们的框架在相同任务评估中将五次全部成功的任务比例提高了 16 个百分点，在相似任务泛化中提高了 13 个百分点。

## Abstract
Large language model (LLM)-powered agents can be accurate on average yet unreliable in production, a discrepancy that has been observed but remains largely unaddressed. When given the same task five times, a ReAct agent on the AppWorld benchmark using GPT-4.1 succeeds in all five runs only 53% of the time, even though its per-run pass rate averages 77%. We call this 24-point shortfall the consistency gap, and we argue that addressing it is a precondition for trustworthy AI agent deployment. We present a self-evolving agent framework that reduces this gap by identifying unstable, low-consistency steps in agent trajectories and converting them into episodic memory the agent can draw on in future runs. At its core is a Consistency Analyzer that pinpoints where and why a trajectory is likely to flip across executions, and a Guideline Generator that converts the diagnosis into targeted guidelines, committed to memory and injected into future agent executions on similar tasks. On AppWorld with ReAct/GPT-4.1, our framework raises the fraction of tasks that succeed in all five runs by +16 points on same-task evaluation and +13 points on similar-task generalization.

### 1. 论文的核心问题与整体含义

论文聚焦于 **LLM 智能体在生产环境中的"一致性差距"（Consistency Gap）** 问题。其核心论点是：

- **背景与动机**：现有 LLM 智能体虽然"平均准确率"表现良好，但在重复执行同一任务时，结果往往不稳定，这种波动性被现有的基准测试指标（如平均通过率）所掩盖。作者认为，这种不一致性是阻碍智能体在生产环境获得信任与可靠性的关键前提性问题。
- **核心发现**：在 AppWorld 基准上，ReAct/GPT-4.1 智能体的单次平均通过率（Mean@5）高达 77.4%，但同一任务连续运行五次全部通过的比率（Pass@5的全对变体 Pass^5）仅为 53.0%，两者存在 24.4 个百分点的巨大落差。
- **研究意义**：该问题并非个别模型独有的偶然现象，而是一个系统性顽疾。它意味着，即使模型拥有很强的单次求解能力，其输出在真实部署中也可能反复横跳，导致用户难以信任其交付结果的稳定性。论文提出了一套自我进化框架来主动识别并弥合这一差距。

### 2. 方法论：核心思想、技术细节与流程

该框架的核心思想是**将"不稳定的低一致性步骤"转化为可复用的提示级指导（Guideline）**，以情景记忆的形式注入未来类似任务的执行中。整个流程由两个阶段构成，形成了一个"分析 → 学习 → 应用"的自我进化闭环。

- **总体架构：检测与生成的两级管道（Pipeline）**
  - 阶段一（Detect，检测）：由 **一致性分析器（Consistency Analyzer）** 采用**黑盒（Black-box）方式**对轨迹中的每一步进行"风险诊断"。它通过重采样（Resampling）同一提示，估算每一步骤输出结果的"分布形态"（即平坦度），从而精确定位出那些容易在多次执行中发生翻转（Flip）的不稳定步骤，生成**逐步与轨迹级的一致性评分卡（Scorecard）**。该方法不依赖模型内部 logits 或智能体源代码，因此适用于任何基于托管 LLM 端点的智能体。
  - 阶段二（Generate，生成）：由 **指南生成器（Guideline Generator）** 基于分析器输出的不稳定步骤诊断，调用 LLM 生成**针对性的自然语言一致性指南（Consistency Guideline）**，例如策略（strategy）、恢复（recovery）、优化（optimization）等类别，以稳定该决策点。这些指南随后被提交到情景记忆系统中存储。
  - **闭环反馈**：运行时通过**余弦相似度检索**（Cosine Similarity）注入到后续相似任务的提示中。该框架构建在已有的轨迹记忆框架之上，存储则采用"嵌入 + 分类/优先级/上下文/来源元数据"的双索引机制。

- **关键技术细节（一致性分析器）**
  - **为何贪婪解码（Greedy Decoding）不够**：即使在温度为零的贪婪解码下，由于平台端浮点运算、批处理或分词器状态引入的噪声，一个平坦的 Token 概率分布也会让"次优 Token"翻转成"最优 Token"。因此，问题不能仅靠解码策略解决，而需要通过**重采样**来估计分布形态。
  - **逐步一致性评分（Step Consistency）**：对每个推理步的提示执行 N 次重采样（N=30，温度 0.5），得到响应集合同，基于响应类型计算分数 `C(si)`：
    - **文本/代码响应**：采用平均两两 SBERT 嵌入余弦相似度，语义相近则视为一致。
    - **类别/离散响应**（如工具名、枚举参数）：采用平均两两 Jaccard 相似度，严格惩罚 Token 级不匹配。
    - **半结构化响应**（如 JSON）：分字段按上述原始类型评分，进行加权求和。
  - **轨迹一致性聚合（Trajectory Consistency Score）**：通过取所有步骤分数的**平均值** `C_mean(T)` 作为轨迹级分数，该指标被证明能有效预测轨迹成败（AUROC≈0.69）。

### 3. 实验设计：数据集、场景与基准方法

- **基准（Benchmark）**：完全基于 **AppWorld**（Trivedi et al. 2024）的**测试正常划分（test normal split）**，共 168 个任务。AppWorld 是一个交互式编码智能体基准，智能体需通过 Python 工具调用来操作模拟的个人应用程序环境。
- **模型与智能体架构**：采用 **ReAct**（Yao et al. 2023）智能体，分别搭配两种不同能力的底层 LLM：
  - **GPT-4.1**（部署于 Microsoft Azure）
  - **GPT-OSS-120B**（部署于 AWS）
- **对比方法**：实验主要是**自我消融对比**，即没有与多种外部方法进行横向对比，而是将框架应用前后的性能进行对比：
  - **Baseline**：未注入任何指南的原始 ReAct 智能体（5 次运行结果）。
  - **同任务评估（Same-Task）**：使用从任务自身轨迹生成的指南注入后再次评估。
  - **相似任务泛化（Similar-Task）**：利用 AppWorld 内置的任务分场景特性（每个场景有 3 个变体），从任务 v1 生成指南，但将其注入 v2 和 v3 的运行中去评估，这形成了一种跨任务泛化的评估设计。

### 6. 论文的主要结论与发现

1. **一致性差距客观存在且不可忽视**：模型的平均准确度严重高估了其在实际部署中的可靠性，同一任务重复执行时成功率远低于单次成功率。
2. **框架能大幅缩小差距**：该自我进化框架（自进化智能体）在 AppWorld 的 168 个任务上，将为 GPT-4.1 驱动的 ReAct 智能体的全五次通过率（Pass^5）在**同任务评估中提升 16 个百分点**（53%→69%），在**相似任务泛化上提升 13 个百分点**，且**没有以牺牲平均准确率（Mean@5）为代价**。
3. **有效性不依赖模型强能力**：在与能力较弱的 GPT-OSS-120B 结合时，虽绝对提升有限，但**相对 Pass^5 提升高达 59%**，说明框架能有效提取可用的改进空间。
4. **轨迹级一致性可作为无监督打分代理**：轨迹一致性得分与任务成败显著相关（AUROC≈0.69），这在缺少硬标签的生产环境中意义重大。

### 7. 优点：方法或实验设计上的亮点

- **首次将"一致性"提升为与"准确率"并列的一级目标**：定义了明确的指标数学形式（Pass^5 vs Mean^5），将主观可靠性量化。
- **黑盒友好，具有高度工程可用性**：不需要访问模型内部结构或改动推理循环，仅通过提示级操作和线下分析，架构普适性强。
- **精妙的"表面变量"研究视角**：将一致性差距归因于模型思维底层 Token 分布的"平坦性"，且针对半结构响应提出的加权分解评分是实用的工程创新。
- **构建了可靠的因果闭环**：清晰的"诊断→处方→验证"逻辑链条，即识别高风险步骤（一致性差）并提取对应建议（指南），逻辑扎实。
- **泛化性实验设计严谨**：利用任务变体开展验证，排除了学习到的过往经验仅是死记硬背的可能，证明了其真正学到了可迁移的策略。

### 8. 不足与局限：实验覆盖、偏差风险与应用限制

- **计算成本过高**：为诊断步骤而进行 N 次重采样，会带来约 **30 倍的单次轨迹 Token 成本开销**。虽然论文将降低此成本列为未来工作，但高额的边际成本限制了其在大规模、低延迟生产流程中的即时可部署性。
- **分析器非"真值验证器"**：一致性分析器衡量的是**稳定性**而非**正确性**。换言之，若模型每次都用同一种错误的思维或行为（如调用错误的 API），分析器会错误地认为该步骤"高度一致"，从而无法识别这种隐藏的、稳定的错误模式。
- **平台端不可控偏差**：论文承认对 Baseline 和注入指南后测试所面临的"平台侧非确定性"无法完全测量与控制，这可能会在对比实验里引入微小的系统性噪声，意味着对比结果可能存在潜在偏差。
- **任务域覆盖较窄**：尽管在 AppWorld 上效果显著，但实验仅在单一的 ReAct 架构与两家云端模型（GPT-4.1 和 GPT-OSS）上运行，缺乏跨不同智能体架构（泛化性）的验证，论文也承认了尚未量化其他架构与模型族的一致性差距。
