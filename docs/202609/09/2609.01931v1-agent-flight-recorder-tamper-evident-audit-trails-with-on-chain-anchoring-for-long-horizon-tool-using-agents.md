## 摘要
长时程智能体会执行数千个动作，导致的是序列性故障而非孤立错误。当一个编码智能体删除了生产数据库，或一次提示注入在智能体间扩散时，事件会引发关于因果性、权限和不可抵赖的第三方验证问题。智能体飞行记录器将每个智能体动作捕获为结构化、规范化序列化的事件，结合了从意图到执行再到来源的八个语义字段。哈希链和Merkle批处理提供了防篡改证据和紧凑的包含证明。对于任何一方的基础设施都不适合作为中立地点的跨组织争议，周期性的链上锚定纪元根使得任何验证者都能独立地根据公开的负载和Merkle证明检查记录，而无需预先商定可信中介。链上足迹极小：每个锚定存储一个32字节的纪元根和一个反向指针，且没有任何事件内容上链。我们在五种累积消融配置上对合成智能体工作负载进行了系统评估。完整系统为每个事件增加了约48微秒的中位延迟和512字节的开销。在100事件纪元下，L2锚定成本为每10万事件2.30美元。完整的完整性堆栈对删除、编辑、重排和分叉篡改的检测率为100%，零误报。结构化取证查询在护栏和委托查询上达到了1.0的精确度，而非结构化文本搜索的精确度分别为0.013和0.077。

## Abstract
Long-horizon agents execute thousands of actions, resulting in sequential failures rather than isolated errors. When a coding agent deletes a production database or a prompt injection spreads across agents, the incident raises questions of causality, authority, and non-repudiable third-party verification. The Agent Flight Recorder captures each agent action as a structured, canonically serialized event binding eight semantic fields from intent through execution to provenance. Hash chaining and Merkle batching provide tamper evidence and compact inclusion proofs. For cross-organizational disputes where no party's infrastructure qualifies as neutral ground, periodic on-chain anchoring of epoch roots lets any verifier with the disclosed payload and Merkle proof check the record independently, without pre-agreeing on a trusted intermediary. The on-chain footprint is minimal: each anchor stores a 32-byte epoch root and a back-pointer, and no event content touches the chain. We evaluate the system across five cumulative ablation configurations on synthetic agent workloads. The full system adds ~48 microseconds median per-event latency and 512 bytes per event. L2 anchoring costs $2.30 per 100K events at 100-event epochs. The full integrity stack detects edit, delete, reorder, and fork tampering at 100% with zero false positives. Structured forensic queries achieve 1.0 precision on guardrail and delegation lookups where unstructured text search yields 0.013 and 0.077 respectively.

### 2. 方法论：核心思想、关键技术细节与算法流程

**核心思想**：将智能体的每个动作捕获为一个包含八个语义字段的结构化事件，通过哈希链 + Merkle 批处理 + 纪元根链 + 链上锚定的层次化构造，实现防篡改、可验证、可选择性披露的审计轨迹。

#### （1）八语义字段事件模型

每个事件捕获一次智能体动作从意图到执行的完整链路：

| 字段 | 内容 |
|---|---|
| 1. Intent | 模型提议的动作（工具名与结构化参数），**不包括**思维链/推理过程（因不稳定、涉 IP 与隐私） |
| 2. Policy evaluation | 护栏规则评估结果（放行/拒绝/升级）及规则版本 |
| 3. Human approval | 人工审批人身份、审批提示、时间戳（建议附带加密签名） |
| 4. Execution | 实际运行的命令、API 调用或变更，含精确参数 |
| 5. Effects | 返回值、状态差异、外部响应或错误等可见结果 |
| 6. Context provenance | 上下文来源（检索文档哈希、上游工具输出、运行环境标识） |
| 7. Code provenance | 智能体二进制版本、工具封装哈希、技能包哈希 |
| 8. Delegation provenance | 多智能体场景中的请求方身份、父事件哈希、授权范围 |

#### （2）关键序列化与事件记录分离

- 使用**确定性 CBOR**（RFC 8949 §4.2）规范序列化，规避 JSON 规范化中的浮点数歧义、键序不定与 Unicode 归一化差异，保证跨系统哈希一致。
- 将**事件负载**（敏感内容，可加密）与**事件记录**（固定大小元数据：事件 ID、序列号、负载哈希、前驱摘要、工具名等）分离。所有完整性结构（哈希链、Merkle 树、纪元根）仅操作不含敏感内容的记录，通过负载哈希绑定内容。

#### （3）三层密码学构造

- **第 1 层——哈希链**：每条记录含前驱哈希 `eᵢ.prev = H(eᵢ₋₁)`，建立全序并支持截断检测。单调计数器 + 并发组标签区分因果顺序与观测顺序。
- **第 2 层——Merkle 批处理**：每 N 个事件构成 Merkle 树叶子，提供 O(log N) 包含证明。
- **纪元根链**：每个纪元产生 Merkle 根 Mₜ，链接上一纪元根形成链：

  > Rₜ = H(Mₜ ‖ Rₜ₋₁)

  仅 Rₜ 上链。纪元根链实现**缺口检测**：删除整个纪元会破坏后继纪元反向指针。

- **第 3 层——链上锚定**：周期性将 32 字节纪元根与反向指针提交至区块链（智能合约仅存根与回指，无任何事件内容上链）。合约记录 `msg.sender`（智能体身份）、纪元号与区块时间。

#### （4）双工作流验证协议

- **完整性验证**（不需内容）：给定事件记录 + Merkle 证明 + 链上锚点引用，验证者重算 Merkle 路径至纪元根、核对锚点匹配、确认纪元连续性。不揭示事件内容。
- **内容验证**（伴随披露）：操作者披露单事件解密密钥后，审计者解密载荷、验证其哈希与已提交记录一致，再执行上述完整性验证。
- 两种流程均**非交互**，无需质疑窗口或挑战期。

#### （5）选择性披露机制

- 采用基于 **HKDF** 的两级密钥层级：
  > Kₜ = HKDF(master, epoch_idₜ)，kₜ,ᵢ = HKDF(Kₜ, event_idᵢ)
- 审计者可仅获授权调查的个别事件的解密密钥，无法推导其他事件密钥。弱点在于若被强制披露纪元密钥 Kₜ，则该纪元内所有事件密钥均可推导。

#### （6）锚定机制的系统比较

论文构建了五维对比框架（信任假设、成本、预协议要求、可验证者、能否在操作者故障后存续），评估无锚定、签名摘要、透明度日志、TSA 与链上锚定。

### 6. 主要结论与发现

#### （1）性能开销极低（RQ1）

- 全系统（Full）每事件中位延迟为 **47.6 μs**，与哈希链配置（48.2 μs）相当。由于签名仅在纪元边界发生（1% 事件），中位数成本几乎不受影响。
- Schema 层（CBOR）快于 JSON 基线（6.0 vs 20.3 μs），但字节数更大（476 vs 272）。
- Merkle 在每第 100 个事件处触发纪元密封，P99 升至 ~4.1 ms；Full 配置锚定签名致 P99 达 ~30 ms（本地预备成本，生产环境异步提交）。
- 存储开销从 272 字节/事件增至 512 字节/事件（+88%）。
- 真实 SWE-agent 轨迹确认了该相对开销模式。

#### （2）链上锚定成本极低（RQ2）

- 实测 Base Sepolia 平均 gas/笔 ≈ 91,800。
- **L2 锚定每 10 万事件仅 $2.30**（100 事件纪元），较 L1 便宜约 3000 倍。
- 纪元大小与妥协窗口直接相关：10 秒窗口（纪元=10）在 L2 上也仅需 $22.95/100K 事件，使亚分钟级窗口实际可行。

#### （3）篡改检测全面覆盖（RQ3）

| 攻击 | Baseline | Schema | Chain | Merkle | Full |
|---|---|---|---|---|---|
| 编辑 | 0% | 0% | 90% | 100% | 100% |
| 删除 | 0% | 0% | 90% | 100% | 100% |
| 重排 | 0% | 0% | 100% | 100% | 100% |
| 分叉/双历史 | 0% | 0% | 0% | 0% | 100% |

- **零误报**。哈希链层漏检的是日志末尾事件（N−1，无后继可查）；Merkle 层弥补了这一终端盲区。分叉检测仅能由链上锚定层解决（对比锚定根的不匹配）。

#### （4）取证查询显著更优（RQ4）

- 结构化查询在护栏评估与委托查询上精确度均为 **1.0**，而文本 grep 分别为 **0.013** 与 **0.077**（因关键词命中大量无关事件）。
- Schema 实现精确字段定位（如 `policy_eval.rule == "destructive_command_check"`），并可通过委托父指针完成关系型因果链跟踪。
- 结构化搜索能重建完整因果链（哈希链指针），而 grep 无法做到。
- 全链上锚定是唯一能够**跨组织中立第三方验证**的配置——无需信任任何一方密钥或日志服务器。

### 8. 不足与局限

#### （1）实验层面的局限

- **合成数据为主**：除了 38 个事件的真实 SWE-agent 验证与 100 笔链上交易外，主要评估完全基于合成数据。对超复杂、多模态智能体工作流的推广有限。
- **基线过于简化**：Baseline 为普通 JSON 日志，未与成熟的审计系统（CloudTrail、签名摘要文件、TSA）做头部对比，对替代方案的相对优势缺乏直接经验证据。
- **单次运行与实验者偏差**：RQ3/RQ4 为单次确定性运行；取证查询由作者构造，无独立事故响应者的评测。
- **成本估算情境化**：gas 价格假设立场强，美元数字仅具参考价值。

#### （2）安全与应用层面的固有局限

- **不完整性**：若动作绕过仪器化网关，记录器不可见；纪元内事件抑制无法从日志本身检测——这是软件审计的基本边界。TEE 远程证明可缓解但非绝对。
- **妥协后不可信**：完全主机妥协后新写入条目无法保证真实（Schneier-Kelsey 边界）。事后完整性保证仅限于妥协前的历史。
- **数据可用性分离**：链上锚定只保证"承诺存在"，并不保证负载/证明/解密密钥可独立获取；数据可用性仍需链下存放安排。
- **密钥推导弱点**：若审计者获得纪元密钥（如传票），可推导该纪元内全部事件密钥；零知识蕴含证明留作未来工作。
- **锚定可用性**：链不可用则妥协窗口扩大；L2 单排序器存在审查风险（force-inclusion 可缓解）；操作者也可战略延迟锚定，需外部监视器。
- **侧信道盲点**：只捕获工具调用语义，不覆盖模型内部状态或频带外通信。
- **选择性遗忘的合规性**：密码学擦除需销毁纪元密钥材料；是否满足 GDPR 取决于司法辖区与元数据关联性，论文明确不作法律充分性声称。
