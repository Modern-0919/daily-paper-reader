## 摘要
长期任务网络智能体往往在最终失败之前就已偏离轨道：即使当前状态、重用技能或计划假设不再支持用户指令，轨迹在局部上仍可能看似合理。现有智能体能够进行规划、反思或复用经验，但其规划很少明确指定在何种证据下应继续信任当前步骤。我们提出FCPAgent，一种用于鲁棒长期任务网络智能体的可证伪承诺规划框架。FCPAgent将每个计划步骤表示为一个可证伪承诺单元（FCU）：一个基于可重用技能的子目标，连同确认性证据、证伪证据及置信度分数。执行被组织为计划-测试-修复循环。混合承诺测试模块在候选动作修改浏览器前对其进行检查，并在执行后观察结果；为提高效率，它结合了轻量级证据匹配与基于LLM的诊断验证。当证据证伪一项承诺时，范围感知修复将矛盾定位至执行、技能或规划层面，并修正最小的适当部分。在WebArena上，FCPAgent的平均成功率相比最强基线提升了13.8%，尤其在长期任务上增益显著。

## Abstract
Long-horizon web agents often go off track before final failure: a trajectory can remain locally plausible even after the current state, reused skill, or plan assumption no longer supports the user instruction. Existing agents can plan, reflect, or reuse experience, but their plans rarely specify the evidence under which an active step should still be trusted. We propose FCPAgent, a falsifiable commitment planning framework for robust long-horizon web agents. FCPAgent represents each plan step as a Falsifiable Commitment Unit (FCU): a subgoal grounded in a reusable skill, together with confirming evidence, falsifying evidence, and a confidence score. Execution is organized as a plan-test-repair loop. The hybrid commitment testing module checks candidate actions before they modify the browser and checks observations after execution; for efficiency, it combines lightweight evidence matching with LLM-based diagnostic verification. When evidence falsifies a commitment, scope-aware repair localizes the contradiction to the execution, skill, or planning level and revises the smallest adequate part. On WebArena, FCPAgent achieves a 13.8% relative improvement in average success over the strongest baseline, with especially large gains on long-horizon tasks.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长周期（long-horizon）网络智能体在最终失败前往往已偏离轨道（off-track execution）。即使当前状态、重用技能或计划假设不再支持用户指令，轨迹在局部上仍可能看似合理，导致智能体在错误路径上持续消耗步骤直至任务失败。
- **背景**：现有LLM/VLM-based web agent可进行规划、反思、复用经验（如ReAct、Reflexion、WebDART、ColorBrowserAgent等），但其计划通常被当作“可执行配方”，而非“可测试对象”。缺乏运行时有效性判据，使智能体在计划失效后仍盲目执行。
- **动机**：借鉴认知心理学中的Test-Operate-Test-Exit (TOTE) 模型，主张应把每个计划步骤视为“可证伪承诺”（falsifiable commitment），即包含明确的预期证据和失效条件，通过在线测试判断承诺是否仍成立，从而在最终失败前及时修正。

## 2. 方法论：核心思想、关键技术细节

### 2.1 形式化定义
- **可证伪承诺单元 (Falsifiable Commitment Unit, FCU)**：每个计划步骤表示为元组 \(c_i = (g_i, s_i, E^+_i, E^-_i, \kappa_i)\)，其中：
  - \(g_i\)：子目标
  - \(s_i\)：可选链接的可重用技能
  - \(E^+_i\)：确认性证据（stage-wise：前置条件、进展、完成）
  - \(E^-_i\)：证伪证据（hierarchical：执行级、技能级、规划级）
  - \(\kappa_i\)：承诺置信度（用于调整测试路由阈值）

### 2.2 框架流程：计划–测试–修复循环
1. **Falsifiable Commitment Generation（可证伪承诺生成）**：
   - 从训练轨迹离线构建技能库\(\mathcal{S}\)和失败-修复库\(\mathcal{F}\)。
   - 测试时，根据查询\(q\)和初始状态\(o_0\)检索相关技能和失败记忆，生成FCU序列\(C = (c_1, ..., c_m)\)。技能提供过程性先验，失败记忆帮助编码已知风险作为证伪证据。

2. **Runtime Commitment Testing（运行时承诺测试）**：
   - **混合测试**：轻量级快速测试 + LLM慢速诊断。
   - **快速测试**：使用预训练模型（NLI: nli-deberta-v3-base + 图像文本匹配: SigLIP2）计算\(\alpha^+_t\)（确认得分）和\(\alpha^-_t\)（证伪得分）。规则检测明显异常（如浏览器错误、未改变状态等）。根据得分和置信度路由：
     - `continue`：跳过慢速测试
     - `complete`、`risk`、`verify`：路由至慢速测试
   - **慢速测试**：LLM检查任务、当前FCU、近期轨迹及路由信号，返回`continue`、`advance`或`repair`，并附带诊断\(u_t\)（指出违规层级）。
   - **动作级测试**：在动作执行前进行类似检查，预防性识别高风险动作。

3. **Repairing Falsified Commitments（承诺修复）**：
   - **范围感知修复**：根据诊断的违规层级选择最小范围修改：
     - 执行级：保持FCU不变，修正即时动作或路径
     - 技能级：保留子目标，替换技能并更新证据
     - 规划级：重写当前及后续FCU
     - 严重漂移：回退至已知安全状态再恢复。
   - 故障库检索提供软引导，但不覆盖当前状态。
   - 修复后重返计划–测试–修复循环。

4. **经验蒸馏**：成功轨迹→技能库；失败/修复轨迹→失败-修复库，用于未来任务。

## 7. 优点

- **方法创新性**：首次将“可证伪承诺”概念引入web agent规划，把计划步骤提升为运行时可验证假设，提供明确的测试接口。
- **完整框架**：从证据生成、混合测试到范围感知修复形成闭环，且经验库可积累（既有成功也有失败）。
- **效率设计**：混合测试通过轻量匹配过滤大部分常规状态，仅对关键、模糊或完成时调用LLM，减少不必要的开销。
- **适应多种失效模式**：证伪证据分执行/技能/规划层级，修复机制据此选择最小修正，避免过度重规划。
- **广泛实验**：覆盖多域、零样本、长任务、消融、效率、人工评估、运行时诊断，论证充分。

## 8. 不足与局限
