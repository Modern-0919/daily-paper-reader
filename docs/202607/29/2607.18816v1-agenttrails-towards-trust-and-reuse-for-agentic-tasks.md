## 摘要
基于大语言模型的智能体通过调用工具、查询数据库、执行代码以及操控中间产物，日益处理复杂任务。这些智能体遵循的轨迹通常存储为时序日志，掩盖了底层的数据流——即其行为与所创建和操控的产物之间的依赖关系。这限制了开发者理解智能体轨迹、比较执行过程、调试失败以及复用计算结果的能力。我们提出AgentTrails，一个用于智能体溯源与意义建构的原型系统。AgentTrails将原始轨迹转换为结构化溯源图，其中工具调用被建模为计算动作，输入和输出被建模为数据产物。该系统通过将多个溯源图置于共享画布上，并构建一个联合商图来对齐轨迹中重复出现的工具、产物和依赖结构，从而支持执行过程的比较。在此表示之上，AgentTrails支持模式提取、下游分析以及技能抽象。我们在真实世界的智能体轨迹上展示了AgentTrails，表明它能揭示隐藏的依赖关系、对齐不同的执行过程，并浮现出超越时序日志的重复工具使用模式。

## Abstract
LLM-powered agents increasingly tackle complex tasks by invoking tools, querying databases, executing code, and manipulating intermediate artifacts. These agents follow trajectories that are typically stored as chronological logs, obscuring the underlying dataflow -- the dependencies between their actions and the artifacts they create and manipulate. This limits developers' ability to understand the agents' trails, compare executions, debug failures, and re-use the computations. We present AgentTrails, a prototype system for agent provenance and sensemaking. AgentTrails converts raw trajectories into structured provenance graphs, where tool calls are modeled as computational actions and inputs and outputs as data artifacts. The system supports the comparison of executions by placing multiple provenance graphs on a shared canvas and constructing a joined quotient graph that aligns recurring tools, artifacts, and dependency structures across trajectories. On top of this representation, AgentTrails supports pattern extraction, downstream analysis, and skill abstraction. We demonstrate AgentTrails on real-world agent trajectories, showing that it reveals hidden dependencies, aligns divergent executions, and surfaces recurring tool-use patterns beyond chronological logs.

- **潜在危害**：这种原始日志格式严重限制了开发者对智能体的理解和利用。
    - **难以理解**：日志掩盖了动作之间的真实**数据流依赖关系**（P2）。例如，一个工具的输出可能是多个步骤后另一个工具的输入，但时序日志无法直接体现这种关系。
    - **难以比较**：智能体执行具有随机性（P3），同一任务的不同执行轨迹在工具调用顺序、分支上可能完全不同，直接的序列比较不具意义。
    - **难以调试和复用**：由于缺乏结构化的理解，开发者难以定位失败原因，也难以提取和复用成功轨迹中的模式或技能。
- **整体含义**：为了实现对智能体任务的可信与复用，需要一个更高级的抽象层次来理解这些轨迹。论文提出应将原始轨迹转化为**执行溯源图（Provenance Graph）**，通过显式建模动作与数据产物之间的依赖关系，为智能体的分析、比较和重用提供结构化基础。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出一个名为`AgentTrails`的原型系统，通过“溯源”的视角，将无序的、隐式的智能体执行日志，转化为有序的、显式的、可比较的结构化信息。
- **关键技术细节**（包含三个阶段）:
    1.  **第一阶段：工具覆盖概览**
        -   **功能**：提供一个全局的、工具无关的视角。构建一个**“轨迹-工具”覆盖矩阵**，以UpSet图的形式展示不同轨迹调用了哪些工具、调用次数以及与关键指标（如分数、成本）的关系。
        -   **目的**：解决P1（轨迹长且异构）问题，允许用户进行初步筛选、分组和比较，而无需深入细节。

    2.  **第二阶段：单个轨迹的溯源图构建**
        -   **核心功能**：将单个原始轨迹`T`转换为一个结构化的二分图`G_T = (A_T ∪ E_T, R_T)`。
            -   `A_T`: **活动节点**，代表工具调用。
            -   `E_T`: **实体节点**，代表活动的输入、输出、中间产物等。
            -   `R_T`: **边**，包含`generatedBy`（活动生成实体）、`usedBy`（活动使用实体）、`informedBy`（弱关联）。
        -   **关键技术：基于证据的依赖关系重建**
            -   **精确证据**：从响应元数据（如文件路径、URL、对象ID）中提取实体，并建立后向引用（`refs`）。如果后一步的参数（`c_i.args`）显式包含前一步的输出键（`K(e_j)`），则建立强依赖边。
            -   **语义证据**：匹配前后步骤中共享的值、查询项、列名等，将其作为“候选依赖”，不直接断言。
            -   **LLM辅助细化**：在精确和候选依赖图的基础上，使用约束的LLM模型进行图补丁操作，只接受符合节点引用、时序顺序和图模式的操作。这使得溯源图是可审计的（精确边、语义候选边、LLM修正边可区分）。

    3.  **第三阶段：多轨迹溯源图对齐与联合商图**
        -   **核心功能**：解决P3（执行随机性）和S2（缺乏对齐锚点）问题。
        -   **关键技术：活动胶囊化与聚类**
            -   **活动胶囊**：将每个活动抽象为一个`胶囊`，描述其工具身份、输入/输出结构、本地图上下文和上游根路径。
            -   **胶囊相似度聚类**：计算两个胶囊的特征加权相似度`S(κ_i, κ_j)= Σ w_m * s_m`，基于Jaccard或余弦相似度比较其工具、结构、上下文等特征。相似的胶囊被聚为一个“联合活动节点”。
        -   **构建联合商图**：根据胶囊聚类结果，将原始边映射到新的联合节点上，聚合相同源和目标的边。最终生成一个能反映多个轨迹共性和差异的**商图（Quotient Graph）** 。高支持度的结构揭示重复出现的工作流模式，低支持度的结构（如路径上的分支、冗余调用）则暴露了轨迹特有的偏差。
