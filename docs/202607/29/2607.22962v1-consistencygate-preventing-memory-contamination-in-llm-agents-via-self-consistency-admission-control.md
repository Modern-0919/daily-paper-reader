## 摘要
在多轮交互中运行的LLM智能体会将事实积累到外部记忆存储中，并将其作为下游推理的前提。因此，某一步骤产生的幻觉事实会作为后续每一步的错误前提持续存在，这种失效模式称为记忆污染。现有的记忆管理方法关注检索和容量，但未解决写入时的正确性问题；这种准入问题无法通过基于效用或时效性的标准解决，且不受控制的污染会在长轨迹中不断累积。我们提出ConsistencyGate，一种写入时准入门控机制：在将从上下文c中提取的候选事实m提交之前，向LLM查询K次以获得软支持分数，并仅在平均分超过阈值时准入m。该机制与模型无关，无需微调，且可简化为对数概率变体中的单次前向传递，适用于延迟敏感场景。为衡量对自然数据的影响，我们在LoCoMo和MSC的长期对话中植入受控的单细节篡改，构建了两个真实对话基准（LoCoMo-Contam和MSC-Contam），并辅以结构化的合成语料库（MemContam）以隔离近乎最优的上界。在四个LLM骨干网络上的实验表明，与全写入基线相比，ConsistencyGate在所有基准上均降低了污染，其代价集中在源上下文中仅隐式陈述的事实上。我们发布了这三个基准以及门控实现。

## Abstract
LLM agents that operate over many turns accumulate facts in an external memory store and reuse them as premises for downstream reasoning. A hallucinated fact written at one step therefore persists as a false premise for every subsequent step, a failure mode we call memory contamination. Existing memory management addresses retrieval and capacity but not write-time correctness; this admission problem cannot be solved by utility- or recency-based criteria, and uncontrolled contamination compounds across long trajectories. We propose ConsistencyGate, a write-time admission gate that, before committing a candidate fact m extracted from context c, queries the LLM K times for a soft support score and admits m only when the average exceeds a threshold. The mechanism is model-agnostic, requires no fine-tuning, and reduces to a single forward pass in a log-probability variant for latency-sensitive deployments. To measure the effect on natural data, we construct two real-conversation benchmarks (LoCoMo-Contam and MSC-Contam) by planting controlled single-detail corruptions in long-term conversations from LoCoMo and MSC, and complement them with a structured synthetic corpus (MemContam) that isolates a near-oracle upper bound. Across four LLM backbones, ConsistencyGate reduces contamination on every benchmark relative to a write-everything baseline, with the cost concentrated on facts that are stated only implicitly in the source context. We release all three benchmarks together with the gate implementation.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：长程交互的 LLM 智能体通过外部记忆存储积累事实，并在后续步骤中作为推理前提。然而，LLM 在从给定上下文中提取事实时也会产生幻觉（hallucination）。一旦幻觉事实被写入记忆，就会被反复检索和使用，成为后续所有步骤的错误前提。作者将这种失效模式称为 **记忆污染（memory contamination）**。
- **现有工作的不足**：现有记忆管理主要关注检索（retrieval）和容量（capacity控制（容量控制），但未解决写入时的正确性（write-time correctness）。基于效用（utility）、新异度（novelty）、时效性（recency）的准入标准无法区分正确事实与其幻觉变体，因此对污染“视而不见”。污染不通过检索清除，也不被驱逐策略消除，是一个独立的准入问题。
- **整体含义**：提出一个在写入时验证事实正确性的准入门控，防止污染进入长期记忆，从而提升智能体在长轨迹中的可靠性。

## 2. 方法论：ConsistencyGate

### 2.1 核心思想
- 在将候选事实 `m` 写入记忆前，利用 LLM 自身的自一致性（self-consistency）进行验证。
- 方法：对同一候选事实，基于源上下文 `c` 向 LLM 查询 `K` 次，每次获得一个软支持分数 `s_k ∈ [0,1]`（0=完全不被支持或矛盾，1=完全直接支持）。计算平均支持度 ˆp = (1/K) Σ s_k。只有当 ˆp ≥ τ（阈值）时，才准入该事实。

### 2.2 关键技术细节
- **默认配置**：`K=5`，固定阈值 `τ=0.7`（推荐）。也可使用自适应阈值：τ* = τ_min + (τ_max - τ_min)·|M|/C，其中 |M| 为当前记忆大小，C 为容量上限。
- **高效单次变体（LogProb）**：将验证提示改为二元（yes/no），从单次前向传递中读取 token-level 对数概率，计算 ˆp_log = softmax(log p(yes), log p(no))。延迟仅 23–28 ms/事实（vs. K=5 的 264–363 ms），但在长对话上下文中效果不及软评分。
- **算法流程**（文字描述）：
    1. 输入候选事实 m、源上下文 c、LLM、采样次数 K、阈值 τ、记忆 M 和容量 C。
    2. 对于 k=1 到 K：构建软验证提示，LLM 生成分数 s_k。
    3. 计算平均分数 ˆp。
    4. 计算阈值 τ*（固定或自适应）。
    5. 若 ˆp ≥ τ*，则将 m 加入 M，返回 True；否则返回 False。
- **模型无关**：不依赖特定模型架构，无需微调，仅需文本提示。

## 3. 实验设计

### 3.1 使用的数据集/场景
- **MemContam**（合成）：5 个结构化上下文，每个生成 40 个样本，共 200 个样本。每个样本含 5 个正确事实和 5 个通过四种策略（数值扰动、否定、专名替换、矛盾从句）生成的错误事实，污染率 50%。提供 600 个 QA 对。
- **LoCoMo-Contam**（真实长对话）：基于 LoCoMo-10 数据集（10 个长时对话，每对话 400–700 轮）。选取最多 5 个 QA 对，将答案转化为事实，篡改单个细节生成错误版本，共 50 个探针对，污染率 50%。
- **MSC-Contam**（人格对话）：基于 Multi-Session Chat（20 个对话，每对话 2 会话）。从人格句子中筛选可验证事实，篡改后生成 41 个探针对，污染率 50%。

### 3.2 基准方法
- **WriteAll**：写入所有提取的事实（全基线）。
- **Random**：以概率 p=0.6 随机准入（匹配 ConsistencyGate 的平均准入率），用于控制记忆大小的影响。

## 6. 主要结论与发现

- **污染显著降低**：在 LoCoMo-Contam 上，ConsistencyGate 将污染率从 50% 降至 34.1%（Qwen2.5-32B），精度从 0.500 提升至 0.659；在 MSC-Contam 上降至 36.7%，精度 0.633。在合成基准 MemContam 上达到近乎最优的 1.2% 污染（Recall 1.0），QA F1 从 0.474 提升至 0.840。
- **跨模型一致性**：所有四个骨干模型均观察到污染降低（20%–62%），Llama-3.3-70B 表现最佳，Llama4-Scout 最弱但仍有效。
- **阈值 τ=0.7 为自然边界**：高于 0.7 的增益饱和。
- **LogProb 变体仅在结构化上下文有效**：在 MemContam 上优于软评分，但在 LoCoMo-Contam 上逊于软评分，因为长对话上下文打破了二值假设。
- **污染级联效应**：随着交互轮次增加，WriteAll 的污染率维持 50% 且 QA F1 下降，而 ConsistencyGate 的污染持续下降至 3% 以下，差距单调扩大。
- **召回权衡**：在 LoCoMo-Contam 上召回仅 0.58，表明隐式或分布性事实易被拒绝；在 MSC-Contam 上召回为 0.93（显式人格事实）。
- **成本集中**：被拒绝的主要是源上下文中隐式陈述的事实。

## 7. 优点

- **方法新颖且实用**：将自一致性思想扩展到写时准入阶段，填补了现有记忆管理的空白（只关注检索和容量）。
- **模型无关、无需微调**：可直接应用于任意 LLM 骨干，仅需修改提示。
- **灵活的效率模式**：默认 K 次采样适用于高精确度场景，LogProb 单次变体适用于延迟/能源受限的部署。
- **构建首个可控污染的真实对话基准**：LoCoMo-Contam 和 MSC-Contam 为未来研究提供可复现的评估工具。
- **揭示污染级联现象**：量化了写时错误在长轨迹中的累积效应，强调了早期准入决策的重要性。
- **消融实验完整**：对 K、τ、LogProb 等关键参数进行系统扫描，为实践者提供明确配置建议。

## 8. 不足与局限

- **额外推断开销**：写时增加 O(K) 次 LLM 调用（虽 LogProb 变体缓解，但仅适用于结构化上下文）。
- **一致性并非正确性**：方法只能验证事实与源上下文的一致性，无法发现需要外部知识或全局推理的错误。因此不能替代权威事实核查。
- **隐含事实召回低**：对分布性、需要多跳推理或仅暗示的事实，门控倾向于拒绝，导致在 LoCoMo-Contam 上召回仅 0.58。在实际部署中，这将永久丢失正确信息。
- **上下文结构依赖性强**：LogProb 变体仅在短结构化上下文有效，在长对话中失效，限制了其在开放域对话中的加速优势。
- **基准覆盖有限**：真实对话基准仅来自两个数据集（LoCoMo、MSC），且规模较小（50 和 41 个探针对），可能不足以代表所有长对话场景。合成基准 MemContam 是内部一致性上界，不能直接体现实际表现。
- **消融未覆盖更多模型或更大规模**：仅测试了 4 个模型，未在更大模型（如 130B、405B）或开源/闭源混合场景中评估。
- **污染类型单一**：人工植入的篡改是单细节变化，未涵盖更复杂的幻觉类型（如完全捏造、时序冲突等）。
