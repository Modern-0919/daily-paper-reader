## 摘要
大型语言模型（LLM）智能体越来越多地用于编码和终端自动化，使得Shell命令分派成为一个高风险的运行时控制点。我们研究在受限路径上下文下，对LLM智能体产生的单个Shell命令进行命令级预执行调解。现有的安全措施仍然有限：通用防护栏不能足够详细地建模Shell结构，始终在线的LLM评判器相对昂贵且可变，而Shell解析器不能直接防止有害执行。我们提出了CARE（规范化、归因和解析引擎），这是一种针对Shell的、静态优先的验证器，用于在执行前验证单个Shell命令。CARE将生成的命令规范化为稳定的验证目标，从语法、命令语义、路径上下文和基于来源的风险模式中推导出确定性证据，并且仅将不确定的情况升级到LLM评判器。这种设计使得常见情况快速、可重复且可审计，同时为边界命令保留神经裁决。在平衡的主划分上，CARE达到了85.64%的F1分数，误报率为0.91%，平均延迟为2.32毫秒。当部署在其静态执行配置文件中时，CARE在0.34毫秒延迟下保持了84.99%的F1分数，并将RedCode-gen上的实际危害降低到37.33%。在外部泛化测试和受控Docker沙箱执行中，这些配置文件揭示了良性恢复、误报负担、延迟和危害减少之间的实际权衡。总体而言，命令级Shell调解可以降低LLM智能体的分派边界风险，同时保留大多数良性工作流。

## Abstract
Large Language Model (LLM) agents are increasingly used for coding and terminal automation, making shell-command dispatch a high-stakes runtime control point. We study command-level pre-execution mediation for individual shell commands produced by LLM agents under bounded path context. Existing safeguards remain limited: generic guardrails do not model shell structure in sufficient detail, always-on LLM judges are relatively costly and variable, and shell parsers do not directly prevent harmful execution. We present CARE (Canonicalization, Attribution, and Resolution Engine), a shell-specific, static-first verifier for individual shell commands before execution. CARE canonicalizes generated commands into stable verification targets, derives deterministic evidence over syntax, command semantics, path context, and provenance-backed risk patterns, and escalates only underdetermined cases to an LLM judge. This design keeps the common case fast, reproducible, and auditable while reserving neural adjudication for borderline commands. On the balanced main split, CARE reaches 85.64% F1 with a 0.91% false-positive rate at 2.32 ms mean latency. When deployed in its static enforcement profile, CARE retains 84.99% F1 at 0.34 ms and reduces realised harm on RedCode-gen to 37.33%. Across external-generalization tests and controlled Docker-sandbox execution, these profiles expose a practical trade-off between benign recovery, false-positive burden, latency, and harm reduction. Overall, command-level shell mediation can reduce dispatch-boundary risk for LLM agents while preserving most benign workflows.

  - 通用护栏不建模 Shell 结构细节；LLM 法官延迟高、成本大、输出不稳定；Shell 解析器仅检查语法正确性，不阻止有害执行。
- **意义**：需要一种专门针对 Shell 命令的低延迟、可审计、静态优先的预执行验证机制，在命令到达主机 Shell 前判定允许/警告/拒绝，以在保留良性工作流的同时减少攻击面。

### 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：CARE（Canonicalization, Attribution, and Resolution Engine）采用**静态优先 + 选择性 LLM 升级**的三阶段混合架构。大部分常见命令由静态规则快速、确定性地处理；仅对边界模糊的命令才调用 LLM 法官，从而兼顾速度、准确率和可审计性。
- **关键技术细节**：
  - **阶段1：规范化（Canonicalization）**：将原始命令 `c` 通过一系列确定性、幂等的重写（包装解包、引号/转义标准化、轻量去混淆）转化为稳定的验证目标 `ĉ`。不执行子进程，仅做文本级规范化。
  - **阶段2：归因（Attribution）**：基于 `ĉ` 提取多维确定性证据：
    - L1（语法/结构）：用 bashlex 解析 AST，检查高风险结构（如 eval、管道到解释器），输出结构惩罚 `δ_struct ∈ [0,1]`。
    - L2（语义分类）：依据命令头部的语义类别（如 READ_ONLY、DESTRUCTIVE）和上下文增强因子，计算语义风险 `s_sem`。
    - L3（路径敏感）：解析路径操作数，根据访问上下文（读/写）和路径敏感度等级（关键/秘密/系统/工作区）计算路径风险 `s_path`。
    - L4（模式与来源）：匹配 139 条带来源标签（MITRE、GTFOBins、手工）的高置信 shell 模式，计算模式风险 `s_pat`。
    - L5（策略与初步裁决）：加权融合上述分数，通过双阈值 `τ_low` 和 `τ_high` 输出初步决策 `d_prov ∈ {ALLOW, WARN, DENY}`。
  - **阶段3：解析（Resolution）**：
    - 高置信 `ALLOW` 和 `DENY` 直接终判（不调用 LLM）。
    - `WARN` 命令先经过跳跃谓词（判断是否已由静态证据明确应拒绝），若命中则直接 `DENY`；否则提交给 LLM 法官（Qwen3-Coder-30B-A3B，单次预测，温度=0），法官默认拒绝，最终输出 `d*`。
- **算法流程**（文字描述）：
  1. 规范化原始命令得到 `ĉ`。
  2. L1 解析 AST，若失败且含高风险标记则直接 DENY。
  3. L2、L3、L4 分别计算 s_sem、s_path、s_pat。
  4. L5 计算综合分数 score，根据阈值得到 d_prov。
  5. 若 d_prov=WARN 且 LLM 法官启用，检查跳跃谓词；若命中则 DENY，否则调用 LLM 法官得到终判；其他情况直接终判。
  6. 返回终判和证据轨迹。

### 6. 论文的主要结论与发现
- 在主评估集上，CARE（完整版）达到 **85.64% F1，0.91% FPR，2.32 ms** 平均延迟；CARE（静态版）达到 **84.99% F1，0.34 ms**，将 RedCode-gen 真实伤害率降至 **37.33%**（远低于无防护的 74.83% 和大多 LLM 方法）。
- 在效用基准上，CARE 的良性任务解决率接近无防护状态（单步 57.00% vs 57.33%），仅产生极少数误拒绝（0.33%）。
- 消融显示语义层贡献最大（−26.68 pp F1），路径层其次（−16.95 pp），模式层贡献 9.50 pp。
- 在 OOD 泛化上，CARE 在混淆、GTFOBins 上表现良好，在 Exploit-DB 上不如正则表达式（因后者捕捉固定关键词更直接）。
- **关键权衡**：静态模式适合最大保守性（零 LLM 延迟、最低伤害）；全模式通过少量 LLM 调用（约 4% 命令）恢复良性工作流（FPR 减半）。

### 7. 优点
- **静态优先混合设计**：将确定性的规则与选择性的 LLM 评估相结合，在保持低延迟、高审计性的同时处理边界情况。
- **细粒度归因**：多层证据（语法、语义、路径、模式+来源）使决策可解释、可溯源，且每一层均可独立验证。
- **全面鲁棒性评估**：覆盖多种 OOD 场景（混淆、LLM 生成、真实 CVE）、多 Shell 方言、LLM 同源偏差控制（用不同厂商模型锚定）。
- **实用部署配置**：提供两种模式（全模式和静态模式），供不同安全/延迟需求选择。

### 8. 不足与局限
- **仅单命令级别**：不防范跨会话攻击链（如分阶段下载-执行）、环境突变等，需与其他沙箱/主机加固措施配合。
- **LLM 法官同源偏差**：法官与攻击命令生成器共享 Qwen3-Coder-30B，可能导致在 RedCode-gen 上对同类欺骗失效（全模式危害率高于静态模式）。虽用不同厂商模型进行了锚定，但未完全消除。
- **FPR 在 OOD 上仍然较高**：在 GTFOBins（13.04%）和 Obfuscation（11.60%）上 FPR 超过 10%，可能对良性用户造成困扰。
- **解析依赖**：依赖 bashlex 进行 POSIX 解析，对不兼容语法可能解析失败（约 11% 的 bash 命令），此时仅能依赖回退规则。
- **应用限制**：仅适用于 Linux bash/sh 环境，不覆盖 Windows PowerShell 或其他 Shell；设计为预执行防护，不提供事后审计能力。
